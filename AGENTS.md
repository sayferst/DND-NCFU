# Инструкции Codex — RPG + ВКР

**Главный источник требований:** `MASTER_CODEX_RPG_VKR_ZERO_COST.md`. Прочитай весь файл перед разработкой. Старые файлы с суффиксом `_OLDER` — только дополнительный исторический контекст; их рекомендации, противоречащие этому файлу, не применять.

## Непереговорные условия
- Реализация Windows-игры бесплатна для пользователя, **последующая эксплуатация 0 ₽**, без подписок/карт/платных API/хостинга. Можно пользоваться бесплатным облачным API только **дополнительно**. Сама игра работает офлайн за счёт `offline_rules`; `local_llm` подключается по возможности. Codex и облачная генерация не являются runtime-зависимостями.
- Python 3.12 (или технически обоснованная совместимая версия), PySide6 (или Tkinter с объяснением), SQLite; правила SRD 5.2.1 CC BY 4.0 с указанием источника; математика конфликтов выполняется проверяемым кодом.
- Рассказчик не меняет состояние БД напрямую; любые изменения через валидатор. Не смешивать язык рассказчика, игровой движок и вычислительный `ConflictSolver`.
- Пользователь новичок: объясняй по-русски простыми словами, давай команды PowerShell с указанием пути и ожидаемого результата. Нет фиктивных отчётов «тесты пройдены».
- Никогда не инициируй незаметные платные операции, регистрации, ввод карты, большие скачивания и удаление файлов. Запрашивай разрешение при потенциальном риске. API-ключи и личные данные — вне репозитория и логов.
- Дроби задачи. Каждый модуль: одна маленькая реализация, тесты, ручная инструкция. После каждого этапа остановись и жди подтверждения. Применяй Git, сохраняй проверяемые версии.
- Веди `DECISIONS.md`, `RESEARCH_LOG.md`, `LICENSES_AND_ATTRIBUTIONS.md`, `KNOWN_ISSUES.md`, при необходимости `CHANGELOG.md` и `OFFLINE_TEST.md`. Источники ВКР — только настоящие проверяемые научные работы, не выдумывать факты/результаты.
- Уточняй проблемы небольшими порциями, как описано в разделе 15 главного документа, не задавай человеку 18 вопросов сразу.

## Формат окончания каждой задачи
1. Что действительно сделано.
2. Какие файлы изменились и почему.
3. Какие тесты реально запускались и результаты (непроверенное пометь).
4. Одна-две команды для ручной проверки Windows PowerShell и ожидаемый экран/результат.
5. Нерешённые ограничения и следующий небольшой этап; остановиться.
