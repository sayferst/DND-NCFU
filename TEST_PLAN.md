# План проверок

## Среда (этап 0A)

Из корня проекта: Windows `.\.venv\Scripts\python.exe scripts\check.py`,
Linux `.venv/bin/python scripts/check.py`.
Команда завершается с ненулевым кодом при любой неудачной проверке.

| Проверка | Что подтверждает |
|---|---|
| Git --version | Git доступен |
| pip check | Зависимости установлены совместимо |
| test_python_is_supported_and_isolated | Python 3.12 используется из venv |
| test_sqlite_persists_unicode_after_reopening | SQLite сохраняет кириллицу на диск и читает её после повторного открытия |
| test_sqlite_rolls_back_failed_transaction | Неудачная транзакция не сохраняет частичные изменения |
| Ruff check / format --check | Python-файлы соответствуют настройкам проверок |

Тесты используют временные каталоги pytest, не пользовательские сохранения.
Успех этих проверок не подтверждает игру, GUI или математическую модель.
Результаты текущего выполнения: см. PROJECT_STATUS.md.

## Будущие проверки (не выполнены)

1. 0B: ручной запуск окна на Windows, ввод и офлайн-ответ, корректное закрытие.
2. Правила: ссылки на раздел SRD, граничные случаи, ограничения ресурсов,
   независимые ожидаемые расчёты; авторские механики отдельно.
3. Сохранения: атомарность, повторное открытие, сбои и миграции на копиях данных.
4. ConflictSolver: числовые примеры, наблюдения NPC, допустимость стратегий,
   воспроизводимость seed и независимость от художественного текста.
5. Рассказчик: некорректный ответ, попытка обойти валидатор, тайм-аут,
   отказ API и переход в offline_rules без потери состояния.
6. Исследование: одинаковые входы A/B, проверка метрик и сохранность сырых данных.
7. Автономность: протокол docs/OFFLINE_TEST.md; переносимая сборка на чистой Windows.

Для каждого запуска записывать дату, команду, среду, количество passed/failed/skipped
и фактические ограничения. Ноль тестов или пропуски не превращать в успех.
