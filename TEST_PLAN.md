# План проверок

Из корня проекта: Windows `.\.venv\Scripts\python.exe scripts\check.py`,
Linux `.venv/bin/python scripts/check.py`. Любая ошибка даёт ненулевой код завершения.
Проверки не требуют сети после установки. QApplication в автотестах работает offscreen.

## Сценарий базового окна 0B (пользователь подтвердил работу окна)

1. Запустить `scripts/run_game.py`. Видны заголовок «У ворот деревни», сцена и поле ввода.
2. Ввести «осмотреться», нажать Enter: в журнале действие и описание дороги.
3. Ввести «помочь», нажать «Отправить»: жительница благодарит за помощь.
4. Ввести «помощь»: видны доступные команды. Ввести «улететь»: появляется уточнение.
5. Пустая строка не добавляется; предыдущие реплики остаются в журнале.
6. В версии 0B журнал ещё не сохранялся. Теперь для восстановления использовать ячейку.
7. Повторить без интернета по docs/OFFLINE_TEST.md. Сохранить вывод тестов и наблюдения.

## Ручная приёмка d20 и ячеек 1A (ожидается)

Выполнить docs/SAVE_SLOTS.md: d20, три ячейки, перезапись/удаление и их отмена,
закрытие и повторная загрузка. История и уже выпавшие числа должны восстановиться.
Проверить предупреждение о несохранённых изменениях и работу без интернета.
Случайное совпадение двух соседних результатов допустимо. Проверка диапазона
на фиксированном seed не является доказательством статистической равномерности.

## Будущие проверки (не выполнены)

- Правила: раздел SRD, независимые ожидаемые расчёты, граничные случаи и ресурсы.
- Сохранения: атомарность, повторное открытие, сбои и миграции на копиях данных.
- ConflictSolver: числовые примеры, наблюдения NPC, стратегии, seed, независимость от текста.
- Дополнительные рассказчики: невалидный ответ, тайм-аут, отказ и fallback без потери состояния.
- Исследование: одинаковые входы A/B, корректность метрик и сохранность сырых данных.
- Релиз: полноценный офлайн-цикл и переносимая сборка на чистой Windows.

Каждый запуск: дата, команда, среда, passed/failed/skipped, ограничения.
Нулевой набор тестов и пропуски не превращать в успех.
