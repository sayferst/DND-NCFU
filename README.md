# DND-NCFU
разработка dnd для выпускной работы для скфу

Учебная текстовая RPG на Python для исследования конфликтных ситуаций.
Windows x64, Python 3.12, PySide6 и SQLite. По текущему решению владельца
игровой чат и создание нового мира требуют облачного ИИ-мастера.
Без подключения доступны локальные сохранения, дневник, знания и кэш изображений.
Облачные расходы зависят от провайдера; платные запросы не включаются автоматически.

**Пакет 1S:** отдельная визуальная память мира: Recraft для обычных предметов,
FLUX для персонажей, существ и сцен, версии и референсы по постоянным ID,
карточки Хроник и кнопка «Изобразить сцену». Бюджет изображений по умолчанию 0 ₽.
Офлайн-пример больше не запускается вместо нового мира.
[Архитектура, ограничения и команды обновления](docs/WORLD_IMAGES.md).
[Что ещё нужно сверить с Images API](docs/IMAGES_API_CONTRACT.md).
1054 теста прошли; живые изображения RouterAI и Windows EXE пока не проверены.
[Проверки](docs/validation/images-2026-10-20/README.md),
[опциональная сборка EXE](docs/BUILD_WINDOWS.md).

Ниже сохранена история пакетов; прежние описания офлайн-режима относятся
к соответствующим старым версиям. Текущая политика — облачный игровой чат.

**Пакет 1R:** новое фэнтезийное меню, единая тема и «Хроники мира» с поиском,
карточками и постепенным раскрытием знаний. Настройки содержат переключатель
Flash и необязательное защищённое запоминание ключа на Windows.
[Обновление локальной папки и инструкция](docs/FANTASY_UI_AND_CHRONICLES.md).
Правила игры, сохранения22 и архитектура мастера сохранены.

**Пакет 1Q:** разделены литературный ответ и состояние мира; общие диалоги
с новыми NPC; один запрос для обычного разговора с `reply`; объяснение
неподдержанного действия и общая проверка; максимум три генерации на ход;
постоянные метрики в SQLite. Короткие реплики и подробные сцены сохраняются.
[Что изменилось, обновление и проверка](docs/MASTER_RESPONSES.md).
[Независимое сравнение до/после](docs/evals/master-response-2026-10-20/RESULTS.md).
Настоящее качество/цена DeepSeek этим набором не измерялись.

**Предыдущий пакет 1P:** стартовый район и сюжетный замысел мастера по биографии героя
и пожеланиям к миру; постоянная SQLite-память кампаний; личный дневник с поиском,
редактированием и закреплением; торговля и схватка в контекстных окнах.
Настройте ИИ **до создания нового героя**, чтобы получить генерацию моделью.
В версии 1P без подключения был авторский случайный старт; в 1S этот запасной
старт отключён в пользовательском интерфейсе. Старые ячейки не заменяются.
[Обновление D:, новая игра и дневник](docs/GENERATED_CAMPAIGNS.md).
Новых зависимостей нет. Полная магия, автономные планы NPC и все правила D&D
пока не реализованы.

**Предыдущий пакет 1O.3:** золото героя и стандартные бинты связаны с переносимыми
предметами, контейнерами, покупкой/продажей и лечением. Остатки и каталог
проверяются вместе. [Что изменилось и как проверить](docs/RESOURCE_LEDGER.md).
Совместимость со старыми ячейками сохранена; дополнительных зависимостей нет.

**Пакет1O.1:** Каталог мира с десятью разделами,46стартовыми типами,
постоянными экземплярами, поиском/созданием мастером поID и рабочейSQLite-копией.
Добавлены проверяемые попытки воздействия на новых существ и исправление
Windows-ошибки длинногоID pytest. [Объяснение и обновление D:](docs/CATALOG_AND_CAUSALITY.md).
Это история основания базы; стартовый район и первые локальные реакции добавлены в1P.

**Пакет 1N.7:** проверяемый план до рассказа — предметы, контейнеры,
количества, соседние места и отношения свидетелей сохраняются в игре.
Переход в лес завершает прежний контакт; оставленная вещь остаётся на месте.
[Как включить Flash и обновить файлы на D:](docs/WORLD_ACTIONS_AND_STATE.md).
Это общий механизм зарегистрированных объектов. В1O.3 связаны прежние бинты
и золото; перенос стартового комплекта ещё впереди, полный генератор и остальные системы остаются ограниченными.

**Пакет 1N.6:** инструкция мастера в TXT, отдельные пожелания к миру при
создании героя и подтверждаемые проверки свободных попыток. DeepSeek может
подобрать категорию проверки для нетипичной формулировки; кубик считает движок.
[Подключение, редактирование инструкции и обновление на D:](docs/MASTER_PROMPT_AND_FREE_ACTIONS.md).
Стартовый генератор добавлен в1P; описание ниже относится к1N.6.

**Добавлен RouterAI:** отдельный облачный API с каталогом моделей/цен в рублях
и проверкой месячного лимита ключа≤2000₽ перед генерацией. Платежи не включаются
автоматически. С версии 1S игровой чат требует облака. Подключение основано на документации,
присланной пользователем; настоящий API/качество ещё ожидают проверки.
[Настройка RouterAI и обновление папки D:](docs/ROUTERAI_WINDOWS.md).

Если проверка Windows сообщает о SHA-256 `save-v15.json` и LF/CRLF:
[восстановление эталона и команды обновления](docs/FIXTURE_CHECKOUT_WINDOWS.md).

**Актуально: бой из свободного ввода и облако без платной замены.**
Явная попытка нападения рассчитывается до рассказа; результат остаётся виден
при ошибке ИИ. Добавлен бесплатный профиль OpenRouter (квоты/доступность сервиса).
Пользователь допускает необязательное платное облако до2000₽/месяц, но платежи
не подключены. [Подключение, ограничения и обновление D:](docs/CLOUD_MASTER_AND_COMBAT.md).

Первое подключение настоящей модели на Windows с хранением на D:
[Ollama + Qwen3 1.7B](docs/INSTALL_LOCAL_AI_WINDOWS.md).
Это историческая инструкция для локальной модели; в новом интерфейсе 1S
локальная модель не предлагается для игрового чата.

## Что уже работает

- **Автоматический мастер через чат:** обычный текст без JSON-команд от модели,
  один автоматический повтор при плохом ответе, SQLite-память и отдельные правила
  для механики. Ручной GPT и кнопки готовых игровых действий удалены.
  [Проверка настоящей модели и необязательный облачный API](docs/AUTOMATIC_MASTER.md).

- **Свободный осмотр и несколько проверок:** исправлен конфликт полей ответа ИИ;
  исследование с интеллектом и выносливостью показывает два расчёта и открывает
  сведения по результатам. [Примеры и ручная проверка](docs/CHAT_AND_INSPECTION.md).

- **Мастер, память NPC и анкета:** вопросы ведущему отделены от разговора, мастер
  сам создаёт недостающие публичные детали NPC и сохраняет их. Свободное описание
  героя до 6000 символов; подписи Мастер/NPC/имя героя. Команды кнопок скрыты.
  [Что изменилось и как проверить](docs/MASTER_AND_CANON.md).

- **Чат с локальным ИИ:** обычная речь → распознанное намерение → проверка движком →
  художественный ответ вместо строки «Мир». Ответ NPC — с его именем и цветом.
  Поддерживаются существующие механики; неизвестное/неоднозначное действие требует
  уточнения. Без модели остаются резервные текстовые действия.
  [Как включить и проверить](docs/DIALOGUE_AND_PROSE.md).
  [Причины отказов, контекст и обучение](docs/LOCAL_AI_IMPROVEMENT_PLAN.md).

- **Память мира:** причины изменений ресурсов, места, отношений и развития.
- **Необязательный локальный рассказчик:** выбор установленной модели Ollama,
  отменяемый запрос, сохранение художественного дополнения без изменения правил.
  Модели не скачиваются автоматически, без них игра работает как прежде.
  [Инструкция и ограничения](docs/LOCAL_NARRATOR_AND_MEMORY.md).

- **Понятный разбор бросков:** итог и история слева, кубики/бонусы/суммы справа
  в постоянной панели. Просмотр 100 действий с бросками и экспорт всех расчётов.
  Вопросы «что я вижу?» и «где я нахожусь?». Подробнее:
  [docs/NARRATOR_AND_ROLLS.md](docs/NARRATOR_AND_ROLLS.md).

- **Создание героя:** авторские профили Боец/Разведчик/Книжник, 24 очка,
  стартовые характеристики 8–16 и разные комплекты. Это не полные классы SRD.
- Развитие от разгрузки телеги, исследования и учебника; первый уровень роста,
  причины начисления и защита от повторного опыта. Подробнее:
  [docs/CHARACTER_AND_PROGRESS.md](docs/CHARACTER_AND_PROGRESS.md).
- Прежний свободный редактор остаётся только для старой учебной песочницы.
- Журнал, свободное поле ввода и кнопки быстрых действий. Неизвестные команды
  запрашивают уточнение; осмотр и разговор зависят от текущего места.
- Кубик с 20 гранями и проверки характеристик: например **проверить силу**, сложность 10.
- Здоровье, золото, бинты, корзина поручения; три места — ворота, дорога, рынок.
- Эпизод **«Доставка на рынок»**: поручение, исследование с риском, награда,
  покупка/продажа бинтов и лечение. Награда и находка выдаются один раз.
- Три ячейки сохраняют героя, мир, журнал и последовательность бросков.
  Перезапись и удаление требуют подтверждения. Старые v1–v12 читаются; запись теперь v13.

Проверки характеристик используют подмножество SRD 5.2.1; источник и атрибуция —
[docs/SRD_RULES.md](docs/SRD_RULES.md), меню **«Справка → О программе и лицензии»**.
Сюжет, цены, награды, стартовое здоровье и лечение бинтом — авторские homebrew.
Это пока один небольшой эпизод; полных классов/боёв SRD и ConflictSolver ещё нет; малая схватка — авторская.

Добавлен пакет схватки: волк/кабан, скрытый подход, отдельные броски попадания и
урона, ответы, уклонение/отступление/бинт. Ссора и нападение делают нейтральных
акторов враждебными: они красные, мирное общение/торговля закрываются. Награда за
первую победу над волком — один раз. Начальный текст 13 pt, жирность регулируется.
Подробности и новая проверка: [docs/COMBAT_AND_HOSTILITY.md](docs/COMBAT_AND_HOSTILITY.md).

Интерфейс объединён навигацией **«Раздел»**: главное меню, приключение, герой,
инвентарь, задание, карта, жители, лавка, кубики, команды, сохранения, настройки
схватка и справка «Как играть». На старте открывается меню: загрузите ячейку или вернитесь
к учебной песочнице; для развития выберите «Новый герой…». F11 — полный экран, Esc — выход из него.

Инвентарь содержит только свои вещи и их применение. Чтобы торговать, сначала
узнайте дорогу на рынок у стражника (или из поручения), придите туда и **подойдите
к торговцу**. Тогда станут известны ассортимент и цены. Деньги торговца скрыты;
при отказе выкупить предмет он скажет об этом. При уходе торговля закрывается.

Поиск/экспорт журнала, история ввода, темы и размер текста сохранены. Инструкция:
[docs/INTERFACE.md](docs/INTERFACE.md), принципы сведений игрока:
[docs/PLAYER_KNOWLEDGE.md](docs/PLAYER_KNOWLEDGE.md). Новых зависимостей нет.

## Получить обновление на свой диск D:

Сначала сохраните сессию и закройте старое окно игры. В PowerShell выполняйте
блок целиком. Он остановится при ошибке скачивания или проверки; сохраните её текст.

```powershell
& {
    Set-Location D:\Projects\DND-NCFU -ErrorAction Stop
    git pull --ff-only
    if ($LASTEXITCODE -ne 0) { throw 'Не удалось обновить проект. Игра не запущена.' }
    .\.venv\Scripts\python.exe scripts\check.py
    if ($LASTEXITCODE -ne 0) { throw 'Проверка не прошла. Игра не запущена.' }
    .\.venv\Scripts\python.exe scripts\run_game.py
}
```

`git pull --ff-only` обновляет именно файлы локального проекта на диске D:.
Рабочая ветка — `setup/development-environment`. Не удаляйте локальные изменения,
если Git отказывается обновляться. Для этого этапа новых зависимостей нет.
Ожидается **290 passed**, успешные pip check и обе проверки Ruff.
Ручную проверку нового интерфейса на Windows выполняет пользователь.

Если устанавливаете с нуля: [docs/INSTALL_WINDOWS.md](docs/INSTALL_WINDOWS.md).
При изменении зависимостей установка выполняется командой:

```powershell
.\.venv\Scripts\python.exe -m pip install --no-cache-dir --require-hashes -r requirements-dev.lock
```

Для обычного повторного запуска достаточно `scripts\run_game.py` через Python из `.venv`.

## Пройти первый эпизод

Можно нажимать кнопки под журналом или отправлять команды в игре:

```text
взять поручение
идти на дорогу
исследовать дорогу
идти на рынок
доставить корзину
подойти к торговцу
купить бинт
использовать бинт
```

В начале 12/12 здоровья, 10 золотых, 1 бинт. Доставка даёт 5 золотых.
Исследование при успехе даёт 2 золотых, при неудаче отнимает до 3 здоровья;
повторно оно не выдаёт ни награду, ни новый бросок. Бинт стоит 3, продаётся за 1
и восстанавливает до 4 здоровья. При полном здоровье бинт не тратится.

Дополнительно: **инвентарь**, **задание**, **состояние**, **торговля**,
**продать бинт**, **идти к воротам**, **осмотреться**, **поговорить**, **помощь**.
Полный сценарий приёмки — [docs/EPISODE.md](docs/EPISODE.md).

Во вкладке персонажа доступны **«Новый герой»** и **«Редактировать героя»**.
Новый герой начинает отдельную сессию с бюджетом; старые ячейки остаются.
Созданный герой развивается действиями, свободный редактор для него отключён.
Старые сессии остаются песочницей; их редактор не выдаёт ресурсов.

## Сохранения и резервные копии

Во вкладке **«Сохранения»** у каждой из трёх ячеек есть **Сохранить / Загрузить / Удалить**. Автосохранения нет.
Сохраняются отправленные действия; черновик поля ввода не сохраняется.
При старте открывается новая сессия — для продолжения выберите «Загрузить».

Для проекта `D:\Projects\DND-NCFU` файлы находятся вне Git:
**`D:\Projects\DND-NCFU-data\saves`**. Путь показан в окне; папка создаётся при
первом сохранении. Делайте отдельную копию папки `saves`. Подробности и перенос
данных: [docs/SAVE_SLOTS.md](docs/SAVE_SLOTS.md).
