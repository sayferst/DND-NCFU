# Учётные записи и подключение

Выпуск содержит один setup.exe для admin и tester. При каждом запуске откроется
окно входа. Пароль передаётся только проверенному HTTPS-хосту, на клиенте не
сохраняется. Хост хранит соль и PBKDF2-хэш, а не открытый пароль. Пять неверных
попыток блокируют вход на минуту. Сессия действует до суток, но бюджет не обнуляется.

Для tester задано 100 ₽, для admin 500 ₽ на весь допуск. Срок — 30 дней от первой
настройки. Мастер и Художник используют ключ соответствующей учётной записи,
который хранится через DPAPI на ПК владельца. Сервер выбирает ключ по сессии:
клиент не может назначить себе admin изменением файла или запроса.
Клиент и исходники не содержат выбранных владельцем паролей/API-ключей.

Это денежные лимиты, а не фиксированное число токенов; расход зависит от моделей.
Повторный вход, смена ключа/пароля и переустановка не сбрасывают расходы.
История прежних допусков также учитывается в общем лимите хоста.
Отзыв и продление выполняет владелец через серверные инструменты рабочей ветки.

«Проверить сопряжение» выполняет GET /health по подписанному адресу, без
генерации. Доступность хоста не гарантирует наличие баланса у провайдера.
Без работающего хоста вход и новая облачная генерация недоступны.

На одном ПК сохранения остаются локальными и общими для установленных вариантов:
учётная запись ограничивает API, но не создаёт отдельный каталог кампаний.

Настройка владельца в ветке setup/development-environment:
CHANGE_ADMIN_API.bat, CHANGE_TESTER_API.bat, SETUP_ACCOUNTS.bat, START_HOST.bat.
Все команды находятся в папке «Команды». Пароли и ключи вводятся локально,
не через GitHub Release. Сборщик из этой ветки — BUILD_SETUP.bat.
