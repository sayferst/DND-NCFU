# DND-NCFU — задание Codex по интеграции RouterAI / DeepSeek V4 Pro

**Дата:** 19 октября 2026. **Статус:** подробное техническое задание; сначала аудит и план. **Только владелец проекта разрешает изменения кода после обсуждения.**

## 0. Назначение

Ты — Codex, инженер-программист проекта DND-NCFU (Python 3.12, PySide6, текущая ветка `setup/development-environment`, репозиторий https://github.com/sayferst/DND-NCFU). Твоя задача — не написать новую игрушку и не заменить текущий движок одной строкой API-вызова. Необходимо безопасно внедрить **DeepSeek V4 Pro 0813 через RouterAI** как **одного облачного ИИ-мастера D&D и рассказчика**, сохранив существующие проверки правил, разбор действий, память, автотесты, GUI, совместимость сохранений и бесплатные режимы Ollama/offline_rules.

### Заявленный результат пользователя

Игрок создаёт героя. Он выбирает класс из доступных вариантов, задаёт имя/характеристики и **пишет свободное текстовое описание внешности, происхождения и биографии**, которое должно стать каноном его героя. По умолчанию **каждому новому персонажу создаётся новая уникальная кампания с новым миром**: историей, географией, магией, государствами, фракциями, NPC, их секретами, ресурсами, убеждениями и отношениями. Дополнительный режим — создание нового героя в **ранее сохранённом мире**, с учётом последствий действий прежних персонажей. Созданный мир не должен произвольно переименовываться при каждом запросе. Названия «Марния», «Луизвиль», «Кротен», «светящееся озеро» в предыдущих текстах — **лишь литературные примеры, не канон и не обязательные шаблоны**.

Мастер ≡ рассказчик ≡ **одна модель**. В основном чате: блоки «Мастер:» (описания и повествование), «Девушка:», «Стражник:» и другие NPC (их прямая речь); написанные игроком реплики показываются под именем героя. **Подписи назначает UI; не заставляй модель дублировать их в тексте.** Быстрые кнопки и служебные строки ожидания не засоряют основной журнал, собственные реплики пользователя сохраняются. Содержание не должно включать «нейтральный NPC», «ресурсы не изменены», «ИИ: описывает результат» и прочие служебные фразы.

Мастер **не предлагает только 1–3 варианта на выбор**: игрок свободно пишет, например «отказываюсь», «оскорбляю», «спрашиваю», «пытаюсь украсть», «ухожу в другой город», «хочу стать торговцем» или «хочу исследовать болото». NPC реагируют исходя из известных им фактов, характера, личного интереса и рисков; девушка не должна внезапно угрожать убийством лишь потому, что игрок отказался. Новые события возникают по причинным связям, а не по случайному шаблону. Игрок может игнорировать основной сюжет; фракции живут и действуют независимо от него.

Перед игровым стартом мастер должен **создать структурированный план мира и ситуации**, а затем постепенно раскрывать его литературными сценами без спойлеров. Мир может расширяться со временем: новые локации и NPC проходят проверку движка и становятся каноном только после регистрации в памяти мира. Все броски, HP, деньги, предметы, XP, урон, перемещения определяет движок; модель не может утверждать произвольное изменение статуса игрока вместо него. **ConflictSolver** нужен для моделирования нескольких рациональных сторон с разными интересами, знаниями, ресурсами, рисками и стратегиями. Не заменяй его «красивыми» сюжетными догадками.

## 2. API-контракт RouterAI

- Base URL `https://routerai.ru/api/v1`; модель фиксировать по ID `deepseek/deepseek-v4-pro-0813`, не alias `latest`.
- Сначала использовать `POST /chat/completions` и клиент `from openai import OpenAI` как в официальной карточке https://routerai.ru/models/deepseek/deepseek-v4-pro-0813 . `POST /responses` и `POST /messages` доступны, но не нужны в первом вертикальном срезе; не смешивать форматы.
- Ключ только через переменную окружения/локальный безопасный менеджер секретов Windows, **никогда** не коммитить в Git, логи, скриншоты, сохранения, поддержку, prompt или issue. API-ключ ≠ RouterAI Master Key ≠ MCP-токен для Codex.
- Неактивный по умолчанию режим RouterAI (нет запроса без ручного включения), нулевая фоновая активность, отсутствие автоматических покупок и платного failover на другую модель.
- Разрешать таймаут, отмену, 401/402/404/429/5xx, временную недоступность, обрыв JSON, пустой текст из-за лимита reasoning, асинхронность PySide6 без блокировки GUI. `max_retries=0` либо явно контролируемый retry после анализа возможного биллинга; игровой ход **не исполнять дважды**.
- Режим пробы: `max_tokens` около 900, ограничение числа вызовов; в релизе адаптивный бюджет 150–2000+ выходных токенов, компактный контекст обычно 3–8 тысяч. Значение `max_tokens` может учитывать токены рассуждения, поэтому измерять `usage`, `finish_reason`, качество и latency.
- RouterAI автоматически выбирает провайдера. Проверь https://routerai.ru/docs/guides/overview/provider-selection и фактический `/endpoints`. Можно указать `provider.only`/`order`, но документация описывает случаи аварийной обработки вне указанного списка; **не называй это жёсткой ценовой блокировкой**. Создать проверку прайса перед сеансом, мягкую локальную отсечку по оценке, а лимиты у аккаунта/ключа проверять в интерфейсе RouterAI и отдельно объяснить, если они только уведомительные.
- Сохранять стоимость каждого вызова (фактический провайдер/usage и цену, если API отдаёт), ID эпизода и версию промпта; ни API-ключ, ни спойлеры, ни личные данные не должны попадать в отладочные логи без согласия.

## 3. Архитектура — ОДИН ИИ, разные этапы применения

Не обязательно несколько обученных нейросетей. Для генерации мира/диалогов/литературного текста можно использовать **один и тот же** DeepSeek через RouterAI с разными специальными инструкциями/контрактами. Отдельно существует детерминированный игровой движок и исследовательский ConflictSolver на Python:

```
UI нового героя (структурированная анкета + свободная биография)
   -> CampaignBuilder (генерация структурированного досье мира, NPC, фракций, секретов)
   -> Validation -> Canonical World DB + world_id/campaign_id/hero_id
   -> Opening Scene (постепенное литературное раскрытие мира)
   -> Свободный ввод игрока
   -> Intent Parser: кому обращено, действие/вопрос/речь, цель, тон, уточнение
   -> Game Engine / ConflictSolver: допустимость, результат, изменение состояния
   -> Canonical State + Event Log + Fact Memory
   -> Narrator: художественная сцена и отдельные реплики NPC по результату
   -> UI (speakers через отдельные блоки) + Memory indexing
```

Для будущего создания новых объектов мастер выдаёт **предложения**, валидация подтверждает ID, связи, доступные правила и ограничения. Только подтверждённое событие становится новой истиной мира. Модель **не должна сама себе назначать броски, выдавать награды или разворачивать целые игровые механики текстом**.

Не передавать модели всю историю из 10 000 сообщений на каждом ходу. SQLite (встроенный FTS5) для закреплённых фактов мира, статуса сюжета, NPC (goal, beliefs, secrets, schedule, relationships, resources), приключений, последствий, способов персонажей разрешать конфликт, отобранных оригинальных эталонных фэнтези-сцен. Выделить: `objective_truth`, `player_knowledge`, `npc_belief`, `rumor`, `hypothesis`; NPC не знают секреты игрока и других NPC без игрового основания. Добавить search/retrieval по сцене, персонажам, месту, теме и актуальным конфликтам с ограниченным числом примеров. Подтверждённые сюжетные детали сохраняются, а недостоверная «красивая» фраза ИИ не становится истиной автоматически.

## 4. Данные и «обучение» — разница принципиальна

`master_system_prompt.txt` в комплекте — начальная **системная инструкция поведения** DM. Это не изменение весов DeepSeek. Предыдущее собрание 55 завязок, 330 вариаций и других карточек Codex уже оценил как **сырой материал**: есть технические фразы, одинаковые концовки, плохие дубли. Не подключай его целиком как эталон. Нужны **отредактированные качественные образцы полных взаимодействий**: оригинальный художественный мир -> анкета героя -> внутренняя секретная информация NPC -> вступление -> 5–15 настоящих ходов со свободными репликами игрока -> результаты движка -> изменившийся мир -> память -> возвращение к прошлой встрече. Отдельные кейсы: отказ от квеста, грубость, просьба купить яблоки, кража, шутка, попытка торга, уход в другой город, возвращение спустя год, сложная многосторонняя политическая дилемма.

Важнее 100 действительно хороших разнообразных размеченных сцен, чем 10 000 повёрнутых одинаковых шаблонов. Литературный язык: русский, разные длины сцен, деталь через действие, характеры в репликах, выбор без навязывания, атмосфера магии и средневекового быта. Не копируй защищённые фрагменты живых авторов и коммерческих кампаний без лицензии. TV Tropes, «Посмотре.ли», записи Critical Role и руководства по D&D — идеи/исследовательские источники, **не автоматически лицензированный тренировочный датасет**. Можно использовать собственные тексты, проверенный общественный домен и материалы с подходящими лицензиями.

План: `prompt + curated few-shot + SQLite RAG + eval` **до** обсуждения настоящего fine-tuning. Возможность и цена обучения весов DeepSeek V4 Pro через RouterAI **не подтверждены**. Не обещай fine-tune API без официальной услуги. Ни одна библиотека не может автоматически дать модели долгосрочную память; это делает приложение.

## 5. Формат чата

Применить типизированный ответ с массивом блоков, например

```json
{
  "blocks": [
    {"speaker_kind": "narrator", "speaker_id": "master", "text": "Девушка остановилась у края дороги..."},
    {"speaker_kind": "npc", "speaker_id": "npc_lena_01", "text": "Вы не могли бы мне помочь?"}
  ],
  "suggested_events": [],
  "memory_proposals": []
}
```

Это **концептуальная целевая схема**; согласовать с существующим протоколом и валидаторами, не считать уже действующим API-контрактом. UI подписывает narrator «Мастер» и NPC известным игроку именем. Слова игрока UI добавляет отдельно. Не хранить в одном тексте монолог с ролями «Мастер:», «Герой:», «NPC:» и не парсить ведущие двоеточия. Модель не должна записывать слова/решения игрока за него.

## 7. Критерии приёмки и научные метрики

- 3 героя с разной биографией → 3 **действительно** разных новых мира, не переименование одной сцены.
- Герой B может начать кампанию в мире героя A только по явному выбору; последствия поступков A сохранены и не потеряны.
- Игрок спрашивает NPC, нужна ли помощь: герой автоматически **не принимает поручение**. «Не хочу» вызывает естественную реакцию. Агрессия не равна немедленному убийству.
- Игрок уходит от завязки: мир продолжается без railroading. Не выдавать три обязательные кнопки; свободный ввод основной.
- Секрет NPC не раскрывается, пока герой его не узнал; NPC не всеведущ.
- В журнале «Мастер»/«Имя NPC»/«Имя героя», ввод игрока отображается; автоматические команды и сообщения ожидания не дублируются.
- Падение/тайм-аут RouterAI не приводит к двум броскам, двум наградам, двум изменениям мира, утере команды или разрушению GUI.
- Каждая цена и количество фактически обработанных токенов известны или помечены как неизвестные; нет выдуманной «полностью бесплатной» квоты.
- Оценка на одинаковых сюжетах с `offline_rules`, Qwen3/Ollama и DeepSeek: coherence (0–5), responsiveness (0–5), agency (0–5), adherence (0–5), NPC consistency (0–5), time, token usage and cost. Отдельный holdout, не совпадающий с образцами в RAG.
- Тесты быстры без API-ключа/сети, real API smoke — **только ручной opt-in**.
