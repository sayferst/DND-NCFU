# 1S — облачная игра и постоянная визуальная память

С версии 1U ключ, модели и бюджет изображений находятся в отдельной панели
«Художник», текстовое подключение — в «Мастер»: [инструкция](MASTER_AND_ARTIST.md).
Сведения о размещении настроек ниже относятся к предыдущей версии 1S.


Пакет от20.10.2026. Подсистема реализована, проверена на локальных тестовых
серверах и временных кампаниях. **Живой контракт RouterAI Images, реальные
картинки/цены/сходство и нативная Windows-сборка пока не проверены.**

## Изменение офлайн-режима

Пользовательский чат теперь требует включённого облачного мастера, модели,
ключа и согласия на отправку сцены. Без них появляется сообщение, ввод остаётся
в поле, герой не действует и RNG не изменяется. Просмотр знаний, картинок,
сохранений и дневника остаётся локальным. Ollama не предлагается в новом UI.

Новая игра не подставляет офлайн-деревню. Ошибка/отмена создания мира сохраняет
профиль для повторной попытки, без запасного сюжета. Пока мир не создан, Хроники
пусты, вводная не рассказывает о стражнике/жительнице. В сгенерированной кампании
показываются её реальные участники. Исторические кампании/файлы/механики старого
эпизода не удалены: это совместимость и регрессионный материал, не новый старт.
Текстовая модель DeepSeek Flash и её клиент/расчёты не заменены генератором картинок.

## Архитектура

| Файл | Ответственность |
|---|---|
| visuals/registry.py | SQLite, неизменяемые файлы, версии, alias entity→образ, расходы/резервы |
| visuals/client.py | отдельный GET/POST Images, загрузка CDN, проверка и нормализация PNG |
| visuals/policy.py | две модели, цены/единицы, разрешения/референсы, настройки |
| visuals/context.py | публичный визуальный контекст, ID типов/экземпляров/событий, референсы |
| visuals/commands.py, ui/visual_commands.py | явные команды изображения до игрового цикла |
| ui/visuals_panel.py | очередь, подтверждения, настройки, карточки, просмотр версий |
| ui/cloud_gate.py | запрет незаметного офлайн-исполнения пользовательского ввода |

Изображения не исполняют транзакции мира, не добавляют предметов/персонажей,
не бросают кубики, не меняют HP/отношения/награды. Канонический writer22 и старые
читатели не менялись. Визуальная SQLite отдельна от основной базы кампаний.

Обычный известный предмет общего типа направляется в Recraft. NPC, существа,
боссы, важные места, события, уникальные/неопознанные предметы — FLUX. При наличии
референсов используется FLUX, включая перегенерацию старого образа. Recraft
никогда не получает input_references. Общий образ типа можно выключить в карточке;
NPC и уникальные объекты не разделяют его с другими экземплярами.

У каждого файла SHA-256 и версия, связанная с campaign/entity или typeID. Имена
NPC не служат ключом идентичности. Смена имени/100других записей/перезапуск не
требуют поиска по всему литературному диалогу: SQLite находит прежнюю картинку
по постоянному ID. Общие типы разделяют образ внутри кампании; другие миры имеют
собственные файлы и связи. Версии не перезаписываются. Возврат к старой JSON-ячейке
не удаляет визуальный архив кампании; изображения являются отдельной памятью.

Для сцены выбираются публично известные присутствующие участники и объекты,
сначала персонажи/существа, затем места/предметы. Для исторического события
используется подтверждённый снимок соответствующего хода; без надёжного снимка
участники не угадываются по текущему соседству. Число референсов ограничивается
подтверждённым лимитом модели; ID и порядок использованных файлов сохраняются.
input_references содержит dataURL PNG. Если лимит/параметр не подтверждён,
идентичность не отбрасывается молча ради дешёвого запроса — генерация остановится.

Промпт задаёт общий medieval fantasy pixel art: чёткие пиксельные формы,
ограниченная палитра, единый свет/стиль, без надписей/рамок/характеристик/HUD.
Оформление карточек остаётся Qt. В запрос идут известные название, описание,
внешность/материал/роль, не скрытые кошельки, HP, планы, прошлое или принадлежность.
Даже внутренние ID не передаются как подписи референсов: используются публичные
подписи. Рисунок не делает придуманную деталь каноном. Сходство и художественное
качество зависят от модели; абсолютная визуальная идентичность не обещается.

## Хранение

Для вашей папки по умолчанию:

```text
D:\Projects\DND-NCFU-data\visuals\
    visuals.sqlite3
    settings.json
    generation.lock
    assets\<хэш кампании>\<sha256>.png
```

Это отдельная папка данных, не исходники/EXE. Backup всей DND-NCFU-data сохраняет
и визуальный архив. JSON-ячейка и экспорт основной SQLite сами по себе картинки
не включают. Для переноса нужен весь каталог данных. Отсутствующая картинка или
повреждённый кэш не запускают новую платную генерацию автоматически.

В собранном EXE данные по умолчанию находятся в `%LOCALAPPDATA%\DND-NCFU`.
Для хранения на D: задайте `RPG_VKR_DATA_DIR`; этот же путь используется исходной
версией. Ресурсы программы читаются из bundle, пользовательские данные — отдельно.

## Управление расходами

| Параметр | По умолчанию |
|---|---|
| Recraft | recraft/recraft-v4.1-flash, порог0.85₽ |
| FLUX | black-forest-labs/flux-3-image-klein, порог5₽ |
| Портрет / сцена | 1K / 1K, варианты768–4K при подтверждённой поддержке |
| Изображений в POST | 1 |
| Месячный бюджет изображений | **0₽: платная генерация не разрешена** |
| Подтверждать запрос | включено |
| Автогенерация на ходе | отсутствует |
| Автоматический повторPOST | отсутствует |
| Очередь | 1активный + до8ожидающих |

Справочные0.75₽ и0.86/0.97/1.18/1.51/3.88₽ не используются как вечный тариф.
Перед запросом выполняются GET ключа/остатка и каталога. Цена должна быть
распознана полностью: фиксированная цена image нужного варианта плюс известный
request-сбор. Непонятные token/MP/дополнительные сборы/варианты не позволяютPOST.
Стоимость сравнивается с лимитом ключа и общим месячным бюджетом изображений.
Этот бюджет общий для всех кампаний в одной папке данных, месяц считается поUTC.
Прежняя проверка ограниченного RouterAI-ключа до2000₽ сохраняется; текстовые
запросы используют тот же счёт, но отдельные метрики.

Recraft выше выбранного порога требует отдельного разового подтверждения цены.
FLUX выше порога (максимум5₽) не отправляется. Изменение положительного месячного
бюджета/согласия подтверждается отдельно в UI. После разрешения резерв суммы
создаётся атомарно вSQLite, предотвращая одновременное превышение локального
бюджета. Второй экземпляр игры не запускает генерацию при занятом generation.lock.

Известная сумма API врублях сохраняется отдельно от оценки. При неизвестной
валюте/сумме факт не превращается в0: остаётся резерв, исходная допустимая
числовая информация о счёте хранится в квитанции. Если ошибка загрузки произошла
после получения счёта, известная стоимость всё равно сохраняется.

Отмена до отправки не оплачивается. Отмена послеPOST отменяет ожидание и очередь;
сервер мог уже принять запрос. Клиент собирает результат в кэш, если ответ придёт.
Аварийно прерванныйPOST при перезапуске получает uncertain и удерживает резерв,
без повтора. Для него есть ручная сверка с кабинетом:0только при подтверждённом
отсутствии списания. Это не возврат денег и не повтор запроса.

Провайдер может сообщить сумму, отличающуюся от предварительной: приложение
сохраняет её, не подменяет лимитом. Серверная тарификация вне контроля клиента;
предварительный расчёт не является финансовой гарантией провайдера. Для реальной
проверки начинайте с минимального явно выбранного бюджета и сверяйте кабинет.

## Настройка и проверка Windows

1. Обновите исходники блоком ниже. Старые миры и изображения не удаляйте.
2. В «Настройки» включите DeepSeek Flash обычным способом. Для игрового чата
   нужен облачный мастер; для изображений используется тот же RouterAI-ключ.
3. В «Визуальная память · RouterAI Images» отдельно разрешите передачу публичных
   описаний/референсов и установите свой небольшой месячный бюджет. Это ваше
   разрешение расхода в приложении, не оплата/пополнение со стороны Codex.
4. В Хрониках выберите известный объект → «Создать изображение». В маленьком
   окне команды находятся в меню «Изображение…». ДоPOST покажется модель, размер,
   число референсов и ожидаемая цена. Проверьте и подтвердите сами.
5. Повторно откройте карточку/версии и перезапустите: новой оплаты быть не должно.
6. Создайте портрет участника, затем запросите «Изобразить сцену»: подтверждение
   должно показывать референсы. После реальной генерации сверяйте сходство и счёт.
7. В чате: «Нарисуй этого персонажа», «Изобрази последнее событие»,
   «Покажи этот предмет». При неоднозначном адресате появится выбор известного
   объекта. Просьба художнику в игровом мире не считается командой изображения.

**Перед первой живой проверкой нужен пример документации RouterAI Images.**
Из облачной среды GET /models и /docs/reference вернули403; контрактные поля
описаны в [IMAGES_API_CONTRACT.md](IMAGES_API_CONTRACT.md). Сообщение о неизвестном
тарифе/параметре не обходите выдуманной ценой. Пришлите примерPOST/ответа и записи
двух моделей безключа: можно будет сверить адаптер до первого платного вызова.
Разрешения на живую платную пробу Codex пока не получено, запросов не выполняли.

Закройте игру и выполните PowerShell:

```powershell
& {
    $ErrorActionPreference = 'Stop'
    Set-Location 'D:\Projects\DND-NCFU'
    $gameData = if ($env:RPG_VKR_DATA_DIR) { $env:RPG_VKR_DATA_DIR } else { 'D:\Projects\DND-NCFU-data' }
    $backup = Join-Path 'D:\Projects\DND-NCFU-backups' (Get-Date -Format 'yyyyMMdd-HHmmss-fff')
    New-Item -ItemType Directory -Path $backup | Out-Null
    if (Test-Path -LiteralPath $gameData) {
        Copy-Item -LiteralPath $gameData -Destination (Join-Path $backup 'game-data') -Recurse
    }
    if (Test-Path 'prompts\master_system_prompt.local.txt') {
        Copy-Item 'prompts\master_system_prompt.local.txt' -Destination $backup
    }
    git switch setup/development-environment
    if ($LASTEXITCODE -ne 0) { throw 'Не удалось переключить ветку.' }
    git pull --ff-only
    if ($LASTEXITCODE -ne 0) { throw 'Git не обновил файлы. Сохраните вывод.' }
    .\.venv\Scripts\python.exe scripts\repair_fixture_checkout.py
    if ($LASTEXITCODE -ne 0) { throw 'Проверка тестового файла не прошла.' }
    .\.venv\Scripts\python.exe scripts\check.py
    if ($LASTEXITCODE -ne 0) { throw 'Проверка не прошла. Сохраните вывод.' }
    .\.venv\Scripts\python.exe scripts\run_game.py
}
```

Новых runtime-зависимостей нет. Опциональная сборка EXE описана отдельно:
[BUILD_WINDOWS.md](BUILD_WINDOWS.md). Результаты проверок и ограничения:
[журнал приёмки](validation/images-2026-10-20/README.md).
