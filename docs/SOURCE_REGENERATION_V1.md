# Условная регенерация исходных существ

`library-regeneration-1` добавляет отдельную типизированную программу для41
закреплённой исходной карточки. У22 программ есть подавление типами урона,
у19 — явно описанная проверка смерти в начале хода при0HP. Сверены все3920
исходных существ по прежним SHA ресурсов; описания массово не экспортируются.

## Исполнение

Программа содержит величину1–100, минимальные HP0/1, конечный список типов
подавляющего урона и флаг особого момента смерти. Произвольных формул, Python,
SQL или команд рассказчика в ней нет. Все предложения и экземпляры проходят
прежний валидатор движка; библиотека не записывает здоровье живого мира.

Подавление учитывает фактически прошедший урон после иммунитетов, сопротивлений
и щитов. Смешанный пакет проверяется по компонентам один раз. Флаг действует
до следующего собственного хода и затем снимается. Регенерация выполняется
до проверки недееспособности: паралич мешает действию, но не пассивному лечению.

Если исходная формулировка прямо задаёт смерть только в начале хода без
возможности регенерации, движок откладывает смерть от повреждения до этой
проверки. Существо при0HP остаётся без сознания и сохраняется в очереди боя.
В начале хода оно восстанавливается либо умирает при подавленной регенерации.
Это отдельное исходное исключение, закреплённое в Definition, а не изменение
обычной математики `owner-rules-1`. Без такого флага массивный урон и счётчики
смерти работают по-прежнему. Смерть от шестого уровня истощения не отменяется.
Ни эта программа, ни обычное лечение не воскрешают уже погибшего актора.

Вне боя движок агрегирует восстановление по своему минутному времени:
десять потенциальных начал хода на минуту, с ограничением максимумом HP.
У полностью здорового актора без подавления нет бесполезных повторных событий.
Это политика существующего календаря движка, а не непрерывная пространственная
симуляция. В бою порядок событий привязан к собственному ходу существа.

## Совместимость

Миграция005 добавляет ревизии схем и запись программы;001–004 не переписаны.
Старые мировые Definition не получают регенерацию задним числом. Состояние
подавления и результаты хода сохраняются и проверяются полным replay. Доктор
подключения читает библиотеки версий3/4/5 без записи и автоматического обновления.
Карточка для мастера объясняет восстановление, типы подавления и момент смерти.

## Проверки и границы

Проверены реальный npc_round,0HP, составной урон, поглощение огня щитом,
однократное подавление, смерть без воскрешения, истощение, паралич,
длительное ожидание, создание исходного вегепигмея и восстановление Session/RNG.
После добавления программы128 профильных проверок прошли за95.97с;
дополнительный набор с представлением карточки выполняется отдельно.

Парсер принимает только полностью распознанные предложения. Он отклоняет
требования солнечного света, текущей воды, температуры, близости другого существа,
определённого материала оружия и неподдержанные дополнительные эффекты.
Например, рубящий урон не подменяется всем физическим уроном. Такие варианты
остаются в перечне неподдержанного. Это41 исполняемая программа, а не все
варианты регенерации на сайтах и не полное исполнение всех исходных правил.

Из корня проекта PowerShell:

```powershell
.\.venv\Scripts\python.exe scripts\build_world_library.py
.\.venv\Scripts\python.exe scripts\enrich_source_regeneration.py
.\.venv\Scripts\python.exe scripts\world_library_report.py
.\.venv\Scripts\python.exe -m pytest tests/test_source_regeneration_runtime.py -q --basetemp=work/regen-check
```

Повторное извлечение использует локальный кеш либо загружает закреплённые
ресурсы. Изменение SHA останавливает извлечение. Команды не меняют сохранения.
