# Схема25: предметы мира, точная торговля и ресурсы героя

26.10.2026 (Москва). Продолжение проверенного набора `899782f`.
Новые кампании с опцией «Приключение v3» создаются в схеме25.
Схема24 открывается прежним обработчиком `gameplay-v3-playable-1`;
новый обработчик — `gameplay-v3-playable-2`, каталог `gameplay-catalog-2`.
Старые кампании автоматически не переключаются.

## Что подключено

- Окно разговора с торговцем показывает реальные физические стопки и экземпляры
  снаряжения этого NPC. Выбор количества получает проверенную цену в медных.
  Предпросмотр не расходует деньги, предметы, время или RNG. Подтверждение вызывает
  Session; перенос, оплата, кошелёк и событие сохраняются вместе.
- Частичная покупка/продажа сохраняет происхождение split-экземпляра и его тип,
  включая последующую подготовку материала и экипировку. Сдача 0–99 медных
  не теряется при сохранении JSON/SQLite. Кошелёк NPC не показывается игроку.
- В сгенерированном мире ассортимент не создаётся из первого обращения к NPC.
  Нужны существующие товары/предметы, проданные этому торговцу. Прежний учебный
  торговец сохраняет объявленный авторский ассортимент.
- Купленное/взятое обычное оружие, броню или щит можно передать из инвентаря
  мира в снаряжение. Предпросмотр показывает итоговую карточку и прочность;
  отмена ничего не расходует. Одна исходная единица превращается в один новый
  экземпляр с именем, базовой ценой и полным снимком происхождения.
- Карточка подтверждается по поддержанному оружию/AC. Противоречивые кубики,
  число рук, нестандартный щит и неподдержанные эффекты отклоняются. Новый урон
  действительно берётся из экипированного экземпляра через общий боевой resolver.
- Износ исходного предмета влияет на его цену. При переводе в шкалу снаряжения
  0–20 используется округление вниз: `condition*20//durability`. Это явно видно
  до подтверждения; оригинальные числа сохраняются в происхождении. Базовая цена
  не заменяется ценой стартового каталога: дешёвое оружие нельзя выгодно
  перепродать только за счёт такого перевода.
- HP/ST/MP рассчитываются новому герою и растут от подтверждённого XP/наград.
  Обычная проверка, давшая уровень, применяет HP в том же атомарном ходе, включая
  пассивный тик. При загрузке проверяется и первичное действие, и рост ресурсов.
- Предыдущая практика уровня1–2 в схеме25 не начисляется параллельно новому XP.
  Прежние команды усилия/исследования учебного эпизода направляются в настоящие
  skill-проверки; обучение идёт через новый экран навыков.
- В конструкторе шесть талантов и предпросмотр фактических HP/ST/MP и стартового
  набора. Ресурсы и поддержанные карточки также передаются Мастеру как данные.
  Спящий/закрытый собеседник не выдаётся ему как присутствующий.

## Зафиксированные числа

Модификаторы остаются `(score−10)//2`, новый герой 8–16, бюджет24.
Для уровня L и текущих подтверждённых характеристик:

- HP: `16 + 2×CON_mod + max(1,6+CON_mod)×(L−1)`.
- ST: `max(10,20+2×(STR_mod+CON_mod)) + 3×(L−1)`.
- MP при доступе к магии: `max(4,12+4×INT_mod+4×(L−1))`, остальным0.

Рост максимума HP/ST добавляет только разницу, а не полное лечение. Рост MP
не пополняет запас. Отдых8часов восстанавливает HP/ST/MP вне боя. Выбывший герой
отдыхом не оживляется. Формулы — авторские кандидаты пособия, не таблицы SRD.

Расход ST: атака2, магия/уклонение/манёвр/бинт/подготовка материала1, изготовление3,
ремонт2; обычный переход10минут —1ST. У безопасного отхода стоимость0, поэтому
истощение не запирает героя в бою. Недостаток проверяется до бросков и расхода.

Таланты первого набора (+1Сила, +1Интеллект, +2лечение) сохранены. Добавлены:
«Крепкий» +2maxHP, «Выносливый» +4maxST, «Сосредоточенный» +4maxMP только после
доступа к магии. Право на талант: начальное и уровни5/10/15/20, один ID один раз.
Сам талант не выдаёт заклинаний и XP. Шесть вариантов покрывают пять наград.

Цена физического товара учитывает его текущую прочность. Покупка умножается
на суточный коэффициент100/110/120%, продажа — половина базы с округлением вниз
для всей партии. Партия дешевле медной монеты отклоняется, а не округляется
в бесплатный товар. Нехватка денег проверяется у обеих сторон.

## Ручная проверка

После обновления исходников:

```powershell
Set-Location D:\Projects\DND-NCFU
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Обновление не выполнено' }
.\.venv\Scripts\python.exe scripts\check.py
if ($LASTEXITCODE -ne 0) { throw 'Проверки не прошли' }
.\.venv\Scripts\python.exe scripts\run_game.py
```

Создать нового героя, включить «Приключение v3», выбрать начальный талант.
На «Подтверждении» сверить HP/ST/MP. В мире подойти к реально присутствующему
торговцу: купить часть стопки, продать часть обратно, проверить медные и остаток.
На странице героя выбрать купленное оружие из инвентаря мира → «Подключить» →
сначала отменить, затем подтвердить → экипировать → провести бой → сохранить/
загрузить. Карточка предмета должна содержать поддержанную механику. Если нужного
товара в мире нет, он не появится только от просьбы игрока.

После выхода/возвращения проверить ST; после отдыха — восстановление.
Старая кампания по-прежнему открывается своим набором. Новый Setup/EXE требует
пересборки на Windows. Git pull получает изменения лишь после их публикации;
локальный коммит среды сам по себе не обновляет диск D:.

## Оставшиеся ограничения

Сохраняются дуэльный бой/скалярная дистанция, малый набор магииI–II и рецептов,
описательные виды, отсутствие полноценной миграции старой копии/rollback,
полного графа знаний и стратегических фракций, полных боевых состояний/лут-таблиц.

уже адаптированного снаряжения пока не включены в общий планировщик вещей.
