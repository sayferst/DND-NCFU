## Реализация

- BAT обновляют и собирают `feature/unified-rpg-automatic-gm`, не переключают
  ветку и не сбрасывают изменения. Выводится фактический SHA сборки. Четыре
  настоящих PowerShell/Git-сценария уже прошли на Windows в CI40591554086.
- Новый `catalog-v2.json` сохраняет все3360ID. Несущие материалы ограничены
  конструкцией, обработка названа отдельно для каждого сырья, исправлены
  названия существ/добыча и расход для конкретного результата ремесла.
  Уровень изделия учитывает доступность обработки его основы. Валидатор
  отклоняет травяные мечи, бесплатные/самовоспроизводящиеся рецепты и отсутствующие входы.
- Старый `catalog-v1.json` не изменён. Старые origin без `catalog_revision`
  используют ревизию1. Новые герои интерфейса автоматически используют2.
  Это внутренний вариант данных схемы31, не новый режим или интерфейс игрока.
- Поиск до ограничения16ранжирует весь доступный пул, учитывает русские
  окончания и словарь намерений. Проверены120адресных запросов безID и синонимы.
  Результат поиска не даёт доступа к неизученной или недоступной технике.
- UI показывает фактический расход выбранного изделия, станцию и время;
  кнопка ремонта использует выбранный ремонтный рецепт.
- Новая ревизия связывает списание резерва, двухдневную поставку, задержку
  на закрытой дороге, поступление, переработку, физическое пополнение продавца
  и цену по реальным запасам. Фракционное производство пищи использует травы,
  не древесину. Записи причин содержат реальные изменения балансов.
- Экологический MVP: ограниченные когорты травоядных/хищников, пища, потери,
  размножение при наличии пищи, ареалы и конечный бюджет встреч. Демографический
  MVP считает иждивенцев с расходом пищи; не создаёт полноценные индивидуальные
  детские NPC. Миграция перемещает существующих голодающих жителей по соседним путям.
- Только новая ревизия допускает10000ходов. Полный журнал операций сохраняется;
  дублированные turns/memory/narrations в снимке заменены проверяемыми хэшами.
  Reader заново исполняет операции и сверяет итог, историю не обрезает.
  Старые кампании остаются при прежнем лимите/формате.
- Полный проверочный набор запускается небольшими отдельными процессами с
  JUnit и общим отчётом. Подсчёт включает все файлы из конфигурации набора;
  ошибка/потеря отчёта не превращается в успешный итог.

## Включение

Обновить ту же ветку обычным `git pull --ff-only`. `Команды/BUILD_EXE.bat`
собирает личную версию без хоста; `START_HOST.bat`, затем `BUILD_SETUP.bat` —
версию с учётными записями. Ключи и пароли повторно задавать не нужно.
Для новых правил создайте нового героя; старые ячейки не конвертируются молча.
Прямой запуск: `.\.venv\Scripts\python.exe scripts\run_game.py`.
Полная проверка: `.\.venv\Scripts\python.exe scripts\check.py`.
Игроку не нужны импорт10kJSONL, ручной выбор ревизии, ML-зависимости или настройка RAG.
