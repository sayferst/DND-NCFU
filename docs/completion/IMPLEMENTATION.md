## 1. Изменённые модули

- `domain/game_catalog.py`, `catalog_authoring.py`: структурированные авторские
  данные и проверки ссылок, эффектов, обязательных полей, чисел и дублей.
- `catalog_engine.py`, `catalog_effects.py`, `catalog_actions_v2.py`: выполнение
  через существующий Session, физический Catalog/InteractiveWorld и общий RNG.
- `catalog_world.py`: ресурсы поселений, потребности, расписания, события и проекты фракций.
- `unified_session.py`, application/storage: новая схема31, повтор операций,
  компактные исторические квитанции и прежний путь чтения схемы30.
- Qt creator/unified_panel/copper_shop/main_window: действующие игровые кнопки,
  простой конструктор, поиск доступного обучения, торговля и физические вещи.
- narrative/catalog_protocol, planner/writer: проверяемая заявка вместо изменения
  состояния прозой, текущие ресурсы и последний подтверждённый ход для памяти.
- training/capture_session: явный локальный экспорт кандидатов с проверенными квитанциями.
- scripts: генерация/аудит каталога, живой A/B, изолированная проверка Windows Setup.

## 5. Что исполняется

Урон и критические кубики, HP/MP/ST, расход вещей/боеприпасов, сопротивления,
состояния и их истечение, лечение/снятие состояний, возврат сознания, отражение,
отложенные/поддерживаемые эффекты, раскрытие существующих объектов/путей/ресурсов,
перемещение по зарегистрированным путям, реальные инструменты/станции,
изучение, расход материалов, производство с качеством/неудачей, ремонт,
физическая передача товаров и денег. Смерть не отменяется обычным возвратом сознания.

В группе до8 участников; инициатива бросается автоматически. NPC расходуют ST,
лучники — конечные боеприпасы, заклинатели — MP; раненые могут лечиться/отступать.
Код из JSON не исполняется: эффекты выбираются из закрытого перечня обработчиков.

## 6. Что доступно игроку

Воин, лучник, плут, маг, жрец, ремесленник. Четыре простых страницы создания,
один начальный талант, характеристики и описание. Нет выбора версий приключения
или валюты навыков. Подготовка растёт с уровнем; повышения характеристик и
выбор талантов доступны на соответствующих уровнях. Изученные способности
используются на странице героя; маг и жрец изучают собственную магию, остальные
могут пользоваться свитками. Рецепты изучаются; фильтр учитывает уровень.
Для ковки/алхимии/производства нужны соответствующие рабочие места.

Новые кампании создаются со схемой31 автоматически. Старые1–30 не переводятся
на новый каталог при загрузке. Схема30 проверена на сохранении, сделанном исходным
коммитом до изменений. Внутренний content_revision обслуживает совместимость,
в интерфейсе его нет. Опубликованный catalog-v1 нельзя молча переписывать:
будущее изменение требует новой версии данных и сохранённого обработчика31.

## 7. Мир

Часы, сутки и сезонные условия; конечные местные узлы сырья/резервы/склады,
добыча и переработка, еда/голод/усталость жителей, расписания, перемещения,
отношения и передача подтверждённых сведений; изменение спроса, временное
закрытие лавки, погода/паводок, снабжение, столкновения и фракционные проекты.
Проекты тратят реальные деньги и материалы, зарплата поступает конкретному NPC.
Рассказчик получает только местные наблюдения и известные сведения о фракциях.

Это конечная авторская симуляция. События выбираются из400 записей с условиями,
не моделируется произвольная демография/макроэкономика/любая профессия/весь мир.
Стартовые ресурсные узлы типовые; биомы и полный экологический спавн ещё не
моделируются. Полной симуляцией мира этот набор не объявляется.

## 9. Исправленные ошибки

Кожа/кожаный доспех в стартовом наборе; восстановление проданной части стопки;
дубли торговых строк; безоружный неподдержанный D2; непоказанные физические вещи
в кратком инвентаре; новые UI-проверки, ранее ожидавшие30; чтение календаря до
создания мира; потеря факта последнего действия в вопросах памяти. Новая защита
от ошибочного «мана полна» и смешанных меток вроде «cold-белое» проверена тестами.
Заголовок новой игры показывает реальные HP/MP/ST и медные вместо старого
виртуального счётчика бинтов. Предварительная проверка заявки ИИ использует
текущее состояние и копию RNG, без загрузки и повторного проигрывания всей истории.
Отдельный тест запрещает Session.from_dict на этом пути и проверяет однократное
применение действия после подтверждения.
Локальный замер синтетической истории200ходов: медиана12.71мс для preview
против4725.26мс для reload+execute; исходный Session/RNG не изменились.
Методика и все повторы — preview-benchmark-01.json; это не замер модели/Windows.

Нативные Windows-прогоны нашли ещё две ошибки переносимости: чтение тестового
сохранения через системную кодировку и печать русского JSON в CP1252 stdout.
Первая исправлена явным UTF-8; во второй файл остаётся UTF-8, а stdout использует
ASCII-экранирование JSON. Коды завершения проверяются по-прежнему. Добавлена
безопасная диагностика запуска без текста исключений, локальных переменных и ключей.

## 15. Ограничения

- Нет реального LoRA, весов, GPU и человечески проверенного SFT-набора.

  проверены по записям и правилам, а не длительным ручным прохождением.
- Мир имеет конечные перечисленные политики; полной симуляцией не объявляется.
- Малая живая A/B-выборка не оценивает длительное качество и не включает локальные модели.
- Автоматическая Windows/Setup-проверка пройдена; ручная приёмка на ПК владельца,
  реальном мониторе и чистой пользовательской системе ещё не выполнена.

## 16. Обновление и включение

Новые возможности включены для новых героев. Старые ячейки сохраняются на своих
правилах. Нельзя продолжить старую кампанию под другим каталогом простым переключением.

```powershell
Set-Location D:\Projects\DND-NCFU
git fetch origin feature/unified-rpg-automatic-gm:refs/remotes/origin/feature/unified-rpg-automatic-gm
git switch feature/unified-rpg-automatic-gm
git pull --ff-only origin feature/unified-rpg-automatic-gm
.\.venv\Scripts\python.exe scripts\check.py
.\.venv\Scripts\python.exe scripts\run_game.py
```

При локальных изменениях Git остановит несовместимое переключение: не удаляйте
сохранения/фикстуры и не применяйте reset --hard ради обновления. Новых зависимостей
для игры нет. Создайте нового героя, откройте «Герой»: изучение, магия,
производство, предметы и развитие работают через один Session. Для обычной игры
не нужны команды training или импорт архива.
