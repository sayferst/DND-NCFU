## Порядок работы после отдельного разрешения

1. Уточнить, кто арендует и какой доступ доступен: SSH или терминал Jupyter.
   Пароли/приватные ключи не отправлять в чат; платный запуск и загрузка~24GB
   исходных Safetensors требуют отдельного согласования владельца.
2. В кабинете выбрать обычную аренду и Linux x86_64. Подойдёт шаблон PyTorch/Jupyter
   с установленным драйвером; проект создаст своё закреплённое Python3.12-окружение.
   Его код не устанавливает драйверы и не меняет защищённые настройки.
3. Передать только папку `gpu-ready` из готового приватного архива. В ней разрешённая
   синтетика; исходные частные сейвы/архив V3 для обучения не нужны.
4. Выполнить аппаратную диагностику, установить отдельный stack и скачать точную базу
   командами из START_HERE_RU.md. Режим установки сам не выбирает тариф и не оплачивает
   сервер. Текущий игровой GGUF переносить для обучения не требуется.
5. Запустить dry-run и настоящий smoke:2 шага на длинном и медианном примерах.
   Проверить loss, VRAM, сохранение и reload адаптера. При ошибке сохранить диагностику;
   полный запуск до исправления не делать. Не считать два шага готовой моделью.
6. По реальной скорости пересчитать оставшееся время. Полный профиль:880 train,
   одна эпоха, около55 optimizer steps;110 val и110 test отдельно. Обучение,
   независимая оценка и возможный экспорт должны укладываться в остаток бюджета.
7. Сохранить адаптер, training-manifest, конфиги, отчёты и checkpoint на свой компьютер.
   Платную машину не держать включённой в ожидании человеческой оценки. Merge/GGUF
   и включение в игру требуют отдельной проверки результата, описанной в V4.

В текущей среде нет GPU и доступа к аккаунту/арендованной машине. Выполнены только
публичные чтения каталога. Пока не подтверждены аренда и крупная загрузка, реальный
GPU-эксперимент остаётся заблокирован этими внешними условиями.
