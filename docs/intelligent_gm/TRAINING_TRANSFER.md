# Переход от игровой Faun к QLoRA

Актуальный полный синтетический корпус, новые команды и ограничения: [TRAINING_DATA_V4.md](TRAINING_DATA_V4.md). Ниже сохранено описание прежнего этапа; оно не заменяет статус V4.

03.11.2026. Игровая Faun Q4_K_M на Acer установлена и отвечает. Для выбранного
QLoRA-пути Iris Xe не подходит: нужны NVIDIA CUDA, BF16 и память выделенной GPU.
Рабочая цель — одна RTX3090/4090 с24ГБ, Linux x86_64 и Python3.12.16ГиБ — только
нижний программный порог, не обещание вместимости; длинные примеры требуют больше.
Окончательная совместимость проверяется реальным smoke, а не названием GPU.

## Что переносится

GGUF7,5ГБ остаётся на Acer. На GPU-компьютере отдельно загружается исходная
Faun Safetensors закреплённой revision bdfc761b14feb9dd03ef158a4d337fc1cf5fd183,
около24ГБ. Обратная конвертация игрового GGUF в обучаемые исходные веса не нужна.
Полные исходные веса заморожены; QLoRA оптимизирует небольшой LoRA-адаптер при
4-bit NF4/double-quant базовой модели. После обучения: независимая проверка →
одобрение → merge с исходной Faun → GGUF Q4_K_M → отдельная тестовая копия в игре.
QLoRA не обещает ускорить CPU-инференс12B на Acer.

До получения разметки можно подготовить весь контур. На Acer из папки проекта:

```powershell
.\.venv\Scripts\python.exe -m training.prepare_faun_transfer --output ..\DND-NCFU-data\faun-qlora-transfer-v1.zip
```

Файл должен быть новым. ZIP содержит инструменты, Linux hash-lock,
faun-smoke.json/faun-full.json с разными output, инструкции и manifest SHA.
В нём нет модели, датасета, ключей, сейвов или готового обучения. Без одобренных
данных dataset_sha256=null и preflight возвращает BLOCKED_DATA. Это ожидаемо.

После появления подготовленного gm-sft-v1 можно собрать НОВЫЙ архив с
`--dataset ПАПКА_ПОДГОТОВЛЕННОГО_ДАТАСЕТА`: проверяются права/метки, SHA split,
непересечение кампаний/ID и непустой test; SHA закрепляется в конфигурациях.
Сам датасет всё равно не включается и передаётся отдельно только с разрешением.
Оценки действий Excel не равны SFT рассказчика: для него нужны проверенные
художественные ответы с настоящими квитанциями. Синтетика не допускается автоматически.

## Порядок на GPU-сервере

Распаковать весь ZIP в новую папку; команды выполнять из её корня.
Нужны хотя бы60ГиБ свободного диска под base/кэш; разумный старт —100ГБ NVMe,
32ГБ системной RAM,4–8 CPU и полный SSH-доступ. Экспорт/merge потребует большего
запаса ресурсов и отдельной проверки. Один контейнер с CUDA не является гарантией
совместимости: закреплённые пакеты пока не проверены реальным Faun batch.

```bash
python3.12 -m training.hardware_preflight --scope friend_gpu --output hardware-001.json
python3.12 -m training.setup_faun_gpu --install-stack
python3.12 -m training.setup_faun_gpu --download-base
.venv-faun/bin/python -m training.train_lora --config faun-smoke.json --dry-run
```

Первые установки/загрузка весов запрашивают отдельное подтверждение. Скрипты
не арендуют сервер и не меняют драйверы/защищённые настройки. PyTorch проверяет
реально выбранную CUDA device0: VRAM/BF16; другая большая карта в nvidia-smi
не делает маленькую выбранную подходящей. При нескольких GPU сначала задать
CUDA_VISIBLE_DEVICES. Qwen-профиль и зависимости самой игры сохранены.

При READY и одобренных данных:

```bash
.venv-faun/bin/python -m training.train_lora --config faun-smoke.json --smoke-test
.venv-faun/bin/python -m training.train_lora --config faun-full.json
```

Первый запуск выполняет2 реальных шага и проверяет сохранение/reload адаптера.
Полный запуск допустим после разбора smoke/loss/VRAM. Сохранение checkpoint каждые
100шагов; resume требует прежней конфигурации и настоящего checkpoint своей output.
Не хранить единственную копию результата на временном сервере. Экспорт и независимая
оценка описаны в [GPU_FAUN_WORKFLOW.md](GPU_FAUN_WORKFLOW.md).
