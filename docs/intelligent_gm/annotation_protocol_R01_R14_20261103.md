# DND-NCFU — утверждённый протокол разметки R01–R14

**Основа:** гибрид D&D 5e и авторских правил DND-NCFU.

**Статус:** R01–R14 утверждены владельцем, но это не человеческое одобрение каждой строки Excel. Разметка остаётся `AI_PROPOSED`, пока конкретные примеры не проверены.

## Решения

### R01
Само объявление действия означает согласие на обычный риск. Мастер предупреждает о последствиях, но не требует второго подтверждения.

### R02
Характеристика проверки зависит от действия, выбранного способа, навыков и инструментов, а не всегда от Ловкости.

### R03
Последствия провала соразмерны риску: время, повреждение, расход материалов либо поломка.

### R04
Маг может осознанно превысить запас MP за HP или истощение; неизвестное заклинание не возникает.

### R05
Доступный чужой предмет можно физически взять, но право собственности не переходит; возможны реакции владельца и свидетелей.

### R06
Натуральная 20 даёт наилучший физически возможный результат, натуральная 1 добавляет осложнение. Невозможные эффекты не возникают.

### R07
При 0 HP персонаж без сознания; проходит проверки смерти; союзники могут стабилизировать.

### R08
Заранее объявленная подходящая несмертельная ближняя атака может оставить цель без сознания при снижении HP до нуля.

### R09
Разумное предложение распределения ресурсов вместе с успешным Убеждением обязывает участвующие стороны принять соглашение.

### R10
За каждый недостающий MP — 2 HP, ИЛИ один уровень истощения за каждые 2 недостающих MP (округление вверх); Аркана DC 10 + 2×нехватка MP; цена уплачивается даже при провале; не более 3 MP перерасхода на одно заклинание.

### R11
Первая помощь стабилизирует, но не возвращает HP; подтверждённое лечение ≥1 HP возвращает сознание живому; мёртвых обычное лечение не оживляет.

### R12
Воскрешение возможно только специальным известным заклинанием или подтверждённым ритуалом с редкими ресурсами, стоимостью и ограничениями; обычное исцеление не помогает.

### R13
При 0 HP бросать d20 проверки смерти: 10–20 — успех, 1–9 — провал. Три успеха — стабилизация, три провала — смерть. Натуральная 1 засчитывает два провала; натуральная 20 немедленно восстанавливает 1 HP. Первая помощь: проверка Медицины DC 10 для стабилизации.

### R14
Предложение разумно, если оно выполнимо, участвующие лица уполномочены распоряжаться нужными ресурсами и жизненно важные ограничения каждой стороны соблюдены. После успешного Убеждения участвующие стороны обязаны принять такое соглашение.

## Порядок применения R13 — проверки смерти

- После достижения 0 HP живой персонаж находится без сознания; подсчёт успехов/провалов ведёт движок.
- Для каждой проверки смерти бросается d20; 10–19 = один успех, 2–9 = один провал, натуральная 1 = два провала, натуральная 20 = немедленное восстановление 1 HP и выход из бессознательного состояния по R11.
- Три накопленных успеха стабилизируют при 0 HP; три накопленных провала означают смерть.
- Стабилизация через Медицину DC 10 не восстанавливает HP. Воскрешение после смерти — только по R12.
- **Не определено владельцем:** последствия нового урона по персонажу при 0 HP, урон, превышающий HP, правила сброса счётчиков после повторного падения в 0 HP, периодичность проверок вне боя. Не добавлять тайно эти правила из D&D без согласования.

## Порядок применения R14 — обязательное соглашение

1. Сначала проверить реальные ресурсы и физическую исполнимость именно предложенного плана.
2. Проверить полномочия на соответствующие ресурсы у сторон, чьё согласие должно связать их обязательством.
3. По доступным фактам определить жизненно важные ограничения каждой стороны. **Если их значения неизвестны, разумность не подтверждена; нужен контекст, а не бросок с гарантией соглашения.**
4. Если шаги 1–3 пройдены, провести проверку Убеждения. При успехе стороны, участвующие в проверяемом соглашении, обязаны принять его. При провале автоматического согласия нет.
5. Фактические перемещения ресурсов выполняет только движок; протоколируются отказ/согласие, время, ресурсы и отношения NPC. Успешный бросок не создаёт несуществующий товар и не распоряжается имуществом отсутствующих лиц.
6. **Не определено численно:** минимальные жизненно важные пороги для каждой группы, условия полномочий в спорной собственности, DC Убеждения. Для таких строк оставить `CLARIFICATION_REQUIRED` и причины.

## Дополнительные открытые вопросы

- R10: можно ли оплатить цену магического перерасхода HP, доводящую мага до 0 HP; максимум уровней истощения; защита от циклов самохил/восстановление MP.
- R13: получение урона при 0 HP и сброс/восстановление счётчиков.
- R14: операционное определение «жизненно важной потребности» в разных сценах и порогов групп.

## Реальное состояние игрового движка (проверено по исходникам ветки codex/intelligent-gm-20261103)

| Правило | Реализация / ограничение |
|---|---|
| R13 | `catalog_engine.Engine.change_hp` переводит NPC при 0 HP в `life=unconscious`, однако не ведёт счётчики трёх death saves. В проверенном `unified.py` при HP0 нет цикла проверок смерти. Это требование к коду, не реализованное поведение. |
| R11/R12 | `catalog_effects.py` различает операции `heal` и `revive`, но `revive` при HP0 добавляет HP без явной проверки отдельного состояния подтверждённой смерти; не приравнивать этот эффект к утверждённому ритуалу воскрешения. |
| R10 | `unified.py` отклоняет `cast` при нехватке MP. Осознанная оплата HP/истощением, DC перерасхода и лимит 3 MP пока не реализованы в проверенном пути. |
| R14 | `food_negotiation.py` использует фиксированный DC 15 и пороги полезности NPC `reservation` с `accepted = persuasive and all(...)`. Это не проверяет в утверждённом виде полномочия и жизненно важные ограничения; принятие разумного предложения пока не гарантировано по R14. |
| R02 | `attempt_plans.py` использует d20 + Ловкость для общего `transform`, а не динамический выбор характеристики. |
| R05 | `attempt_plans.take` при чужой собственности требует уточнение передачи/кражи и после подбора переписывает `owner` в `hero`. Это расходится с раздельным физическим владением и юридическим правом по R05. |
| R06 | `attempt_plans.transform` ориентируется на итог броска и не выделяет натуральные 1 и 20 для утверждённых крайних исходов. |

Эти расхождения не исправлены самим документом. Для работы игры нужны отдельные изменения Python, тесты и версионирование правил без переписывания старых сохранений.

## Статус корпуса

- В Excel v2 находятся 20 тематических семейств × 10 формулировок × 5 вариантов условий = 1 000 синтетических кандидатов, не 1 000 реальных игровых квитанций.
- В очереди `HUMAN_FIRST` 200 строк, в `AI_LATER` 800, распределение задаёт `training/annotation_v2.py`.
- Размеченные ИИ строки не получают `HUMAN_APPROVED` и не допускаются к SFT. Ответы мастера могут быть обучающими только при подтверждённых фактах и законной процедуре допуска.
