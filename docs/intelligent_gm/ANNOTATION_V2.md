# Разметка сценариев v2

Файл для работы: [scenarios-1000-v2.xlsx](scenarios-1000-v2.xlsx).
Исходная v1 сохранена без изменений. В v2 — те же1000 устойчивых ID,
20 семейств,200 формулировок и5 вариантов условий для каждой формулировки.
Это синтетические задания, а не1000 сыгранных эпизодов.

Сначала сохраните личную копию вне Git, например в соседней папке
`DND-NCFU-data/annotation`. Не заполняйте единственный экземпляр внутри проекта:
Git-обновления не должны затрагивать вашу разметку.

На листе «Действия игроков» включите фильтр «Очередь разметки» → «Сначала человеку».
Выборка содержит200 строк:40 на каждый тип условий,10 на каждое семейство;
условия меняют доступ, ресурсы, состояние инструмента и известность обстоятельств.
Каждая из200 формулировок представлена в ручной выборке ровно один раз.
Остальные800 строк предназначены для предложения меток и последующей проверки.

Заполняйте удобные поля: возможность попытки, достижимость цели, D20, исходы,
риски, расход. Ответ мастера и его оценку можно внести на первом или втором листе.
Если заполнены оба, совпадающие поля должны согласовываться. Для отрицательной
оценки используйте `-`; введённый знак `−` импортёр тоже понимает.
Неизвестное отмечайте «Неясно», а необязательные поля оставляйте пустыми.
Книгу можно сохранить и импортировать частично заполненной.

Обычная попытка с метлой допустима; устойчивый полёт без работающей способности
недостижим. Большой D20 не восполняет отсутствующий ресурс. Смотрите отдельный
лист «Примеры разметки»:20 программных иллюстраций объясняют решения, но
не считаются вашими оценками. Проверка человеческого литературного качества
не заменяется этими примерами или pytest.

Исходные факты защищены от случайного редактирования, технические ID/источник
скрыты. Защита листа служит удобству: импортёр независимо проверяет все ID,
отсутствие дублей, исходные факты, допустимые метки и формулы в импортируемых
листах. Нельзя вставлять Excel-формулы в ответы или комментарии.
На листе «Статистика» используются16 обычных COUNTIF/COUNTIFS/COUNTA-формул;
Excel должен пересчитать их при открытии. Проверены синтаксический разбор
openpyxl и ожидаемые значения по исходным строкам; нативный Excel здесь не запускался.

На листе «Конфликтные ситуации» — четыре действительно рассчитанные альтернативы
одного авторского продовольственного состояния, включая полезности и Pareto.
Ручная оценка и комментарий сохраняются при импорте. Это корпус математических
конфликтов, а не дополнительные реальные партии.

Из PowerShell **в папке проекта**, после сохранения вашей копии:

```powershell
.\.venv\Scripts\python.exe -m training.annotation_v2 --input ..\DND-NCFU-data\annotation\scenarios-owner-v2.xlsx --output ..\DND-NCFU-data\annotation\import-v2-001
```

Папка результата должна быть новой. Получатся раздельные `action_labels.jsonl`,
`narrator_reviews.jsonl`, `verified_episodes.jsonl`, `math_conflicts.jsonl` и
manifest с SHA книги и количеством записей. Пустые поля не отклоняют всю книгу.
`verified_episodes` при импорте Excel пуст: придуманные задания не становятся
подтверждёнными игровыми эпизодами. Допуск в SFT всегда0.

Когда вы действительно проверили строку, выберите «Одобрено человеком» либо
«Отклонено человеком», укажите одинаковое имя/псевдоним в «Кто проверил» и
передайте импортёру `--reviewer ИМЯ --confirm-human-review`.
Это явное подтверждение уже выполненной проверки. Без него человеческий статус
отклоняется. Одобрение решения о действии не одобряет автоматически ответ на
другом листе. Одобренное действие требует трёх решений: попытка, цель, D20;
одобренный ответ требует текста и оценки. «Допущено в обучение» из Excel запрещено.

Если v1 уже заполнена, создайте **новую** книгу с переносом:

```powershell
.\.venv\Scripts\python.exe -m training.annotation_v2 --carry-from ..\DND-NCFU-data\annotation\scenarios-owner-v1.xlsx --output ..\DND-NCFU-data\annotation\scenarios-carried-v2.xlsx
```

Исходник не перезаписывается. Полные исходные ячейки обоих листов остаются в
архивных листах; совместимые поля переводятся в v2. Общая «Ручная разметка»
действия v1 переносится в пояснение ограничений, не подменяет оценку рассказчика.
Сложность v1 также сохраняется в пояснении; никакое решение человека не выдумывается.

Новый импорт вызывается через `training.annotation_v2`; старый модуль
`training.annotation` оставлен для совместимости с v1.

Проверки: [независимый разбор и пересохранение](../validation/faun-owner-v2-2026-11-03/xlsx-independent-01.json),
[12 регрессий v2](../validation/faun-owner-v2-2026-11-03/excel-final-12.txt).
