# Faun: подготовленный путь и реальные блокировки

Проверенные публичные метаданные от03.11.2026:
[Faun](https://huggingface.co/limloop/MN-12B-Faun-RP-RU), revision
`bdfc761b14feb9dd03ef158a4d337fc1cf5fd183`; GGUF revision
`25523f7d9bccf7a6c7335bd64282b5f43f4118ca`.
Карточка объявляет Apache2.0; это merge трёх моделей, происхождение исходных
обучающих данных независимо не доказано. Веса не скачивались.

В config.json: MistralForCausalLM,40слоёв, hidden_size5120, vocab_size131074,
Transformers5.3.0. В tokenizer_config класс TokenizersBackend; шаблон находится
в отдельном chat_template.jinja и использует ChatML. Старый стек Transformers4.51.3
нельзя считать совместимым по предположению. Новый профиль и отдельный candidate
стек описаны в `training/configs/faun_qlora_v1.json` и requirements-faun.in;
совместимость на GPU ещё не подтверждена настоящим тренировочным батчем.
Рабочая Qwen-конфигурация и runtime lockfile не изменены.

В train/serve Faun не получает enable_thinking=False. Проверяются архитектура,
SHA шаблона, наличие исходного Safetensors index и слои LoRA. SFT токенизируется
полным шаблоном с ответом, loss маскирует префикс. Данные дополнительно защищены
SHA каждого split. Настоящий запуск включает BF16 preflight, checkpointing,
оптимизацию, сохранение и повторную загрузку адаптера; экспорт по-прежнему требует
несмоковый manifest и настоящее владельческое holdout approval. Наличие кода не
является результатом обучения. Фактически оптимизационных шагов0, адаптеров0.

CPU-диагностика этой Linux-среды дала BLOCKED_HARDWARE; отдельный локальный
probe — BLOCKED_PROVIDER. Отчёт не относится к ноутбуку владельца. Проверка
физического Windows-ПК остаётся внешней блокировкой. Транспорт существующего
OllamaClient проверяется настоящим loopback HTTP с тестовым сервером и Faun-tag;
это проверка протокола, не инференс весов. Для Faun из локального HTTP-пакета
удаляется Qwen-параметр think; DeepSeek и прочие провайдеры сохранены.

На ноутбуке владельца, без скачивания моделей:

```powershell
Set-Location D:\Projects\DND-NCFU
.\scripts\diagnose_faun.ps1 -Output faun-hardware-report.json
.\.venv\Scripts\python.exe -m training.ollama_probe --output faun-local-report.json
```

Ожидается отчёт о реально найденной памяти/диске/движке/GPU, а не установка.
Если модели нет, probe выдаст BLOCKED_MODEL; он никогда не делает pull.
После отдельного разрешения на7.48ГБ-класс загрузки пользователь может выполнить
официальную команду `ollama run hf.co/limloop/MN-12B-Faun-RP-RU-GGUF:Q4_K_M`.
В этой работе она не запускалась. Уже установленная копия повторно не скачивается.
После установки `training.ollama_probe --measure` сохраняет загрузку/латентность/
токены в секунду/контекст/ответы; потребление RAM и художественное качество
нуждаются в отдельном наблюдении и человеческой оценке.

Компьютер друга: сначала тот же hardware_preflight со scope friend_gpu, затем
отдельное Linux/WSL NVIDIA-окружение с requirements-faun.in и локальными весами
указанной ревизии. Переносить только одобренный обезличенный dataset с SHA;
ключи приложения, сейвы и приватные диалоги не передавать. После CUDA/BF16 и
реального batch preflight выполнить --smoke-test, проверить checkpoint и holdout,
только затем полное обучение в пределах разрешённого оборудования. Никакой
аренды GPU или оплаты автоматически нет. Характеристики компьютера друга пока
неизвестны; цену обучения без его smoke-test не оцениваем как установленный факт.

Новый сравнительный сборщик хранит пять условий A–E раздельно. Сейчас все NOT_RUN:
ни Faun, ни платный DeepSeek в этой работе не вызывались. Прошлые результаты из
репозитория не выдаются за новый эксперимент. Обученная модель не включена.
Существующий localhost PEFT route сохранён; автоматического PEFT→Ollama или
проверенного merge/GGUF в этой среде нет. training.merge_gguf реализует
локальный путь через PEFT и llama.cpp, требует владельческое holdout approval,
настоящий адаптер и предварительную проверку свободных RAM/диска.
Без --execute выполняется только preflight; автоматического включения нет. Сервер и публичные настройки не менялись.
