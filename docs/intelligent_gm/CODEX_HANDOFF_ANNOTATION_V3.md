# Передача Codex: разметка 1000 сценариев по R01–R14

Это **ИИ-предложения**, не человеческое утверждение, не реальные игровые эпизоды и не готовый SFT-корпус.

Ветка пакета: chatgpt/annotation-review-1000-20261103. Существующий PR №3 и ветка codex/intelligent-gm-20261103 этим пакетом не менялись.

## Файлы для переноса

- docs/intelligent_gm/annotation_proposals_R01_R14_1000_v3.jsonl — 1000 строк, с точными ID, исходными фактами, метками, причинами неопределённостей и происхождением.
- training/apply_ai_review_proposals.py — безопасный перенос в копию сценариев v2, с проверкой исходных данных и запретом перезаписи человеческих оценок.
- docs/intelligent_gm/annotation_review_1000_R01_R14_v3_codex.rtf — нумерованный документ для Word: что было, что предложено, спорные моменты.
- docs/intelligent_gm/annotation_protocol_R01_R14_20261103.md — 14 утверждённых правил, ограничения движка.

## Подсчёт

- 1000 уникальных ID: 20 семейств × 5 условий × 10 действий.
- 200 HUMAN_FIRST, 800 AI_LATER.
- 380 записей с явно названными недостающими фактами.
- 618 записей с хотя бы одной меткой «Неясно».
- Объединённая очередь: **681 требует проверки**, 319 имеют три определённые предложенные метки без явно названных пробелов.
- Человеческих одобрений — 0, подтверждённых игровых квитанций — 0, SFT-допущенных примеров — 0.

Числа 319/681 — результат правил очередности, а не процент правильности разметки.

## Как перенести в ветку Codex

Не сливать всю ветку ChatGPT. Сначала на рабочей ветке Codex выбрать только четыре перечисленных файла.

~~~powershell
git fetch origin
git switch codex/intelligent-gm-20261103
git pull --ff-only origin codex/intelligent-gm-20261103
git restore --source origin/chatgpt/annotation-review-1000-20261103 -- docs/intelligent_gm/annotation_proposals_R01_R14_1000_v3.jsonl docs/intelligent_gm/annotation_protocol_R01_R14_20261103.md docs/intelligent_gm/annotation_review_1000_R01_R14_v3_codex.rtf training/apply_ai_review_proposals.py
~~~

После проверки исходных данных и наличия openpyxl:

~~~powershell
.\.venv\Scripts\python.exe -m training.apply_ai_review_proposals --input docs\intelligent_gm\scenarios-1000-v2.xlsx --proposals docs\intelligent_gm\annotation_proposals_R01_R14_1000_v3.jsonl --output ..\DND-NCFU-data\annotation\scenarios-owner-R01-R14-proposed.xlsx
~~~

Проверить новый файл существующим импортёром:

~~~powershell
.\.venv\Scripts\python.exe -m training.annotation_v2 --input ..\DND-NCFU-data\annotation\scenarios-owner-R01-R14-proposed.xlsx --output ..\DND-NCFU-data\annotation\import-proposals-R01-R14-001
~~~

**Фактически эта XLSX-копия ещё не генерировалась и не тестировалась здесь**: Codex должен исполнить команды и сохранить доказательства. Код-генератор не изменяет оригинальный v2 и не перезаписывает существующий выходной файл.

Скрипт присваивает статус «Нужна проверка» любой строке, в которой есть неизвестные исходные факты ИЛИ метка «Неясно». Остальные получают «Предложено ИИ». Импортёр не должен считать ни один из них HUMAN_APPROVED.

## Известные расхождения текущего движка

- R02: remесло привязано к Ловкости, а должно выбирать характеристику по действию.
- R05: take чужой вещи не допускается и owner переписывается как hero, а нужен раздельный учёт собственника и держателя.
- R06: нет специальных общих эффектов натуральных 1/20.
- R10: cast при недостаче MP отклоняется, нет сознательной оплаты HP/истощением, Арканы DC и ограничения в 3 MP.
- R11–R13: неполная система unconscious/stable/dead, нет полноценных death saves; revive при HP0 нельзя объявлять воскрешением мёртвого.
- R14: fixed DC15 и полезности в food_negotiation.py не заменяют полную проверку выполнимости, полномочий и жизненно важных нужд каждой стороны.

Нужны изменения Python и регрессионные тесты. Не переписывать исторические сохранения без безопасной миграции.

## Нерешённые владельцем вопросы

**R10.** Разрешать ли оплату HP до нуля; предел истощения; запрет злоупотребления заклинаниями восстановления HP/MP через перерасход.

**R13.** Что делает дополнительный урон при 0 HP, как часто проводить проверки вне боя, когда обнулять предыдущие счётчики.

**R14.** Как определять жизненно важные потребности групп и полномочия при спорной собственности, если они отсутствуют в состоянии.

Не додумывать ответы. Сохранять UNKNOWN и явную причину; после решения пользователя обновить только соответствующие строки.

## Результат для пользователя

Codex должен предоставить реальную созданную Excel-копию, результаты проверки импортёра, список ещё неопределённых полей, тесты несовместимых с R01–R14 механик и точные инструкции. Не заявлять, что ИИ-разметка уже человеком одобрена или подходит для SFT.
