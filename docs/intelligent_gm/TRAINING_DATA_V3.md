## Прямые решения владельца

В сообщении подтверждены R01–R14, отдельная проверенная синтетика и реальные
эпизоды, бюджет первого эксперимента до **500 ₽**. Это ориентир, а не поручение
оплатить сервер. Разрешение владельца на использование предоставленных партий
учитывается как `OWNER_AUTHORIZATION`, без выдуманного независимого юридического
аудита. Наличие такого разрешения не создаёт отсутствующие квитанции игры.

Запись решений подаётся отдельным `--owner-decisions`, её SHA связывается с
точным файлом правил. Архив сам себя одобрить не может. Правила одобрены как
желаемые; полное соответствие текущего игрового движка этим правилам пока
**не подтверждено**. Исторические сохранения и обработчики не менялись.

Уточнённая политика:

- Перерасход R10: 2 HP за недостающий MP либо `ceil(нехватка/2)` уровней
  истощения; максимум три недостающих MP; DC `10+2*нехватка`; цена остаётся
  при провале. Выбор способа оплаты должен быть явным. Допустима оплата до
  ровно 0 HP с потерей сознания. Это homebrew, не заклинание из SRD.
- Истощение по SRD 5.2.1: каждый уровень даёт −2 к D20 Tests и −5 футов
  скорости; шестой уровень означает смерть. Завершённый длительный отдых
  снимает один уровень, а не всё истощение. Короткий отдых обычно не снимает
  его. Действуют условия отдыха и специальные ограничения источника истощения.
- При 0 HP: спасброски смерти, три успеха стабилизируют, три провала означают
  смерть, натуральная 1 даёт два провала, натуральная 20 восстанавливает 1 HP.
  Обычный урон при 0 HP даёт один провал, критическое попадание — два;
  урон не меньше максимального HP означает смерть. Стабилизация или реальное
  восстановление HP сбрасывают счётчики. Медицина DC10 стабилизирует, но
  не восстанавливает HP. Стабильная цель с 0 HP остаётся без сознания.
- R08 из утверждённого архива оставляет оглушённую цель при 0 HP: это отдельное
  homebrew-правило. В самом SRD 5.2.1 «Knocking Out a Creature» оставляет
  **1 HP**. Эти варианты нельзя выдавать за одно правило.
- R06 о натуральных 1/20 для обычных проверок и обязательное разумное соглашение
  R14 — авторские правила. Для R14 нужны подтверждённые полномочия,
  выполнимость, явные жизненно важные ограничения и успешное Убеждение;
  неизвестные ограничения уточняются. Высокий бросок не добавляет ресурсы.

Официальный PDF SRD 5.2.1 прочитан заново: с.17–18 (урон, смерть, помощь,
оглушение), с.181 (истощение), с.185 (Long Rest). SHA256 официальной загрузки
совпал с ранее записанной PDF-копией:
`8974902d109d6e63672d7c490bde9ccf052410503d9cfa768237154fbc5e3d87`.
Источник: https://media.dndbeyond.com/compendium-images/srd/5.2/SRD_CC_v5.2.1.pdf .
System Reference Document 5.2.1, Wizards of the Coast LLC, CC BY 4.0:
https://creativecommons.org/licenses/by/4.0/ . Описания выше — русский пересказ;
авторские изменения обозначены отдельно. Одобрение издателем не подразумевается.

## Отдельный пилот из 40 примеров

Ответы отредактированы по mock-квитанциям: сохранены ограничения и расход,
убраны неподтверждённые реакции NPC, предметы, причины отказа и детали обстановки.
Это `ASSISTANT_EDITORIAL_REVIEWED`, не ручное одобрение владельца.

`gm-sft-v1` по-прежнему отвергает синтетические примеры. Для пилота создан
отдельный `gm-synthetic-sft-v1`, который требует сохранённый исходный пример,
SHA исходной пары и исправленного ответа, редакторскую запись, явную синтетику
и связь с отдельным решением владельца. Он допускается только при явной
`dataset_policy=synthetic-pilot-v1` и статусе `PILOT_READY`.

Пилот делится по целым семействам: **32 train / 4 val / 4 test**. Исходный
800/100/100 остаётся у корпуса предложений и не используется для разделения
этого пилота. Исходные 40 пар по нему распределялись 37/2/1; это исправлено в
новом производном корпусе. Пилот нельзя смешивать с исходной разметкой как
с независимым тестом. Четыре тестовых ответа не дают надёжной оценки качества.

CPU-проверка настоящим токенизатором: максимум226 токенов, ни одной отброшенной
строки, все входные ID/маски совпали с `AutoTokenizer` Transformers5.3.0.
В 32 обучающих строках всего1 066 supervised-токенов. При эпохе1 и
накоплении16 это всего два обновления весов: проверка процесса, не полноценное
обучение мастера. Арендовать восемь часов только ради этих40 строк не требуется.

## Воспроизводимая проверка до GPU

Подготовка предложений с отдельным подтверждением правил:

```powershell
Set-Location D:\Projects\DND-NCFU
.\.venv\Scripts\python.exe -m training.review_training_pack --archive INPUT.zip --output ..\DND-NCFU-data\review-v3-1 --repair-question-links --owner-decisions OWNER.json
```

Ожидается `VALID_PROPOSALS_BLOCKED_DATA`, реальный SFT0. Это успешная проверка
предложений, а не допуск всех1 000 строк. Неполные факты не заполняются выдумками.
644 случая сохраняются в очереди: неизвестные ID, доступность, материалы,
стоимость действий, эффекты магии, полномочия и ограничения NPC.

Создание проверенного пилота из редакторского файла:

```powershell
.\.venv\Scripts\python.exe -m training.synthetic_corpus --archive REVIEWED.zip --editorial EDITORIAL.jsonl --owner-decisions OWNER.json --output ..\DND-NCFU-data\synthetic-pilot-v1
```

Получится `PILOT_READY`; человеческое одобрение0, реальных квитанций0.
Редакторские SHA — связь с просмотренным текстом, не автоматическая
семантическая оценка и не криптографическая подпись человека.

Для токенизации используется отдельное окружение, без Torch/весов/CUDA.
Установка небольших CPU-библиотек не меняет `.venv` игры:

```powershell
py -3.12 -m venv .venv-faun-cpu
.\.venv-faun-cpu\Scripts\python.exe -m pip install --require-hashes -r training\requirements-faun-cpu.lock
.\.venv-faun-cpu\Scripts\python.exe -m training.fetch_faun_tokenizer --output ..\DND-NCFU-data\faun-tokenizer
.\.venv-faun-cpu\Scripts\python.exe -m training.tokenize_dataset --config PILOT_CONFIG.json --tokenizer ..\DND-NCFU-data\faun-tokenizer --output ..\DND-NCFU-data\cpu-tokenization-01.json
```

Загружаются только четыре публичных файла токенизатора/метаданных около17MB;
все четыре SHA закреплены. Подготовленный PILOT_CONFIG должен указывать каталог
корпуса, его SHA из manifest и `dataset_policy=synthetic-pilot-v1`.
Существующий отчёт не перезаписывается. Слишком длинный пример, изменённый split,
утечка test, разделители ролей в данных или потеря assistant-prefix дают ошибку.
Веса не загружаются и строки не удаляются ради успешного отчёта.

## Перенос и бюджет

```powershell
.\.venv\Scripts\python.exe -m training.prepare_faun_transfer --dataset ..\DND-NCFU-data\synthetic-pilot-v1 --synthetic-pilot --cpu-report ..\DND-NCFU-data\cpu-tokenization-01.json --output ..\DND-NCFU-data\faun-pilot-transfer-01.zip
```

ZIP содержит инструменты, hash-lock и связанные конфигурации. Корпус и CPU-отчёт
в него автоматически не копируются. Передаются отдельно только выбранные данные;
отчёт нужно положить рядом с manifest под именем `cpu-tokenization.json`.
`START_HERE.md` объясняет GPU-проверку, отдельное окружение и загрузку оригинальной
базы. Для синтетики создаются `faun-smoke.json` и `faun-pilot.json`, не full-конфиг.

На Linux GPU после отдельных установок/загрузок:

```bash
.venv-faun/bin/python -m training.train_lora --config faun-smoke.json --dry-run
.venv-faun/bin/python -m training.train_lora --config faun-smoke.json --smoke-test
.venv-faun/bin/python -m training.train_lora --config faun-pilot.json
```

Перед выделением памяти под модель скрипт заново проверит все три split,
маски и SHA CPU-отчёта, сверит два пути токенизации. Обучается только train,
val используется для loss, test не поступает в градиенты. Smoke сохраняет
контрольные точки каждого шага; полный запуск — каждые25 шагов, сохраняются
две последние. Нельзя продолжить smoke как full или сменить конфигурацию resume.
Результат содержит фактические шаги, loss, пик VRAM и проверку перечитывания
адаптера. Перечитывание адаптера отдельно от восстановления Trainer-checkpoint.

RTX3090 24GB — выбранный кандидат, но здесь GPU batch/VRAM/скорость/resume не
проверялись. Цена27 ₽/ч взята с пользовательского снимка, не свежей котировкой:
8ч =216 ₽ только вычисления.500 ₽ хватит примерно на18,5ч только при той же
ставке и отсутствии других платежей. Хранилище, сеть, минимальная оплата,
скачивание базы и подготовка среды могут тарифицироваться отдельно.
Сначала короткий GPU smoke с замером, затем оценка времени по реальному шагу.
Отсутствие OOM на коротких226 токенах не доказывает вместимость2048 токенов.
Остановка Python не гарантирует остановку оплаты сервера: сервер надо остановить
в кабинете сервиса. Здесь ни аренда, ни оплата не выполнялись.

## Что ещё требуется для полноценного обучения

1. Привести новую версию движка в соответствие R01–R14 и проверить replay;
   подтверждение правил само по себе не меняет код игры.
2. Заменить общие фразы по1 000 действиям конкретными входными фактами,
   допустимыми исходами и квитанциями поддерживаемых механик; спорные строки
   до этого держать вне SFT. Не выдумывать исходное состояние реальной партии.
3. Расширить корпус ответов: не повторять40 примеров до нужного числа строк.
   Нужны независимые контексты, новые сочетания предметов и ограничения.
4. Собрать настоящие эпизоды через существующий коллектор, сохранить источник,
   проверить ответы и отделить кампании для test. Пять QA-наблюдений этого не заменяют.
5. Провести GPU smoke, затем независимое сравнение базовой и обученной Faun
   по тем же публичным состояниям, проверить сохранение фактов и качество текста.
   Проверки Faun/DeepSeek и человеческий литературный тест этим пилотом не выполнены.

Текущий результат позволяет провести ограниченный проверочный QLoRA-пилот после
готовности GPU/базы. Называть полный корпус мастера готовым было бы неверно.
