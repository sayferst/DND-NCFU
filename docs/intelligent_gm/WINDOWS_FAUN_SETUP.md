# Установка бесплатной Faun на Windows

Установщик реализован, но **на вашем Acer он ещё не запускался**.
Ожидаемый режим — CPU: i5-1135G7, Iris Xe,16ГБ RAM. Скорость12B заранее
не обещается. GGUF Q4_K_M нужен для игры; обучение исходных Safetensors — отдельная задача.

## Обновление проекта

Откройте PowerShell в существующей папке DND-NCFU, где лежат `.venv` и `scripts`.
В присланном журнале тесты Windows прошли, а Git сообщил, что ветка уже существует.
Для неё не нужно снова выполнять `git switch --track`.

```powershell
git fetch origin
if ($LASTEXITCODE -ne 0) { throw "Не удалось обновить сведения Git" }
git switch codex/intelligent-gm-20261103
if ($LASTEXITCODE -ne 0) { throw "Не удалось переключить ветку; сохраните локальные изменения" }
git merge --ff-only origin/codex/intelligent-gm-20261103
if ($LASTEXITCODE -ne 0) { throw "Обновление остановлено; не выполняйте reset или удаление файлов" }
```

Альтернатива — `scripts/update_intelligent_gm.ps1`: он выбирает существующую ветку,
а отслеживаемую создаёт только при её отсутствии. Он не делает reset, stash или
удаление. Если политика Windows запрещает PowerShell-скрипты, используйте команды
выше; менять политику выполнения не требуется. Личные файлы разметки храните вне Git.

Обновление исходников не обновляет отдельно установленный старый EXE.
Для этой проверки запускайте приложение из обновлённого проекта.

## Запуск установщика

Дважды нажмите [scripts/SETUP_FAUN.cmd](../../scripts/SETUP_FAUN.cmd) в проводнике
или выполните из папки проекта:

```powershell
.\scripts\SETUP_FAUN.cmd
```

Это запускает настоящий `training.setup_faun` через Python проекта. Требуется
рабочая `.venv` Python3.12; в вашем предыдущем журнале она уже использовалась.
Альтернативная оболочка — [setup_faun_windows.ps1](../../scripts/setup_faun_windows.ps1).
CMD не требует изменения ExecutionPolicy. Окно остаётся открытым после завершения.

Мастер проверяет общую/свободную RAM, диск хранения моделей, Ollama, loopback-сервис
и точный тег `hf.co/limloop/MN-12B-Faun-RP-RU-GGUF:Q4_K_M`.
Текущие пороги: примерно16ГБ общей RAM,9ГиБ свободной и не менее17ГБ на диске
моделей перед новой загрузкой. Закройте браузер и тяжёлые программы при нехватке RAM.
Это предварительные пороги, а не гарантия отсутствия нехватки памяти при длинной игре.

Каждая операция подтверждается отдельно:

1. Если Ollama отсутствует — загрузка видимого официального установщика с
   `https://ollama.com/download/OllamaSetup.exe`. Проверяется действительная
   Authenticode-подпись издателя Ollama. Завершите обычный мастер установки Windows.
2. Если локальный сервис ещё не работает — запуск `ollama serve` на127.0.0.1:11434.
3. Если точной Faun нет — загрузка примерно7,5ГБ Q4_K_M через `ollama pull`.
4. После проверки digest/размера/квантовки — короткий русский запрос на CPU.

При отказе соответствующая операция не выполняется. Мастер не меняет firewall,
антивирус, ExecutionPolicy, системный OLLAMA_HOST или тарифы API. Модели Ollama
Cloud/remote не принимаются за локальные. Если OLLAMA_HOST задан внешним адресом,
проверка останавливается, не исправляя защищённую настройку автоматически.
Установленные Ollama и точная Faun повторно не скачиваются; прерванный pull
обрабатывает кэш самой Ollama. После незавершённого установщика повторите мастер.

Отчёт находится в соседней папке `DND-NCFU-data/diagnostics/faun-setup-*.json`.
В нём — точное имя, digest, размер, квантовка, ответ, время загрузки и генерации,
токены/сек и снимки рабочего набора процессов Ollama до/после запроса.
Это **не пиковая RAM**. Ключи API не требуются.

`LOCAL_SMOKE_OK_GAME_EVALUATION_REQUIRED` означает, что короткий локальный запрос
выполнен. Это ещё не приёмка качества мастера. `INSTALLED_NOT_BENCHMARKED` означает,
что веса найдены, а запрос не запускался. `NEEDS_*` требует соответствующего шага;
`BLOCKED_RESOURCES`, `BLOCKED_SERVICE`, `BLOCKED_MODEL_IDENTITY` или `FAILED`
сохраняют причину и безопасную подсказку. Не отключайте защиту Windows ради обхода ошибки.

Только проверить, без установки, запуска сервиса, pull и генерации:

```powershell
.\.venv\Scripts\python.exe -m training.setup_faun --check-only
```

## Подключение в игре

Запустите проект из той же папки:

```powershell
.\.venv\Scripts\python.exe scripts\run_game.py
```
Откройте раздел «Мастер» в настройках разработчика/владельца, выберите
«Локально: Ollama · Faun · без оплаты API», нажмите «Найти установленные модели»
и «Выбрать установленную Faun». Панель показывает результат проверки Ollama,
наличие Faun, выбранный тег и готовность мастера. Сохранённый тег при следующем
запуске требует обновления списка, а не считается подтверждённым соединением.

Faun использует существующий OllamaClient: тот же контекст, квитанции и проверка
повествования. Перегенерация не применяет игровую транзакцию снова. Ошибка локальной
модели не вызывает скрытого платного запроса. Кнопка «Вернуться к DeepSeek через
RouterAI» только выбирает облачный провайдер: для него отдельно нужны модель,
ключ и согласие. Автоматического разрешения расходов она не даёт.
Профили доступа тестировщиков и привязка личной сборки остаются прежними.

Для свободных действий нужна новая кампания catalog3 с free_action_policy1.
Старые сохранения автоматически не переводятся на новые правила. Для старой
catalog3 есть отдельный `training.enable_attempts_copy`, создающий новую копию;
исходник сохраняется. См. [FREE_ACTIONS.md](FREE_ACTIONS.md).

## Настоящий игровой тест на Acer

После установки, из папки проекта, с уже работающей Ollama:

```powershell
.\.venv\Scripts\python.exe -m training.game_benchmark --live --limit 3 --output ..\DND-NCFU-data\diagnostics\faun-game-001.json
```

Первый прогон делает три последовательных запроса для разных исходов переделки
лука. Затем используйте `--all` и **новое имя** результата для11 сценариев:
ремонт брони, копьё, метла, монеты с изученной другой магией и без неё, рукавица,
дорога, переговоры о пище. Сценарии авторские: личные сейвы не читаются.
Квитанции, RNG и мир проверяются до/после рассказа; save/load проверяется для
каждого случая. Модель ничего не скачивает и не обучает. Один CPU-ответ может
занимать несколько минут; тайм-аут одного запроса10минут.

`LIVE_COMPLETED_REQUIRES_HUMAN_REVIEW` требует ручной проверки русского языка
и соответствия фактам; отклонённые/недоступные ответы дают `LIVE_DEGRADED_REQUIRES_REVIEW`.
В отчёте есть реальные ответы, задержки, local timing, токены/сек и снимки RAM
на Windows. Нулевая RAM либо null не заменяется догадкой о потреблении.
Без `--live` это только контрактные тесты, без инференса модели.

В текущем каталоге нет реализованного заклинания создания настоящей валюты.
Знание света не даёт такой способности; оба монетных сценария сохраняют запрет
создания ресурса. Случай с реально зарегистрированным эффектом валюты остаётся
за границей поддерживаемой магии, а не изображается успешным.

Чтобы отдельно проверить возможность QLoRA без загрузок:

```powershell
.\.venv\Scripts\python.exe -m training.hardware_probe
```

Команда теперь существует и пишет новый диагностический JSON. Iris Xe не является
NVIDIA CUDA: для выбранного QLoRA-профиля ожидается `BLOCKED_HARDWARE`.
Это не запрещает CPU-инференс GGUF. Сам Acer в этой облачной сессии недоступен;
установка, скорость, RAM и качество настоящей Faun на нём пока не подтверждены.
