# Универсальные планы свободных действий v1

Модель и офлайн-интерпретатор предлагают один и тот же закрытый план:

```json
{"operation":"transform","goal":"spear","items":["existing_pole"],"tool":"existing_knife"}
```

Операции: transform, repair, restore, use, magic, take, move, explore. План не
может содержать DC, урон, награду, новые ID, свойства материала или готовый
исход. Валидатор проверяет схему, реальные предметы, владение, доступ через
контейнеры, инструменты, состояние и физические свойства. Модель получает
только доступные предметы героя и словарь поддерживаемых возможностей.
Скрытые кошельки и удалённые запасы в этот контекст не передаются.

Офлайн-словарь отвечает только за слова и привязку ID. Общий движок
`attempt_plans` опирается на shaft/cord/fabric/binding/rigid/cut/repair и
реальные свойства каталога. У контрольных лука, метлы, монет и рукавицы нет
собственных обработчиков исхода. Для любой комбинации применяется один из
восьми общих примитивов. Малый декларативный набор форм включает удочку,
копьё, шину, перевязь, обмотку и связку. Это граница реализованных физических
механик; он не претендует на симуляцию всей физики или понимание любого русского
текста. Неизвестная формулировка передаётся модельному планировщику либо требует
уточнения. Новая формулировка не требует нового Python-обработчика.

Четыре режима: AUTO_SUCCESS, CHECK_REQUIRED,
ATTEMPT_WITHOUT_TARGET_SUCCESS, CLARIFICATION_REQUIRED. Уточнение не меняет
мир, время и RNG. Вопросы, отрицания, цитаты и неоднозначные цепочки не исполняют
скрытые действия. Обычное использование доступного свойства и подбор не требуют
D20. При отсутствии нужного свойства допустимая попытка описывается без успешного
создания невозможного результата. Высокий бросок не создаёт шнур, металл,
способность полёта или деньги. Имена магических предметов не являются свойствами.

Общее преобразование требует пригодных исходных единиц и инструментов.
Результат получает один из исходных ID; остальные входы расходуются. Прежние
формы и экипировка исчезают. Режущий инструмент изнашивается. Проверка:
d20 + модификатор Ловкости - временное ослабление. Подготовка за стрельбу не
превращается в подготовку ремесленника. Авторская шкала (homebrew, не SRD):

| Итог | Последствие для любого поддерживаемого преобразования |
| --- | --- |
| до10 | Повреждённые материалы, прочность0; ослабление -1 на30мин |
| 11–17 | Незавершённая заготовка, прочность2 |
| 18–20 | Грубое изделие, прочность3, штраф применения -3 |
| от21 | Импровизированное изделие, прочность6, штраф -1 |

Работа занимает30мин. Копьё использует общий бой, 1d4, износ и штраф к попаданию;
оно проверено экипировкой и настоящей атакой. Переделанная снасть не остаётся
луком. Профессиональные изделия с большей прочностью не появляются от большого
броска. Общий ремонт тратит совместимый материал и инструмент: от15 восстанавливает
до5прочности, 10–14 — до2, ниже — материал потерян. Обратная сборка требует
сохранённого происхождения и возвращает половину прежней прочности.

Нестандартное применение фиксирует предмет, назначение и место в physical_uses,
помечает его развёрнутым. Это не полный расчёт нагрузок конструкций. Улов,
наживка, иллюзорная валюта и магический полёт не выдумываются: если соответствующая
исполняемая механика не зарегистрирована, цель не достигается. Кража требует
отдельного намерения, а не присвоения чужой вещи через обычный подбор.

Перемещение использует существующий travel: соседство, известный путь, закрытие
дороги и реальные часы мира. Исследование использует конечный encounter-движок;
его случайность не является автоматически проверкой D20.

Квитанция содержит план, режим, собственные броски попытки, исход, изменения
предметов и время. Повтор request_id возвращает прежний ход. Рассказчик получает
результат без повторного исполнения; StrategicCritic проверяет несколько
критических противоречий. Проверка прозы остаётся ограниченной, не доказательством
истинности каждой фразы. JSON/SQLite повторно проверяют журнал операций.

Новые кампании catalog3 включают free_action_policy1. Старые origin читаются с
policy0: их исторические команды не переосмысливаются. Автоматической миграции
старой кампании в новую политику нет. training.enable_attempts_copy создаёт
отдельный проверенный файл для старой catalog3, сохраняя источник неизменным. Старые gameplay1–5 и каталоги1/2 сохранены.

Проверка Windows из папки проекта:

```powershell
Set-Location D:\Projects\DND-NCFU
.\.venv\Scripts\python.exe -m pytest tests/test_free_actions_pipeline.py tests/test_attempt_generalization.py -q
```

Ожидаются успешные регрессии. В новой игре лучника действие «Разбираю свой лук
и делаю из него удочку» изменяет реальный инвентарь; локальный расчёт не требует
облачного API. Дополнительные тесты используют отсутствовавшие в ТЗ копьё из
древка, шину из двух компонентов, ремонт брони и применение древка как опоры.
