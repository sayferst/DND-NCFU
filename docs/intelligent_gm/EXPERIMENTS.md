# Математическая модель и протокол ВКР

Рабочая постановка: G=(N,S,A,T,O,U,γ). NPC — программные участники с разными
интересами, собственными наблюдениями и обновляемыми убеждениями. Дополнительная
LLM на каждого NPC не запускается. Это конечная модель; полный POMDP/POSG-solver
или доказательство новой теории не заявляются.

В `strategic_conflicts.Agent` используется нормированная полезность:

Uᵢ = (Σₖ wᵢₖ Δxₖ / scaleₖ) / Σₖwᵢₖ − λᵢ risk − cost.

Шкалы фиксируются до сравнения альтернатив, веса неотрицательны. Разные участники
не оптимизируют одну общую функцию. В продовольственном примере жители имеют
веса(0.85,0.15,0), гарнизон(0.1,0.9,0), правитель(0.35,0.35,0.3) по пище жителей,
обеспеченности стражи и изменению бюджета. Эти числа — авторские предположения,
не измеренные человеческие предпочтения и не правила SRD.

Pareto-доминирование требует неухудшения всех полезностей и строгого улучшения
хотя бы одной; равные исходы не доминируют друг друга. Bayes проверяет нормировку
prior/likelihood и отклоняет наблюдение нулевой вероятности. Повторные
подтверждённые выдачи пищи меняют доверие, posterior и будущий порог согласия NPC.
В игре наблюдаются только присутствующие участники и реально предложенные рационы.
Неизвестные запасы/права доступа не возникают из оптимизации.

Общий планировщик вычисляет ожидаемую дисконтированную полезность до4шагов
с явным бюджетом узлов. Переходы задаются вероятностями с суммой1; выбор
воспроизводится seed. MCTS не используется: для этого малого пространства
достаточно ограниченного перебора. Результат является советом о вариантах,
не автоматическим выбором за игрока.

Исходный пример: пища100, потребности70+50, казна40, поставщик20 за30. Варианты
дают70/30,50/50,58/42 либо70/50 с уменьшением казны до10 и выплатой продавцу30.
Закупка отсутствует, когда нет продавца, товара или денег. Поведение NPC в игре
зависит от полезности их группы и истории взаимодействий; даже успешная проверка
переговоров не заставляет участника принять предложение ниже его порога.

Выполнен реальный CPU-прогон40авторских состояний:5уровней пищи ×4бюджета ×
2состояния доступности продавца. Получены122допустимых исхода,0нарушений
сохранения денег/пищи. Сценарии и все исходы сохранены в conflict-trials-01.json.
Авторский baseline — фиксированный приоритет жителей; формальная часть перечисляет
допустимые альтернативы и полезности. Это структурное сравнение, не вывод
о превосходстве математической модели по мнению игроков. Записаны базовый
commit и SHA фактического исходника; прогон сделан до коммита изменений.

Тесты независимо проверяют точные квоты70/30 и50/50, перевод денег продавцу,
исключение недоступной закупки, разные предпочтения, равенство Pareto-альтернатив,
Bayes, частоту стохастических переходов на2000seed, бюджет поиска, настоящую
передачу рационов в Session и replay. Числа тестов пересекаются с полным набором.

Для сравнения рассказчиков предусмотрены пять условий:

| Условие | Состояние этой работы |
| --- | --- |
| DeepSeek без нового Conflict Engine | NOT_RUN |
| Исходная Faun | NOT_RUN |
| Faun после обучения | NOT_RUN, адаптера нет |
| DeepSeek + Conflict Engine | NOT_RUN |
| Обученная Faun + Conflict Engine | NOT_RUN, адаптера нет |

`training.compare_models` принимает реальные записанные прогоны, сохраняет
отсутствующие условия как NOT_RUN с metrics=null, проверяет одинаковые holdout ID,
запрещает пересечение с заданными тренировочными семействами. Автоматических
утверждений об улучшении литературного качества нет.

Перед настоящим экспериментом: независимые семейства и кампании → одинаковые
публичные состояния/seed/лимиты → запись модели/revision/латентности/квитанции →
проверка механических нарушений → отдельное человеческое литературное ревью.
Измерять отказы без причины, выдуманные факты/ресурсы, действия за героя,
русский язык, связность, содержательность альтернатив, время, RAM и стоимость.
SFT-образцы и близкие варианты не должны попадать в holdout. Уменьшение loss
не является доказательством улучшения игры. Протокол и оформление главы
необходимо сверить с методическими требованиями кафедры.
