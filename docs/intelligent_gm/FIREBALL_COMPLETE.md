# FIREBALL: полный доступный filtered-корпус

04.11.2026. Это отдельный внешний архив наблюдений и задач, а не расширение
схемы игровых квитанций. Полный проход по доступному закреплённому filtered-релизу
выполнен. Автоматический импорт не присваивает человеческое одобрение, не реализует
правила Avrae в игре и не запускает обучение.

## Источники и фактическое покрытие

| Источник | Revision | Прочитано |
|---|---|---:|
| [HF lara-martin/FIREBALL](https://huggingface.co/datasets/lara-martin/FIREBALL) | `1b363686ed0d681bf8a0eb1e943af75d3716f7c8` | 1 471 JSONL, 153 829 ходов, 2 038 606 547 байт |
| [GitHub FIREBALL](https://github.com/zhudotexe/FIREBALL) | `02a040bdfc9de5c7da271ca7faad56be090669ba` | демонстрация: 25 троек и 342 raw-события |
| [FIREBALL-data-processing](https://github.com/zhudotexe/FIREBALL-data-processing) | `b3f9b5eca6dbbe1b7504c14dcbc055687bd4c7b4` | закреплены дерево, код схемы и лицензия; чужой код не исполнялся |

Дерево HF получено целиком, с обеих страниц API. Список `files.txt` совпал
с 1 471 фактически загруженным файлом: отсутствующих и лишних файлов нет.
Число 153 829 получилось чтением строк, а затем сравнено с карточкой.
Это не счётчик, до которого добирались размножением примеров.

Всего канонизированы **154 196 исходных строк из 1 473 файлов**. Отдельный
потоковый проверяющий сверил каждую строку, SHA файла/строки и все исходные JSON-значения:
ошибок, пропущенных строк и потерянных полей — **0**. Фактическая инвентаризация:
2 132 сочетания пути поля и типа. Демонстрационные raw-события и тройки относятся
к одному бою; их нельзя складывать как независимые партии.

Официальный полный raw-архив по URL из README возвращает **HTTP 403 из этой среды**
на HEAD и GET с Range. Свидетельства сохранены; это не доказательство глобального
отсутствия архива. Полный filtered обработан, но он не объявляется полным raw.
Без raw нельзя восстановить всех авторов последующих реплик, полную историю
alias/snippet resolution, все необработанные события и связи с кампаниями.
Сохранены 1 375 744 исходных индексных ссылки; доступные 342 demo-события не подменяют
полный raw-релиз.

## Три слоя и восстановимость

- **A:** неизменяемые JSONL в `originals/filtered`, демонстрация и закреплённые
  первичные материалы в `primary`. Manifest содержит размеры, SHA-256, revision,
  URL и число строк. Загрузчик дополнительно проверяет Git blob/LFS digest.
- **B:** `observations.sqlite`, таблица `observations`: сжатый исходный JSON со
  всеми полями, source/file/line/hash, исходная группа, роль с основанием,
  эвристика языка, состояние разбора. Байтовое оформление JSON остаётся в A.
  Неизвестные значения, null, ложные значения, нестандартные HP и расширения схемы
  сохраняются. Непарсящиеся строки сохраняются в quarantine как исходные base64-байты.
- **C:** `views`, `dispositions`, `view_links`, `exported` в той же базе:
  вход/выход каждой задачи, происхождение, split, готовность, связи истории,
  точная длина Faun и hash токенов. Для каждой исходной записи есть восемь
  решений: кандидат, только наблюдение либо недоступно с конкретной причиной.

В полном проходе quarantine не понадобился; тесты отдельно проверяют повреждённые
строки, повторные JSON-ключи, NaN и недопустимый UTF-8. Оригинал не заменяется
редакцией. Только производные входы/выходы проходят удаление contact/Discord/URL
полей и автоматический поиск контактов в тексте. Это предварительный экран,
а не сертификат отсутствия всех персональных сведений. Оригиналы и кандидаты
остаются ограниченными локальными материалами; автоматического допуска в SFT нет.

Номер строки нового архива — **с единицы**. В исторических 96 примерах он был
с нуля, а hash строки считался без перевода строки: это явно учтено в карте lineage.
ID наблюдения — непрозрачный стабильный ключ пространства импорта; достоверные
revision и hash исходника хранятся отдельно, включая отдельный GitHub revision demo.

## Представления и готовность

| Задача | Представлений | Что является target |
|---|---:|---|
| utterance_to_command | 120 396 | фактические нормализованные команды; роль автора не считается подтверждённой |
| command_to_result | 153 826 | исходные результаты **bot/automation** |
| observed_transition | 153 854 | наблюдаемое состояние после; это не универсальное правило причинности |
| grounded_utterance | 43 383 | исходные связанные последующие реплики; человеческая роль/роль DM не подтверждена |
| dialogue_sequence | 120 420 | исходные реплики с порядком и безопасной предысторией |
| entity_observation | 153 983 | карточки наблюдённых сущностей, без вымышленных определений |
| negative_outcome_candidate | 14 390 | реальные bot-ответы с лексическими признаками ошибки/неудачи; смысл требует проверки |
| raw_event | 342 | все типы событий доступной демонстрации |

Всего **760 594 представления**, а не столько новых игровых эпизодов.
Шесть предиктивных направлений дают 606 269 представлений для проверки формата
и длины. В 11 511 началах диалога нет достаточной безопасной предыстории:
они сохраняются как наблюдения, а не как содержательная SFT-пара.
Итого 594 758 структурных кандидатов на проверку и 165 836 представлений
только для наблюдения. Остальные 472 974 решения «задача недоступна» относятся
к сочетаниям запись×задача, а не к выброшенным строкам.

Всего решений **1 233 568 = 154 196 × 8**, необъяснимо исчезнувших записей — 0.
**human_approved = 0, train_admitted = 0, training_steps = 0.**
Смысл отрицательного исхода не устанавливается одним словом `failed`: такая
строка может описывать провал спасброска, а не ошибку команды. Кандидат сохраняется
с указанием необходимости проверки, исходный контекст доступен полностью.

Пустая последующая реплика не мешает задачам команд и состояний. Отсутствие роли
DM ограничивает задачи рассказчика, но не удаляет команду или результат Avrae.
Для доступной парной GitHub-демонстрации разрешены 218 индексных ссылок на raw:
12 after-ссылок ведут к сообщениям с author_bot=False. Это метка аккаунта,
а не доказательство человеческого авторства каждого слова или роли DM. Данные
доступны в event_references и --observation; сходство HF с demo не даёт права
переносить raw-индексы между выпусками без точной проверки.
Источник механики — наблюдение Avrae; совместимость с DND-NCFU учитывается
независимо от сохранности и пригодности задачи.

Инвентаризация поверхностных названий: 1 447 spell forms, 1 667 actions,
28 409 attacks, 5 050 effects, 4 075 class forms, 4 197 race forms. Это наблюдаемые
строковые формы, не очищенный официальный справочник; запятые вне скобок служат
кандидатными границами. Исходные целые значения сохранены. Повторные появления
в before/after/current/caster учитываются как появления полей, не независимые эпизоды.
Определения и runtime-поддержка не угадываются: `UNKNOWN_NOT_CLASSIFIED`,
`UNASSESSED_NOT_REQUIRED`. Сведения о прочих предметах и ресурсах сохраняются
в B даже без отдельного распознанного класса сущности.

## Независимые части и ограничения проверки дублей

Карта splits строится **до** task views и окон истории. Основная единица —
опубликованный файл боя; основание видно в закреплённом `distill4_normalize.py`.
Явные session/combat ID используются, когда доступны. Общий участник не доказывает
общую кампанию. При отсутствии достоверных campaign-связей независимость кампаний
не обещается.

Нормализованные полные наблюдения и обнаруженные близкие совпадения объединяют
группы. Два demo-файла дополнительно связаны прямым описанием их общего боя
в upstream README. Итог: **1 473 исходные группы, 1 470 компонент**;
train **1 176**, validation **147**, test **147** — 80/10/10 по компонентам.
Один ход и все его задачи всегда находятся в одной части.

Проверены полные JSON-дубли: 0; нормализованные дубли полного содержимого:
45 кластеров, 76 дополнительных записей. Приближённый поиск: две min-trigram
полосы, Jaccard ≥ 0,95 при одинаковых roster и commands; обнаружены 24 связи.
Это воспроизводимая проверка близких копий, а не исчерпывающее доказательство
семантической уникальности. Автоматическое определение всех смысловых дублей
и всех кампаний не заявляется.

Для demo25: точных совпадений полного нормализованного ядра с HF — 0, но есть
23 близкие связи с одним HF-файлом; поэтому demo связан с основным боем.
В окончательной карте все эти данные вместе. Уточнение карты и перенос двух
пограничных групп задокументированы; входы, targets и токены не менялись.

Окно истории включает максимум пять предыдущих наблюдений только из той же
исходной группы/файла. Индексы окончания предыдущего наблюдения должны быть
строго меньше начала текущего; неизвестный порядок не угадывается. Для
utterance_to_command исключены результаты текущей команды и after-state.
Для grounded_utterance подтверждённые результаты намеренно являются input.
Исходная `utterance_history` содержит только сведения до команды по upstream
кодексу; для предсказания самой очередной реплики она не берётся, поскольку
может содержать эту реплику. Полная история по-прежнему доступна в A/B.

## Faun и перенос

Используется точный закреплённый tokenizer Faun revision
`bdfc761b14feb9dd03ef158a4d337fc1cf5fd183`, без весов и Torch. Для всех предиктивных
представлений проверяются полный ChatML, совпадение generation-prefix и начало
маски loss. Prompt целиком получает -100, target целиком обучаемый, включая
`<|im_end|>` и завершающий перевод строки. Настройка `eos_token=</s>` отличается
от терминатора этого ChatML; дополнительный EOS самовольно не приписывается.
Сырые управляющие delimiters внутри исходного JSON обратимо экранируются.

Предусмотрены профили 2 048/4 096/8 192/16 384/32 768/65 536/131 072 токена,
а более длинные случаи остаются на long-context review. Метаданные модели
указывают 1 024 000 позиций; это не доказательство вместимости GPU. Большой
профиль не означает, что он помещается в RTX 3090. Ответы не обрезаются.
Полный проход: 606 269 представлений, 1 206 068 534 общих токена,
240 528 171 target-токен, максимум 38 276. Профили 2048/4096/8192/16384/32768/65536
содержат 368 769/181 150/51 890/4 270/186/4 представления. Число токенов
суммируется по шести задачам и частям, а не по независимым исходным эпизодам.
Все 9473 shards сверены с SQLite: messages, target, source IDs, маски, длины,
hashes, группировка. Потерь/дублей/расхождений — 0. Полный набор не является
назначением обучать всё за 8 часов или на бюджет500₽: сначала нужен отдельный
проверенный состав задач и GPU smoke. Фактическое распределение и все SHA
находятся в CPU tokenization manifest.

Конфиги по шести задачам разделены и имеют BLOCKED_REVIEW. Обучение команд Avrae
не объявляется обучением игрового рассказчика. Конфиги — спецификации следующего
проверенного эксперимента; кандидаты не допускаются автоматически в существующий
`training.train_lora` и не заменяют проверенный V4-путь. Ручная проверка роли,
приватности, смысла и качества должна предшествовать отдельному admission.

Полный комплект содержит все A/B/C и token ledger. При необходимости task JSONL
восстанавливаются из SQLite без повторной долгой токенизации:

```powershell
Set-Location "D:\Projects\DND-NCFU"
git pull --ff-only origin codex/intelligent-gm-20261103
if ($LASTEXITCODE -ne 0) { throw "Обновление остановлено" }
$fbRoot = "D:\Projects\DND-NCFU-data\fireball-full-01"
.\.venv\Scripts\python.exe -m training.fireball_verify --root $fbRoot
.\.venv\Scripts\python.exe -m training.fireball_verify --root $fbRoot --tasks
.\.venv\Scripts\python.exe -m training.fireball_materialize --root $fbRoot --output "D:\Projects\DND-NCFU-data\fireball-task-export-01"
```

Ожидается PASS на 1 473 файлах/154 196 строках; materialize создаёт все восемь
видов, human_approved/train_admitted остаются 0. Выбирайте новую выходную папку.
В `source-record-ledger.csv.gz` есть каждая строка и восемь решений;
в `task-review-queue.csv.gz` — каждое представление и причины проверки.
Исходное наблюдение или представление открывается по ID из очереди:

```powershell
.\.venv\Scripts\python.exe -m training.fireball_audit --root $fbRoot --observation OBSERVATION_ID
.\.venv\Scripts\python.exe -m training.fireball_audit --root $fbRoot --view VIEW_ID
```

Вывод остаётся локальным. Оригинальные контакты не предназначены для GitHub
или передачи модели.

## Воспроизведение с нуля

Для отдельного нового каталога, с достаточным диском (ориентир 15–20 ГБ для
источников, SQLite, экспортов и резервов; без весов модели):

```powershell
$fbRoot = "D:\Projects\DND-NCFU-data\fireball-rebuild-01"
.\.venv\Scripts\python.exe -m training.fireball_discover --root $fbRoot
.\.venv\Scripts\python.exe -m training.fireball_discover --root $fbRoot --probe-raw
.\.venv\Scripts\python.exe -m training.fireball_archive --root $fbRoot --workers 6
.\.venv\Scripts\python.exe -m training.fireball_observations --root $fbRoot
.\.venv\Scripts\python.exe -m training.fireball_verify --root $fbRoot
.\.venv\Scripts\python.exe -m training.fireball_readiness --root $fbRoot
```

Скачивается именно публичный filtered; ~2,04 ГБ. `.partial` и проверенные файлы
возобновляются без удаления оригиналов. Обработанный каталог C не затирается
повторным build; для новой обработки используйте новую папку. После загрузки
повторный запуск archive проверит кэш, ingest отдельно умеет продолжить
незавершённый проход. Блокирующий raw URL отражён в отчёте, его нельзя подменить
демонстрацией. Если raw станет доступен, нужен отдельный проход по этому архиву;
текущий выпуск не утверждает, что такой проход уже состоялся.

Только токенизатор требует отдельного CPU-окружения из существующего hash-lock:

```powershell
py -3.12 -m venv .venv-faun-cpu
.\.venv-faun-cpu\Scripts\python.exe -m pip install --require-hashes -r training\requirements-faun-cpu.lock
.\.venv-faun-cpu\Scripts\python.exe -m training.fetch_faun_tokenizer --output "D:\Projects\DND-NCFU-data\faun-tokenizer"
.\.venv-faun-cpu\Scripts\python.exe -m training.fireball_tasks --root $fbRoot --tokenizer "D:\Projects\DND-NCFU-data\faun-tokenizer" --output "D:\Projects\DND-NCFU-data\fireball-native-faun-01"
.\.venv\Scripts\python.exe -m training.fireball_manifest --root $fbRoot
```

Это загрузка ~17 МБ tokenizer/metadata, не 12B-весов. Экспорт разбит на атомарные
shards и возобновляется с проверкой их SHA; код использует короткие keyset-чтения,
чтобы не удерживать многогигабайтный SQLite WAL. Во время экспорта не запускайте
другую запись в ту же базу. Воспроизведение не арендует GPU и не вызывает LLM.

## Существующие V4 и 96 HP-примеров

1100 синтетических строк V4 сохранены отдельно и не названы реальными партиями.
Исторический выпуск 1196 = V4 + 96 не перезаписан. Для всех 96 построена связь
с полным архивом и проверены SHA исходника/строки. Состояния — наблюдения FIREBALL,
HP-delta — расчёт кода, русская инструкция и ответ — авторские тексты ассистента,
не человеческая запись и не перевод. Они не увеличивают число независимых
реальных эпизодов и не ограничивают новый полный архив.
