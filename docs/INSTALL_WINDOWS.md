# Установка и проверка для Windows

Эти команды предназначены для вашего ПК. Облачная проверка выполняется на Linux
и не заменяет ручную проверку Windows-интерфейса. Доступен первый оконный прототип.

## 1. Проверить инструменты

Откройте PowerShell (меню «Пуск» → PowerShell):

```powershell
py -3.12 --version
git --version
```

Ожидаются Python 3.12.x и версия Git. Если команды отсутствуют, установите
бесплатные Python 3.12 x64 с https://www.python.org/downloads/windows/ и Git
с https://git-scm.com/download/win. Для Python 3.12 официальный Windows-установщик
есть у 3.12.10; более поздние исправления ветки могут поставляться исходниками.
Не заменяйте его случайной сторонней сборкой. После установки откройте PowerShell
заново. VS Code необязателен. Компилятор, Docker, Node.js и GPU для настройки не нужны.

## 2. Открыть папку и установить зависимости

Сохраните подготовленные файлы проекта в `D:\Projects\DND-NCFU`.
Если выбрали другой путь, замените путь в первой строке.
Не переносите `.venv` из Linux: создайте её заново на Windows.

```powershell
Set-Location D:\Projects\DND-NCFU
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements-dev.lock
.\.venv\Scripts\python.exe scripts\check.py
```

Каждую команду запускайте после успешного завершения предыдущей.
Установка впервые требует доступа к PyPI и files.pythonhosted.org.
Версии и контрольные суммы пакетов закреплены в `requirements-dev.lock`.
Для последующих проверок интернет не нужен.
При несовпадении хэша остановитесь и сохраните текст ошибки; не отключайте проверку.
При ошибке не удаляйте проект или сохранения.

Успех: 198 тестов пройдены, зависимости совместимы, Ruff не сообщает ошибок.
Нулевое количество тестов не считается успехом. Автотесты используют невидимое
окно Qt; для ручной проверки отдельно запустите:

```powershell
.\.venv\Scripts\python.exe scripts\run_game.py
```

Откроется «Пограничье — первый прототип». Введите «помочь» и нажмите Enter:
жительница поблагодарит вас. Команда «проверить силу» покажет d20 +2 против
сложности 10. Неизвестная команда вызывает уточнение.
Журнал сохраняется вручную в одной из трёх ячеек. Подробная приёмка — в
TEST_PLAN.md и docs/SAVE_SLOTS.md.

При установке добавляются PySide6 Essentials 6.10.1 и shiboken6 (около 72 МБ на
Windows). Локальные модели, Qt Addons и платные компоненты не устанавливаются.
При повторном запуске устанавливать зависимости заново не нужно.

## 3. Git и резервная копия

В облачной папке Git уже был. При скачивании ZIP история может отсутствовать:

```powershell
git rev-parse --show-toplevel
```

Если команда сообщает, что это не репозиторий, выполните `git init` в папке проекта.
Проверяйте `git status --short` перед сохранением версии. В коммит должны попасть
код, документы, конфигурация и lockfile; `.venv`, ключи и игровые сохранения — нет.
Для первого коммита Git может попросить локальные `user.name` и `user.email`:
укажите свои выбранные значения, не копируйте чужую личность.
Публикация и GitHub для локальной истории не нужны.
Периодически делайте отдельную локальную копию проекта вместе с `.git` и
исследовательскими результатами; Git в той же папке не заменяет резервную копию.

## Обновление зависимостей (только отдельной задачей)

Обычному пользователю `uv` не нужен: установка работает через pip.
Для сопровождающего: бесплатный uv 0.12.23 использовался при создании lockfile.
После обоснованного изменения `requirements.in` или `requirements-dev.in`:

```text
uv pip compile requirements-dev.in --universal --python-version 3.12 --generate-hashes --index-url https://pypi.org/simple --output-file requirements-dev.lock
```

Затем переустановить зависимости с `--require-hashes`, выполнить `scripts/check.py`,
проверить Windows и обновить журнал лицензий. Не обновлять пакеты автоматически
в каждой сессии. Для архивирования офлайн-установки позже можно сохранить wheelhouse
на целевой Windows, вместе с лицензиями и хэшами; сейчас Windows wheelhouse не создан.

## Облачный Linux

В `/workspace/DND-NCFU`:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements-dev.lock
.venv/bin/python scripts/check.py
```

Службы и секреты не требуются. Работа ведётся в существующем checkout.

Для обновления уже клонированного проекта: проверить `git status --short` и ветку
`setup/development-environment`, выполнить `git pull --ff-only`, затем установку
lockfile и проверки выше. Если Git сообщает о локальных изменениях, не делать reset
или принудительную перезапись; сохранить текст ошибки и обсудить её.
