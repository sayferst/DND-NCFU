# Автоматический доступ мастера к 19 000 фрагментам

Обновление 27.10.2026, исходный код `0721083`. Прямое поручение владельца:
завершить автоматический RAG по всему предоставленному корпусу. Доступ больше
не ограничен 24 авторскими методами. Ни нового игрового режима, ни кнопок
импорта, ни установки моделей игроку не требуется.

В `data/corpus_knowledge/cards.sqlite3` подготовлены **19 000 канонических
справочных карточек** и 200 алиасов. Manifest фиксирует SHA исходного ZIP,
SHA готовой базы, схему, состав и способ подготовки. Каждый документ хранит
исходный ID, SHA файла и диапазон строк. Проверены все восемь входных корпусов;
корпус из 200 старых партий совпадает с частью основного и не удваивает записи.

| Канонический источник | Карточек |
| --- | ---: |
| Партии | 1 000 |
| Смерть и NPC | 1 000 |
| События | 1 000 |
| Поведение | 5 000 |
| Сущности | 5 000 |
| Бытовые действия | 1 000 |
| Ремесло | 5 000 |
| Всего | 19 000 |

Это производная справочная база: название и короткие описательные поля каждого
фрагмента. Полные стенограммы, участники чужих партий, скрытые причины событий,
итоги, квитанции, числовые правила и инструкции из архива в неё не переносятся.
Состав полей задан явным списком для каждого типа. Таким образом, поиск охватывает
все 19 000 источников, а модель получает подходящие очищенные справки, не полный
исходный текст каждой записи. Карточки остаются машинно отфильтрованными,
не объявляются человечески одобренными, игровыми фактами или SFT-примерами.

На создании мира, планировании хода и написании рассказа автоматически
вызывается один read-only reader `learning/corpus.py`. SQLite FTS5 ранжирует
весь индекс; для ремесла/поведения/событий учитывается тема вопроса. Есть
точное обращение по полному или короткому ID и поддержка 200 алиасов.
Без FTS5 используется ограниченный SQL-поиск. Никаких embeddings, Torch,
скачивания весов и дополнительных запросов к модели.

За запрос выбирается до трёх справок, в пределах 2 400 UTF-8 байт. В реальном
payload они находятся в `archive_references`. Системная политика отделяет
справки от инструкций, знаний NPC и подтверждённых событий. Прежние 24 метода
сохранились отдельным небольшим каналом. Ни один канал не меняет состояние
Session, броски, кошельки или инвентарь.

Подготовленная база поставляется с checkout и явно включена в PyInstaller.
Reader проверяет размер, схему и SHA; соединение `mode=ro&immutable=1`,
запросы параметризованы, время SQL ограничено. SHA кэшируется по метаданным
файлов, корпус не загружается целиком в Python на каждом ходе. Если база
отсутствует или повреждена, работает прежний путь мастера; `--self-check`
показывает состояние `automatic_corpus`, без raw-текста и ключей.

Разработчик воспроизводит артефакт из проверенного ZIP одной командой:

```powershell
.\.venv\Scripts\python.exe -m training.build_corpus_knowledge --input "ПУТЬ_К_CODEX_READY.zip" --output "НОВАЯ_ПАПКА_БАЗЫ"
```

Существующая версия не перезаписывается. При обновлении разработчик заменяет
проверенный подготовленный артефакт в `data/corpus_knowledge`; игрок получает
его обычным обновлением игры. По личным папкам пользователя поиск не ведётся.

Проверки и итоговые числа: `docs/validation/automatic-corpus-2026-10-27/`.
Итог: **1894 теста прошли**, pip/Ruff успешны; Linux self-check/smoke
подтвердили `ready/19000`. Все карточки содержат описательные поля;
карточек только с названием нет. Нативная Windows-приёмка ещё не выполнена.
Тест проверяет настоящий FTS-match для **каждого из 19 000 rowid**, а не только
COUNT внешней content-таблицы. Проверены последние ID каждого корпуса, алиасы,
поиск обычными словами, лимит контекста, фильтрация hidden/injection/numeric,
повреждение/отсутствие, read-only, три реальных пути формирования payload и
неизменность Session/RNG. Новых платных запросов нет. Художественный прирост
модели и качество на всех возможных запросах не измерялись.

Обучение весов не проводилось: SFT-ready по-прежнему 0. Будущая слепая оценка
обученной модели должна использовать новые кампании, не примеры из доступного
всему runtime корпуса. Существующие архивные train/test-разбиения сами по себе
уже не обеспечивают слепоту относительно RAG.
