Рассказчик по-прежнему не изменяет Session. Планировщик/валидатор/квитанция
определяют действие, проза приходит после него. «Осмотреть» не означает
покупку; ремесло проверяет реальные материалы; повтор рассказа не повторяет
бросок/расход. Эти работающие цепочки не переписаны и проверяются прежними тестами.
Профили NPC, их потребности и локальные отчёты существующей симуляции сохранены.

Новая память не создаёт вторую каноническую БД: читает существующие typed turns,
сохраняемые Session и SQLite кампаний. Исторические события помечены как прошлые;
текущее состояние важнее. NPC получает только наблюдаемые действия при наличии
свидетельства, без дневника, private_plot, кошелька или текста намерения героя.
Выбор адресата использует существующий turn_brief. Сведения разных world/hero
не объединяются. Это не реализация общего multiplayer-сервера мира.

## Предложения шаблонов

templates.candidate показывает локальные ссылки и границы применения;
для crafting перечисляет действующие recipe_id. Неизвестный рецепт остаётся
кандидатом, автоматической реализации 5000 эффектов нет. EV/FI/LO/BA не наносят
урон и не выдают добычу при просмотре.

propose_catalog принимает только локально одобренные entities/behavior, включённый
flag и оригинальные поля оператора. apply_catalog требует подтверждения,
проверяет world/hero/place и вызывает действующий register_catalog. Повтор
request_id идемпотентен после загрузки. HP1 нового нейтрального actor явно задан
адаптером; это не перенесённая боевая статистика источника. Из UI доступен
просмотр кандидата, программный каталог-адаптер предназначен для инструментов
владельца; автоматический генератор импортированных NPC не включён.
