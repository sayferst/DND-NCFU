# Включение библиотеки CODEX READY

> Историческая инструкция предыдущего интерфейса. После объединённого ТЗ
> вкладка «Библиотека мастерства»,ZIP-импорт и RAG-переключатели удалены из игры.
> Для игрока24разрешённых метода работают автоматически. Актуальные developer
> команды: [training/README.md](../../training/README.md), итог:
> [acceptance_report.md](../unified/acceptance_report.md). Шаги UI ниже
> относятся к старой реализации и больше не выполняются. CLI сохранён.

Все новые флаги по умолчанию выключены; старые кампании/правила не мигрируют.
Исходный ZIP и производная SQLite остаются в локальных данных, вне Git.
При установленной игре это её пользовательская папка, в checkout обычно
`D:\Projects\DND-NCFU-data`. Сетевой API для импорта/поиска не нужен.

## Обновление и проверка

```powershell
Set-Location D:\Projects\DND-NCFU
git -c gc.auto=0 -c maintenance.auto=false pull --ff-only
.\.venv\Scripts\python.exe scripts\check.py
.\.venv\Scripts\python.exe scripts\run_game.py
```

Зависимости не добавлены. Ожидается успешный scripts/check.py, затем привычное
окно игры. При локальных изменениях git не затирает их: сначала разберите status;
не используйте reset --hard для обновления. Старое предупреждение pytest об
очистке pytest-current не является разрешением менять ACL или удалять Temp.

## В интерфейсе

1. Откройте существующую консоль «Разработчик» с вашим локальным допуском
   (в account-сборке — admin). Выберите «Библиотека мастерства».
2. Нажмите «Импорт ZIP…», выберите CODEX_READY. До импорта база не открывается
   и фоновая задача не запускается. Можно отменить; активная версия сохранится.
3. «Состояние»:19000записей,24индексированных авторских метода,0raw в индексе.
   «Карточки» ищет по ID/названию; Enter/двойной щелчок открывает локальный raw.
4. Для включения отметьте «Поиск по проверенным выдержкам» и «Память…»,
   режим «Подсказки в ответе», затем «Сохранить режим». Обычная игровая
   генерация использует этот контекст. Новый запрос сам не запускается.
5. «Теневой поиск» собирает trace без изменения текста prompt. «Выключено»
   возвращает прежний путь. Включение не меняет модель, ключи и бюджет.

«Проверенный поиск» работает только локально. Для ручного допуска выберите
карточку, самостоятельно проверьте источник, напишите безопасную короткую
выдержку без числовых правил, укажите проверяющего и нажмите «Одобрить локально».
В held-out частях допуск сохраняется в журнале, но не даёт runtime-индексацию.
«Отклонить / отозвать допуск» немедленно убирает выдержку из поиска.
Права raw на внешнюю передачу остаются закрыты; RouterAI получает собственные
методы проекта. Человеческое ревью — действие владельца, не автоматический QC.

«Перестроить индекс» восстанавливает его по текущим review. «Версии» /
«Выбрать версию» переключают готовую библиотеку, не кампанию. Ревизии разных
архивов сохраняются отдельно; повтор идентичного ZIP не сбрасывает ваши review.
Выйдя из режима разработчика, вы скрываете raw и отменяете незавершённую задачу.

## Командная строка без UI

Глобальные параметры directory/report идут **перед** подкомандой. directory
можно не указывать: используется та же папка, что в игре. Отчёты пишутся
только в новый файл, поэтому при повторе меняйте номер.

```powershell
.\.venv\Scripts\python.exe scripts\learning\manage_library.py ingest "$env:USERPROFILE\Downloads\DND_Training_Package_CODEX_READY (1).zip"
.\.venv\Scripts\python.exe scripts\learning\manage_library.py stats
.\.venv\Scripts\python.exe scripts\learning\manage_library.py query "осматриваю чужой меч" --remote
.\.venv\Scripts\python.exe scripts\learning\manage_library.py candidates --namespace crafting --offset 0
```

record ID показывает полный raw только в вашей консоли; не пересылайте этот
вывод во внешнюю телеметрию. review ID path.txt --reviewer owner --approve
допускает локальную выдержку из UTF-8 файла; без --approve — отзывает допуск.
rebuild перестраивает индекс; versions перечисляет ревизии; activate ИМЯ.sqlite3
переключает готовую версию; splits экспортирует только ID/семейства/split.
Каталог-адаптер templates.py не запускается автоматически: его применять
только из собственных инструментов с явным подтверждением и оригинальными полями.

## Повтор офлайн-сравнения

```powershell
.\.venv\Scripts\python.exe scripts\learning\evaluate.py --output "$env:TEMP\dnd-offline-ab-01.json"
.\.venv\Scripts\python.exe scripts\learning\live_probe.py --output "$env:TEMP\dnd-pilot-plan-01.json"
```

Первая команда:100сценариев×4условия, mock,без сети и оплаты. Вторая по умолчанию
только dry-run READY_NOT_RUN. `--execute` отдельно разрешает максимум8живых
генераций **deepseek/deepseek-v4.1-flash**, не другие модели, с резервом до5₽
и месячным потолком1000₽ для этой проверки. Ключ передайте через временный
приватный файл `--key-file` вне репозитория либо переменную DND_ROUTERAI_API_KEY;
не вставляйте его в скрипт/отчёт/коммит. При timeout повтора нет: неизвестный
расход остаётся зарезервированным. Каждый явный новый запуск — новая платная
проверка, не запускайте его вместе с каждым pytest. Фактические списания
контролируются в кабинете RouterAI; оценка по каталогу не заменяет счёт провайдера.

Откат функций: установите режим «Выключено», снимите новые флаги и сохраните.
learning.json не содержит ключей. Файлы кампаний и SQLite библиотеки удалять не нужно.


Расширенная проверка: scripts/learning/live_suite.py по умолчанию также dry-run;
24игровых состояния×2режима, максимум48ответов. --case позволяет выбрать
конкретные состояния, --max-output-tokens2048 — резерв для reasoning.
--execute --budget-rub задаёт бюджет **одного запуска**, не всего аккаунта;
повторный запуск платный. Для выполненных здесь запусков совокупный резерв
38.29₽из разрешённых150₽; ключ уже удалён из этой рабочей среды. Программа
не меняет лимиты кабинета. Параметры передавайте с пробелом: например,
`--max-output-tokens 2048 --case memory_100 --budget-rub 5`.
