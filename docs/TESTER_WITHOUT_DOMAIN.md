# Персональный Setup без домена — версия0.3.1

Тестировщик получает один Setup.exe: устанавливает и запускает игру. Python,
cloudflared, Git, API-ключи и ручной ввод допуска ему не нужны. При первом запуске
игра автоматически активирует персональный допуск и подключает Мастера и Художника.
Интернет нужен. ПК владельца и окно хоста должны работать во время игры.

Для обычного запуска уже настроенного хоста откройте `Команды/START_HOST.bat` двойным
щелчком в корне проекта. Права администратора не нужны. Дождитесь трёх HTTPS-проверок
и оставьте окно открытым. Остановка — Ctrl+C; при запросе Windows подтвердите Y.
Памятка команд: `HOST_COMMANDS.txt` в той же папке. BAT не обновляет проект,
не устанавливает программы и использует уже сохранённые настройки хоста.

Условия владельца:100₽ одному человеку на30дней. Это предел, не включённые кредиты:
в кабинете RouterAI должен быть достаточный баланс. Доступ прекращается при расходе
лимита, истечении срока или отзыве. Модельные запросы здесь не проверялись за деньги.
Срок начинается при создании допуска командой build. Продление не обнуляет расходы.
Общий серверный предел также100₽ за всю историю БД; выдача нового допуска его не
сбрасывает. Для нескольких людей или увеличения бюджета нужна отдельная настройка.

## 1. Обновить и подготовить сборщик на ПК владельца

Сохраните игру и закройте её. Скопируйте папку пользовательских данных в резервную
папку перед обновлением. Исходники находятся в D:\Projects\DND-NCFU.

```powershell
Set-Location D:\Projects\DND-NCFU
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Обновление остановлено.' }
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements-build.lock
if ($LASTEXITCODE -ne 0) { throw 'Зависимости не установлены.' }
.\scripts\check_tester_host.cmd
```

Новая зависимость cryptography нужна для проверки подписи адреса Ed25519.
Её версии/зависимости/хэши закреплены, лицензии включаются в приложение.
Результат проверки tools_ready=true вы уже подтвердили наWindows.

Для создания Setup нужен бесплатный Inno Setup6 только владельцу. Если его ещё нет:

```powershell
winget install --id JRSoftware.InnoSetup --exact --source winget
```

Прочитайте условия установщика; после установки откройте PowerShell заново.
Если cloudflared отсутствует, команда установки:
`winget install --id Cloudflare.cloudflared --exact --source winget`.
Инструменты не устанавливаются скрыто. Права администратора, изменение политики
PowerShell, открытие портов роутера и отключение брандмауэра игре не требуются.
CMD запускает сборщик с политикой только отдельного процесса.

## 2. Запустить хост

```powershell
Set-Location D:\Projects\DND-NCFU
.\scripts\tester_host.cmd start
```

Первый запуск попросит API-ключ RouterAI обычным видимым вводом. Вставьте его только в это
окно, Enter; не присылайте в чат. Рекомендуется отдельный ключ с лимитом в кабинете.
Он сохраняется Windows DPAPI только для вашей учётной записи.
Если GitHub попросит вход для push — используйте обычный Git Credential Manager.
Пароль GitHub и токен в код, команды и чат не вставляются.

Команда запускает локальный шлюз на127.0.0.1 и cloudflared, публикует в отдельную
ветку `tester-host-address` существующего репозитория только endpoint.json:
HTTPS-адрес, срок, номер и подпись. Исходная ветка игры не переключается. Файл
доступен публично; ключи, допуски, промпты, IP ПК и базы туда не отправляются.
Подпись проверяется до передачи активации/допуска по новому адресу.

Дождитесь: **«Адрес опубликован и подпись проверена. Платных проверок не было.»**
Далее это окно не закрывайте. Автоматические проверки — GET ключа/каталога RouterAI, документа и health;
они не генерируют мир, текст или изображение. Ключ, лимит, наличие утверждённых моделей и цены проверяются по метаданным.
Успешную платную генерацию это не доказывает: она проверяется при игре.

Если GitHub недоступен, вход не прошёл, публикация запрещена настройками веток или
туннель не запускается, процесс остановится без выпуска персонального установщика.
Не отключайте проверку подписи, TLS или лимитов для обхода ошибки.

## 3. Собрать персональный установщик во втором PowerShell

```powershell
Set-Location D:\Projects\DND-NCFU
.\scripts\tester_host.cmd build tester1
```

Сборка проверяет опубликованный адрес и живой шлюз без платной генерации, создаёт
допуск100₽/30дней, запускает тесты, PyInstaller, изолированные проверки настоящего
EXE и Inno Setup. При ошибке проверок сборка останавливается. Это может занять
несколько минут; сеть нужна для зависимостей и получения публичного адреса.

Готовый персональный файл:

**D:\Projects\DND-NCFU\dist\Tester-tester1\DND-NCFU-Setup.exe**

Передавайте этот файл только одному тестировщику. Setup содержит одноразовый код,
который можно извлечь из пакета; первым активировать его должен нужный человек.
После активации другим Windows-пользователем/установкой код уже не пригоден.
Это ограниченный допуск к вашему шлюзу, не общий RouterAI-ключ. Копирование уже
активированных защищённых данных не заменяет серверный контроль срока/бюджета.

Не запускайте этот персональный Setup в своей учётной записи «для проверки» до
отправки человеку: так вы займёте его активацию. Автоматические EXE self/smoke
проверки изолированы от реального допуска и сервиса, они его не расходуют.
Повторная команда build с тем же именем восстанавливает тот же допуск, не квоту.
Именованные старые Setup сохраняются в папках dist\Tester-…; обновляйте передаваемый
файл после новой успешной сборки. Не отправляйте gateway-data, AppData хоста,
папку проекта, build, файлы активации или ключи вместе с установщиком.

## 4. Что увидит тестировщик

1. Установка игры и запуск ярлыка. Защитник Windows может показать сообщение о
   неизвестном издателе: платная цифровая подпись установщика не приобреталась.
2. Подключение выполняется в фоне; сообщение «Тестовая игра подключена».
   Если хост запускается позже, проверка повторяется раз в минуту; кнопка активации
   также запускает проверку, ручной код в персональной сборке не требуется.
3. «Новая легенда» → анкета героя и пожелания миру → «Создать героя» → центральная
   «Создать новый мир». На экране загрузки — фоны/фразы/полоса ожидания, затем история.
4. Диалог, «Изобразить сцену», сохранение, перезапуск и продолжение. Создание мира
   может занимать до15минут: короткие проверки статуса не повторяют генерацию.
5. Подтверждённые изображения и сохранения остаются локально после отзыва.

**Перед передачей как проверенного релиза** установите сборку под отдельным
тестовым допуском/учётной записью наWindows и проверьте этот путь. Сборка Linux не
проверяет Windows Installer, DPAPI, доступность модели/сети человека и качество
реального мира. Первый запуск реальной генерации расходует RouterAI; он не входит
в бесплатные автоматические проверки. Не обещайте непрерывную неделю QuickTunnel:
при обрыве/остановке запустите хост снова, клиент получит новый подписанный адрес.
Уже отправленная генерация не повторяется автоматически при потере соединения.

## Управление доступом

Во втором окне PowerShell из папки проекта:

```powershell
.\scripts\tester_host.cmd list
.\scripts\tester_host.cmd revoke tester1
.\scripts\tester_host.cmd extend tester1 --days 30
```

Последние две команды — разные действия: отзыв окончательный; продлить можно
только неотозванный допуск. Продление меняет срок, не денежную/числовую квоту.
Новый Setup для отзыва/продления не нужен. Отзыв запрещает новые запросы и получение
результатов. Уже отправленный RouterAI запрос отменой допуска не возвращает деньги.
При неизвестном расходе резерв удерживается до сверки, повтор автоматически не идёт.

Смена ключа: `.\scripts\tester_host.cmd key`, видимый ввод, затем перезапуск хоста.

Остановка хоста: Ctrl+C в первом окне; локальный сервер и туннель закрываются.
Повторный start обновляет подписанный адрес, игру у человека переустанавливать не
нужно. При непрерывной работе подпись обновляется раз в7дней. Сон/выключение/обрыв
интернета останавливают доступ: настройки сна при необходимости меняет владелец.
Службы/автозагрузка/сон/брандмауэр скрипт не меняет.

Данные хоста: `%LOCALAPPDATA%\DND-NCFU-Host`, вне Git и Setup. База хранит хэши
допусков/срок/квоты/расходы, ключи защищены DPAPI. Сохраните резервную копию папки;
восстановление DPAPI требует той же Windows-учётной записи. Потеря ключа подписи
потребует новой сборки с новым публичным ключом. Не удаляйте папку ради сброса квот.

Официальные инструменты: https://github.com/cloudflare/cloudflared/releases и
https://jrsoftware.org/isinfo.php. Код не регистрирует сервисы и не оплачивает хостинг.

## Если хост остановился при проверке ключа

Повторный `start` использует уже защищённый ключ и не просит вводить его заново.
Общая ошибка старой версии «не подтвердил ключ и положительный лимит» не позволяет
отличить ключ, формат ответа и сеть. После обновления выводится точная причина:

- «Месячный лимит не подтверждён» — у самого API-ключа в кабинете RouterAI задайте
  положительный месячный лимит, например100₽. Баланс аккаунта и лимит ключа — разные
  поля; серверный лимит допуска100₽ также не заменяет лимит API-ключа.
- «Лимит исчерпан» — проверьте расход ключа; не нужно создавать новый допуск,
  удалять базу или сбрасывать сохранения. Хост не пополняет баланс автоматически.
- HTTP401 — ключ отклонён, HTTP403 — доступ запрещён. Проверьте ключ и права
  в кабинете. Для замены ключа: `.\scripts\tester_host.cmd key`, затем start.
- Ошибка соединения/таймаут/TLS — проверьте интернет, доступ к routerai.ru и дату
  Windows. Не отключайте TLS, защитник или брандмауэр для обхода проверки.
- Неверный формат метаданных — пришлите только безопасный текст ошибки. Ключ,
  содержимое защищённых файлов и полный ответ с личными полями присылать не нужно.

Эти проверки выполняют только GET метаданных, без генерации и без списаний за модель.
Ошибка о ключе ещё не доказывает недостаток денег; сначала нужна точная причина.

### HTTP400 после проверки метаданных

Если после обновления до8c20e05 появилось «RouterAI вернул HTTP400», это отказ
HTTP-запроса проверки, а не доказательство нехватки денег. В следующем исправлении
GET-запросы метаданных приведены к формату клиента игры: `Accept: application/json`,
без `Content-Type` и без тела. Публичный каталог запрашивается без ключа; проверка
ключа по-прежнему передаёт его в Authorization только RouterAI. POST генерации
сохраняет JSON-тело и авторизацию, автоматических повторов нет.

Для исправления достаточно обновить исходники и снова выполнить start. Повторно
устанавливать зависимости, Inno Setup или пересобирать игру не нужно. Если HTTP400
останется, пришлите безопасный текст новой ошибки; ключ не меняйте и баланс
не пополняйте только ради попытки обойти эту ошибку.

## Замена ключа после перегенерации в RouterAI

Перегенерация в кабинете не обновляет копию в защищённом хранилище вашего ПК.
Шлюз продолжает читать старый ключ, пока вы явно не замените его:

```powershell
Set-Location D:\Projects\DND-NCFU
.\scripts\tester_host.cmd key
```

Вставьте новый обычный API-ключ RouterAI в консоль и нажмите Enter.
По просьбе владельца ввод отображается. Вставляется только ключ, без `Bearer`, кавычек или JSON.
Команда заменяет только защищённый ключ RouterAI для Мастера и Художника.
Ключ подписи адреса и персональные допуски тестировщиков при этом не меняются.

Затем запустите хост заново: `.\scripts\tester_host.cmd start`.
Если он работает в другом окне, сначала остановите его там через Ctrl+C.
Новый Setup для смены серверного API-ключа не нужен.

Для отдельной безопасной проверки сохранённого ключа:

```powershell
.\scripts\tester_host.cmd diagnose
```

Это один GET метаданных ключа, без генерации, туннеля, публикации адреса и доступа
к базе квот. Для HTTP400 читается максимум8КиБ пояснения ответа и определяется
одна из фиксированных категорий ошибки. Сам ответ, ключ, произвольные коды,
персональные поля и тексты исключений в отчёт не включаются.
`reason_is_inferred=true` означает распознавание по текстовым признакам, а не
независимое подтверждение типа ключа. Неизвестный ответ остаётся `unrecognized`.
Если после замены start снова остановился, пришлите JSON-отчёт diagnose.
Сам ключ и содержимое защищённых файлов не присылайте.

### Видимый ввод и чтение из буфера обмена

По прямой просьбе владельца ввод ключа в `key` и при первом `start` теперь виден
в консоли. Программа не добавляет значение ключа в свои диагностические отчёты.
Для обычной вставки:

```powershell
.\scripts\tester_host.cmd key
```

Если вставка в консоль не работает, используйте:

```powershell
.\scripts\tester_host.cmd key --clipboard
```

Сначала запустите команду. Когда появится подсказка, откройте кабинет RouterAI,
скопируйте только сам ключ, вернитесь в консоль и нажмите Enter. Вставлять его
в строку не нужно. Чтение производится локально через стандартный Get-Clipboard,
значение не передаётся аргументом процесса и не выполняется как команда.
Пустой/слишком большой буфер, внутренние пробелы, переносы, Ctrl+V как управляющий
символ и обёртка в кавычках не заменяют старый сохранённый ключ. Пограничные
невидимые BOM/zero-width символы браузерного копирования убираются перед проверкой;
внутри ключа ничего не склеивается. После подтверждения сохранения выполните start.

### Ожидание после публикации адреса

Первый запуск ждёт доступность подписанного файла и HTTPS-туннеля до5минут.
Не закрывайте окно во время «Ожидаю доступность». В сообщении отдельно указано,
что ещё не готово: документ GitHub или HTTPS-туннель Cloudflare. Повторяются
только GET-проверки, без генерации и расходов. После обновления проекта
повторите `scripts\tester_host.cmd start`; ключ вводить повторно не нужно.
Если ожидание закончится ошибкой, передайте последнюю строку — URL/ключ не нужны.

### HTTP530 от Cloudflare

Обновлённый хост использует HTTP/2 через исходящий TCP7844 и ждёт регистрации
соединения до публикации. Это обход возможной блокировки QUIC/UDP, а не
гарантия устранения любого530. Входящие порты открывать не нужно.
Повторите `git pull --ff-only`, затем `scripts\tester_host.cmd start`.
Если появится сообщение об исходящем соединении или TCP7844, пришлите итоговые
строки. Ключ менять и Setup пересобирать для этого исправления не требуется.

### Если обычный DNS недоступен

Обновлённый `start` получает адреса узлов через DNS-over-HTTPS, а при отказе
использует резервные IPv4 из официальной документации Cloudflare. В cloudflared
передаются числовые адреса; DNSWindows для поиска узлов туннеля не требуется.
Настройки адаптеров/hosts/реестра не меняются, права администратора не нужны.

```powershell
Set-Location D:\Projects\DND-NCFU
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Обновление остановлено.' }
.\scripts\tester_host.cmd start
```

До запуска проверяется исходящий TCP7844 к узлам. Если он недоступен, смена DNS
не поможет: потребуется разрешение исходящего доступа или другая сеть/VPN.
Входящие порты открывать не нужно. TLS, подпись адреса и лимиты остаются включены.

### Сборка после успешного запуска хоста

Inno Setup, установленный в `%LOCALAPPDATA%\Programs\Inno Setup 6`, находится
автоматически. Переустанавливать его, менять PATH и запускать сборку от
администратора не требуется. Хост оставьте открытым в первом окне.
Во втором окне выполните:

```powershell
Set-Location D:\Projects\DND-NCFU
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Обновление остановлено.' }
.\scripts\tester_host.cmd build tester1
```

Готовый файл: `dist\Tester-tester1\DND-NCFU-Setup.exe`. Передавайте его только
назначенному тестировщику; первое включение использует персональную активацию.
На вашем ПК этот Setup запускать не нужно. Во время тестирования хост должен
работать, а компьютер оставаться включённым и подключённым к интернету.

Повторная сборка tester1 сохраняет прежний допуск, срок и расходы. Если хост
остановлен или HTTPS снова недоступен, preflight остановит сборку с конкретной
причиной. Ошибка во время сборки покажет этап: тесты, PyInstaller, проверки EXE
или Inno. Старый Setup не копируется вместо отсутствующего нового результата.

### Если start сообщил об успехе, а build получил HTTP530

Оставьте start открытым. Во втором окне после обновления проекта выполните:

```powershell
.\scripts\tester_host.cmd diagnose-tunnel
```

Команда не читает API-ключ, не выпускает допуск и не меняет настройки. Она проверит
подписанный адрес и трижды сравнит health через системный HTTP-прокси и напрямую.
`direct` здесь не отключает VPN в TUN-режиме. При работающем соединении это обычно
несколько секунд; при сетевых тайм-аутах может занять около минуты.

Пришлите полученный JSON целиком: он не содержит URL, ключей, proxy-значений,
RayID и сырых ответов. `connector_lost_1033` означает код1033 в ответеCloudflare,
`system_proxy_route` — все прямые проверки успешны, системные не все успешны при
настроенном HTTP-прокси. Эти факты требуют разных исправлений.

### Cloudflare1033: коннектор потерян

Если оба маршрута возвращают530 с1033, Cloudflare не видит работающий коннектор.
Новый хост подтверждает готовность тремя последовательными HTTPS-проверками и
продолжает проверятьhealth каждые15с. Приошибке готовность снимается; после3отказов
коннектор пересоздаётся, обновляя подписанный адрес. Шлюз, допуски ирасходы сохраняются.
Восстановление пробуетHTTP2 иQUIC, до3перезапусков/час. Проверки не запускают генерацию.

Обновление файлов не изменяет уже запущенный процесс. Остановите старыйstart
через Ctrl+C и запустите заново после gitpull. Дождитесь «Устойчивость подтверждена
тремя HTTPS-проверками», затем собирайте tester1 во втором окне. Еслиоба транспорта
не держат соединение, код не сможет снять ограничение внешней сети: потребуется
проверкаVPN/другойсети наWindows. Не отключайте TLS, подписи или бюджетные проверки.

### Переход на ngrok вместо Cloudflare — 22.10.2026

Для сети владельца Cloudflare остаётся неустойчивым. Теперь можно выбрать ngrok
с выданным бесплатным доменом `.ngrok-free.dev` или `.ngrok-free.app`. Покупать
домен не требуется. После настройки обычный `start` использует ngrok автоматически:
Cloudflare, его поиск DNS-узлов и порт7844 в этом режиме не используются.

Остановите старый хост через Ctrl+C. В PowerShell владельца:

```powershell
Set-Location D:\Projects\DND-NCFU
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Обновление остановлено.' }
winget install --id Ngrok.Ngrok --exact --source winget
.\scripts\tester_host.cmd update-ngrok
```

Затем подставьте свой домен из кабинета (без звёздочек, таблицы и пути):

```powershell
.\scripts\tester_host.cmd ngrok --domain ВАШ-ДОМЕН.ngrok-free.dev
.\scripts\tester_host.cmd start
```

Команда `ngrok` попросит **ngrok Authtoken**, а не RouterAI API-ключ. Найти его:
https://dashboard.ngrok.com/get-started/your-authtoken — кнопка Copy. Вставьте
только значение токена в локальный запрос скрипта, не всю команду из кабинета.
Ввод виден в вашей консоли по выбранному владельцем способу ввода. Не отправляйте
токен в чат. Он сохраняется защищённым Windows DPAPI в
`%LOCALAPPDATA%\DND-NCFU-Host\ngrok-token.bin`; публичные настройки домена —
в `tunnel.json`. При запуске токен передаётся только через окружение дочернего
агента, без аргументов командной строки и без записи в его временный config.
Локальная инспекция HTTP-запросов агента отключена. В Setup агента и токена нет.

Если нужно заменить именно ngrok Authtoken, повторите настройку с
`--replace-token`. Для RouterAI остаётся отдельная команда `tester_host.cmd key`.
База допусков, подпись, прежний бюджет100₽/30дней и расходы не сбрасываются.

После сообщения «Устойчивость подтверждена тремя HTTPS-проверками» оставьте
первое окно открытым. Во втором:

```powershell
Set-Location D:\Projects\DND-NCFU
.\scripts\tester_host.cmd build tester1
```

Передайте `dist\Tester-tester1\DND-NCFU-Setup.exe`. Эту версию Setup нужно
пересобрать: в клиент добавлены заголовок обхода браузерной страницы ngrok
для активации/Мастера/Художника и более редкий опрос заданий. Тестировщику не
требуется устанавливать ngrok, Python или VPN. Работать должны ПК владельца,
окно хоста и интернет; настройки Windows/Happ скрипт не меняет. Доступ ngrok к
исходящему TLS443 всё равно требуется; ни один туннель не гарантирует обход
любого ограничения сети. При отказе присылайте итоговую строку или код
`ERR_NGROK_...`, без токена.

Бесплатный тариф ngrok на дату проверки: стабильный выданный dev-домен,
без тайм-аута сессии, но **1ГБ исходящего трафика и20000 HTTP-запросов в месяц**.
Иллюстрации расходуют трафик. Это отдельные ограничения от бюджета RouterAI.
Health хоста проверяется каждые5минут (около8640 запросов за30суток непрерывной
работы), задания в клиенте — каждые10с. При обрыве восстановление может занять
несколько таких проверок; перед выпуском допуска build всегда проверяет HTTPS
снова. Самостоятельного повторения платного POST нет. Для экономии квоты
закрывайте хост, когда тестирование не идёт. Изменение тарифов проверяйте в
кабинете; обещать неограниченную бесплатную работу нельзя.

Источники: https://ngrok.com/docs/pricing-limits/free-plan-limits и
https://ngrok.com/docs/agent . Проверки кода и пределы подтверждения:
[ngrok-host-2026-10-22](validation/ngrok-host-2026-10-22/README.md).

### Если winget установил ngrok3.3.1 и агент сразу завершился

Строка «Запускаю ngrok через HTTPS/443» не является сетевой ошибкой.
Winget у владельца выдал старую3.3.1; поддержанный в хосте config/параметры
проверены на3.39.12. Без вывода агента нельзя приписывать такой отказ VPN.
Старый хост скрывал ошибки разбора аргументов и бессмысленно повторял запуск.
Теперь версия проверяется заранее: минимум3.39.12, несовместимость не повторяется.

Остановите start и выполните:

```powershell
Set-Location D:\Projects\DND-NCFU
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Обновление остановлено.' }
.\scripts\tester_host.cmd update-ngrok
if ($LASTEXITCODE -ne 0) { throw 'Обновление ngrok не завершено; start пока не запускать.' }
.\scripts\tester_host.cmd start
```

Команда копирует установленный агент в
`%LOCALAPPDATA%\DND-NCFU-Host\ngrok-agent\ngrok.exe` и запускает штатное
`ngrok update` для этой portable-копии. Официальный updater скачивает новую
версию и проверяет подпись ngrok. Файл winget не изменяется; права администратора
обычно не нужны. Обновление требует интернета и скачивает агент. Временный config
совместим со старым агентом, токенов не содержит и удаляется. Секреты DPAPI и
база допусков не читаются и не меняются; сохранённые токены не передаются updater.
Обновление нельзя запускать одновременно со start; общий lock это проверяет.
Новый хост предпочитает portable-копию старому псевдониму в PATH.

Ожидается «ngrok обновлён:3.39.12» либо более новая версия. Повторно вводить
Authtoken/RouterAI-ключ или настраивать домен не требуется. При отказе обновления
start не запускайте: передайте итоговую строку без токенов. Эта команда исправляет
несовместимость агента, но сама по себе не доказывает доступность сети/VPN.
Значение `ERR_NGROK_...` и ошибки CLI теперь классифицируются без сырого вывода
агента; явное отклонение запуска не маскируется серией сетевых переподключений.
