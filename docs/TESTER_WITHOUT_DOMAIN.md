# Персональный Setup без домена — версия0.3.1

Тестировщик получает один Setup.exe: устанавливает и запускает игру. Python,
cloudflared, Git, API-ключи и ручной ввод допуска ему не нужны. При первом запуске
игра автоматически активирует персональный допуск и подключает Мастера и Художника.
Интернет нужен. ПК владельца и окно хоста должны работать во время игры.

Условия владельца:100₽ одному человеку на30дней. Это предел, не включённые кредиты:
в кабинете RouterAI должен быть достаточный баланс. Доступ прекращается при расходе
лимита, истечении срока или отзыве. Модельные запросы здесь не проверялись за деньги.
Срок начинается при создании допуска командой build. Продление не обнуляет расходы.
Общий серверный предел также100₽ за всю историю БД; выдача нового допуска его не
сбрасывает. Для нескольких людей или увеличения бюджета нужна отдельная настройка.

## 1. Обновить и подготовить сборщик на ПК владельца

Сохраните игру и закройте её. Скопируйте папку пользовательских данных в резервную
папку перед обновлением. Исходники находятся в D:\Projects\DND-NCFU.

```powershell
Set-Location D:\Projects\DND-NCFU
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Обновление остановлено.' }
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements-build.lock
if ($LASTEXITCODE -ne 0) { throw 'Зависимости не установлены.' }
.\scripts\check_tester_host.cmd
```

Новая зависимость cryptography нужна для проверки подписи адреса Ed25519.
Её версии/зависимости/хэши закреплены, лицензии включаются в приложение.
Результат проверки tools_ready=true вы уже подтвердили наWindows.

Для создания Setup нужен бесплатный Inno Setup6 только владельцу. Если его ещё нет:

```powershell
winget install --id JRSoftware.InnoSetup --exact --source winget
```

Прочитайте условия установщика; после установки откройте PowerShell заново.
Если cloudflared отсутствует, команда установки:
`winget install --id Cloudflare.cloudflared --exact --source winget`.
Инструменты не устанавливаются скрыто. Права администратора, изменение политики
PowerShell, открытие портов роутера и отключение брандмауэра игре не требуются.
CMD запускает сборщик с политикой только отдельного процесса.

## 2. Запустить хост

```powershell
Set-Location D:\Projects\DND-NCFU
.\scripts\tester_host.cmd start
```

Первый запуск попросит API-ключ RouterAI скрытым вводом. Вставьте его только в это
окно, Enter; не присылайте в чат. Рекомендуется отдельный ключ с лимитом в кабинете.
Он сохраняется Windows DPAPI только для вашей учётной записи.
Если GitHub попросит вход для push — используйте обычный Git Credential Manager.
Пароль GitHub и токен в код, команды и чат не вставляются.

Команда запускает локальный шлюз на127.0.0.1 и cloudflared, публикует в отдельную
ветку `tester-host-address` существующего репозитория только endpoint.json:
HTTPS-адрес, срок, номер и подпись. Исходная ветка игры не переключается. Файл
доступен публично; ключи, допуски, промпты, IP ПК и базы туда не отправляются.
Подпись проверяется до передачи активации/допуска по новому адресу.

Дождитесь: **«Адрес опубликован и подпись проверена. Платных проверок не было.»**
Далее это окно не закрывайте. Автоматические проверки — GET ключа/каталога RouterAI, документа и health;
они не генерируют мир, текст или изображение. Ключ, лимит, наличие утверждённых моделей и цены проверяются по метаданным.
Успешную платную генерацию это не доказывает: она проверяется при игре.

Если GitHub недоступен, вход не прошёл, публикация запрещена настройками веток или
туннель не запускается, процесс остановится без выпуска персонального установщика.
Не отключайте проверку подписи, TLS или лимитов для обхода ошибки.

## 3. Собрать персональный установщик во втором PowerShell

```powershell
Set-Location D:\Projects\DND-NCFU
.\scripts\tester_host.cmd build tester1
```

Сборка проверяет опубликованный адрес и живой шлюз без платной генерации, создаёт
допуск100₽/30дней, запускает тесты, PyInstaller, изолированные проверки настоящего
EXE и Inno Setup. При ошибке проверок сборка останавливается. Это может занять
несколько минут; сеть нужна для зависимостей и получения публичного адреса.

Готовый персональный файл:

**D:\Projects\DND-NCFU\dist\Tester-tester1\DND-NCFU-Setup.exe**

Передавайте этот файл только одному тестировщику. Setup содержит одноразовый код,
который можно извлечь из пакета; первым активировать его должен нужный человек.
После активации другим Windows-пользователем/установкой код уже не пригоден.
Это ограниченный допуск к вашему шлюзу, не общий RouterAI-ключ. Копирование уже
активированных защищённых данных не заменяет серверный контроль срока/бюджета.

Не запускайте этот персональный Setup в своей учётной записи «для проверки» до
отправки человеку: так вы займёте его активацию. Автоматические EXE self/smoke
проверки изолированы от реального допуска и сервиса, они его не расходуют.
Повторная команда build с тем же именем восстанавливает тот же допуск, не квоту.
Именованные старые Setup сохраняются в папках dist\Tester-…; обновляйте передаваемый
файл после новой успешной сборки. Не отправляйте gateway-data, AppData хоста,
папку проекта, build, файлы активации или ключи вместе с установщиком.

## 4. Что увидит тестировщик

1. Установка игры и запуск ярлыка. Защитник Windows может показать сообщение о
   неизвестном издателе: платная цифровая подпись установщика не приобреталась.
2. Подключение выполняется в фоне; сообщение «Тестовая игра подключена».
   Если хост запускается позже, проверка повторяется раз в минуту; кнопка активации
   также запускает проверку, ручной код в персональной сборке не требуется.
3. «Новая легенда» → анкета героя и пожелания миру → «Создать героя» → центральная
   «Создать новый мир». На экране загрузки — фоны/фразы/полоса ожидания, затем история.
4. Диалог, «Изобразить сцену», сохранение, перезапуск и продолжение. Создание мира
   может занимать до15минут: короткие проверки статуса не повторяют генерацию.
5. Подтверждённые изображения и сохранения остаются локально после отзыва.

**Перед передачей как проверенного релиза** установите сборку под отдельным
тестовым допуском/учётной записью наWindows и проверьте этот путь. Сборка Linux не
проверяет Windows Installer, DPAPI, доступность модели/сети человека и качество
реального мира. Первый запуск реальной генерации расходует RouterAI; он не входит
в бесплатные автоматические проверки. Не обещайте непрерывную неделю QuickTunnel:
при обрыве/остановке запустите хост снова, клиент получит новый подписанный адрес.
Уже отправленная генерация не повторяется автоматически при потере соединения.

## Управление доступом

Во втором окне PowerShell из папки проекта:

```powershell
.\scripts\tester_host.cmd list
.\scripts\tester_host.cmd revoke tester1
.\scripts\tester_host.cmd extend tester1 --days 30
```

Последние две команды — разные действия: отзыв окончательный; продлить можно
только неотозванный допуск. Продление меняет срок, не денежную/числовую квоту.
Новый Setup для отзыва/продления не нужен. Отзыв запрещает новые запросы и получение
результатов. Уже отправленный RouterAI запрос отменой допуска не возвращает деньги.
При неизвестном расходе резерв удерживается до сверки, повтор автоматически не идёт.

Смена ключа: `.\scripts\tester_host.cmd key`, скрытый ввод, затем перезапуск хоста.

Остановка хоста: Ctrl+C в первом окне; локальный сервер и туннель закрываются.
Повторный start обновляет подписанный адрес, игру у человека переустанавливать не
нужно. При непрерывной работе подпись обновляется раз в7дней. Сон/выключение/обрыв
интернета останавливают доступ: настройки сна при необходимости меняет владелец.
Службы/автозагрузка/сон/брандмауэр скрипт не меняет.

Данные хоста: `%LOCALAPPDATA%\DND-NCFU-Host`, вне Git и Setup. База хранит хэши
допусков/срок/квоты/расходы, ключи защищены DPAPI. Сохраните резервную копию папки;
восстановление DPAPI требует той же Windows-учётной записи. Потеря ключа подписи
потребует новой сборки с новым публичным ключом. Не удаляйте папку ради сброса квот.

Официальные инструменты: https://github.com/cloudflare/cloudflared/releases и
https://jrsoftware.org/isinfo.php. Код не регистрирует сервисы и не оплачивает хостинг.

## Если хост остановился при проверке ключа

Повторный `start` использует уже защищённый ключ и не просит вводить его заново.
Общая ошибка старой версии «не подтвердил ключ и положительный лимит» не позволяет
отличить ключ, формат ответа и сеть. После обновления выводится точная причина:

- «Месячный лимит не подтверждён» — у самого API-ключа в кабинете RouterAI задайте
  положительный месячный лимит, например100₽. Баланс аккаунта и лимит ключа — разные
  поля; серверный лимит допуска100₽ также не заменяет лимит API-ключа.
- «Лимит исчерпан» — проверьте расход ключа; не нужно создавать новый допуск,
  удалять базу или сбрасывать сохранения. Хост не пополняет баланс автоматически.
- HTTP401 — ключ отклонён, HTTP403 — доступ запрещён. Проверьте ключ и права
  в кабинете. Для скрытой замены ключа: `.\scripts\tester_host.cmd key`, затем start.
- Ошибка соединения/таймаут/TLS — проверьте интернет, доступ к routerai.ru и дату
  Windows. Не отключайте TLS, защитник или брандмауэр для обхода проверки.
- Неверный формат метаданных — пришлите только безопасный текст ошибки. Ключ,
  содержимое защищённых файлов и полный ответ с личными полями присылать не нужно.

Эти проверки выполняют только GET метаданных, без генерации и без списаний за модель.
Ошибка о ключе ещё не доказывает недостаток денег; сначала нужна точная причина.
