# Первый тест без домена: подготовка компьютера владельца

Владелец подтвердил: ПК может работать в часы теста, допуск одному человеку —
100 ₽ на 30 дней. Это верхняя граница будущих расходов, не пополнение счёта,
не разрешение Codex отправлять платные запросы и не гарантия 30 дней при любом
расходе. После исчерпания квоты облачные функции блокируются до решения владельца.

Выбран путь: бесплатный временный HTTPS-туннель на ПК владельца и обновляемый адрес.
Знакомому нужны только Windows и персональный Setup. Программа туннеля — только
на компьютере владельца. Отдельного домена пока нет и покупать его сейчас не нужно.
У временного туннеля нет гарантии недельного непрерывного соединения; смена адреса
должна обрабатываться клиентом, отключённый компьютер не обслуживает запросы.

## Что выполнить сейчас на Windows

Закройте старую игру, сохраните кампанию; обновление исходников не обновляет EXE.
Откройте PowerShell:

```powershell
Set-Location D:\Projects\DND-NCFU
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Обновление остановлено.' }
.\scripts\check_tester_host.cmd
```

Это локальная проверка Python/Git/cloudflared/winget, без сети, чтения ключей,
запуска сервера, установки программ, изменения сна/брандмауэра/служб Windows.
Скрипт не выводит имя ПК/пользователя и IP. Код выхода2 означает отсутствующий
инструмент, не повреждение игры. Пришлите полученный текст проверки.

Если cloudflared не найден и winget_available=true, установите бесплатную программу
туннеля из пакета Cloudflare, не на компьютере знакомого:

```powershell
winget install --id Cloudflare.cloudflared --exact --source winget
```

Ознакомьтесь с показываемыми установщиком условиями. Не добавляйте флаги скрытого
согласия с условиями. Затем откройте PowerShell заново, снова выполните проверку.
Если winget отсутствует или установка отклонена, пришлите текст — не меняйте
политики безопасности и не скачивайте случайную копию программы с другого сайта.
Официальная программа: https://github.com/cloudflare/cloudflared/releases

Пока не создавайте новый Setup и не передавайте существующий как готовый комплект
с автоматическим подключением через туннель: следующие компоненты ещё не реализованы.

## Что остаётся подготовить в игре и шлюзе

1. Local HTTP listener только127.0.0.1 за публичным HTTPS-туннелем. Сейчас serve
   требует собственный сертификат; открывать незашифрованный0.0.0.0 нельзя.
2. Асинхронные задания и проверка результата короткими запросами. Текущий
   world_seed допускает15минут, а Cloudflare документирует ограничение ожидания
   ответа125секунд. Обычное проксирование текущего долгого POST может оборваться.
   Проверки состояния не должны повторно вызывать платную генерацию.
3. Постоянная ссылка на небольшой подписанный документ обновления адреса.
   В открытом репозитории допустимы адрес, версия, срок и подпись. Ключ RouterAI,
   клиентские допуски, одноразовые коды и закрытый ключ подписи туда не попадут.
   Публичный ключ проверки закрепляется в персональной сборке. Игра должна
   проверить подпись до отправки допуска на новый адрес. Одного HTTPS JSON с
   произвольным адресом недостаточно для такой передачи учётных данных.
4. Персональная автоматическая активация установщика: одноразовый код, серверная
   квота100₽/30дней, сохранение допуска DPAPI, отзыв и продление без нового Setup.
   Сейчас клиент поддерживает ручной ввод допуска; автоматический обмен ещё нужен.
5. Запуск/остановка туннеля, безопасное обновление документа адреса и сборка Setup.
   Сначала проверки локально, потом проверка на ПК владельца и разрешённая им
   отдельная облачная проба. Не выдавать эту инструкцию за уже работающий сервис.

Ссылка для чтения публичных файлов существующего репозитория проверена без
авторизации (README вернул HTTP200). Это ещё не опубликованный документ адреса.
Никакой серверный адрес, токен или ключ в репозитории в этом этапе не публиковался.

## Что понадобится позже от владельца

- Отдельный RouterAI-ключ с установленным лимитом в кабинете, вводимый только
  локально на ПК. Не присылайте ключ в чат и не вставляйте его в команды Git.
- Запуск подготовленного шлюза/туннеля и вход в GitHub для обновления публичного
  документа адреса. Доступа к учётной записи/пароля от владельца Codex не запрашивает.
- Проверка установленной игры знакомым. Отзыв должен блокировать новые генерации,
  оставляя сохранения и готовые иллюстрации доступными.

Подготовка кода и туннеля не делает RouterAI бесплатным: запросы оплачивает владелец.
В этом этапе нет платных POST, арендованных серверов, регистрации или установки
cloudflared из среды Codex. Windows-проверку владелец выполняет сам; Linux её не заменяет.
