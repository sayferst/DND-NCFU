# Каталог мира, постоянные ID и проверяемые попытки

Пакет1O.2 (каталог1O.1 и исправление SQLite), 19 октября2026. Владелец подтвердил архитектурный план и поручил
начать с Windows-ошибки и общей базы. Оригинал требований сSHA-256 сохранён в
research/system_logic. Инструкции из вложения сами по себе не запускают команды.

## Для чего мастеру база

Мастер получает постоянные записи о типах и экземплярах. «Железный меч» — тип;
конкретный меч в сундуке — экземпляр с собственнымID, держателем и состоянием.
Знание типа не выдаёт меч герою. Возможная добыча босса не означает выпавшую добычу.

В SQLite есть таблицы типов, экземпляров, категорий, состава, эффектов, возможной
добычи и событий создания. Поиск работает по русскому названию и точномуID.
Мастер получает до6 релевантных записей, может запросить до5 ID/поисковых фраз
одной дополнительной пачкой. Повторный поиск ограничен; вся база в запрос не идёт.
Физический контекст большого реестра ограничен40предметами/20существами, остальные
доступны поиском. Дополнительный запрос к модели может оплачиваться.

## Десять разделов

1. Квестовые предметы.
2. Материалы: камень, металлы, руда, дерево, жидкости, газы, ткань, стекло и т.д.
3. Оружие, боеприпасы, посохи, книги заклинаний.
4. Растения, включая лекарственные/ядовитые и разумные/агрессивные.
5. Медицина, зелья, отвары, свитки, бинты.
6. ВстреченныеNPC.
7. Животные и мобы.
8. Боссы.
9. Броня, включая защиту животных.
10. Остальные бытовые и сюжетные объекты.

Категорий у записи может быть несколько: живое растение-босс использует разделы
растений, существ и боссов. Поведение зависит от свойств, разделы помогают искать.

Стартовая база содержит **46 собственных типов**, включая23материала. Это начало
каталога вымышленного мира; исчерпывающий список заранее не требуется. Новые типы
и экземпляры добавляются мастером при появлении в сцене. Пять старых участников
учебного эпизода сохранены адаптером совместимости; новый случайный мир этим
пакетом ещё не создаётся. Невстреченные старые участники скрыты в публичном просмотре.

## Какие данные хранятся

Тип содержитID, имя, вид, категории, редкость, исходную цену, свойства, материалы,
эффекты, возможную добычу и происхождение. Экземпляр содержит другойID, ссылку
на тип, размещение, собственника, количество и индивидуальное состояние.

- Физические свойства: масса, объём, переносимость, вместимость, допустимая масса,
  запирание/открытие и прочность. Знакомые ограничения проверяются общим кодом.
- Состав: ссылки на типы материалов и их доли. Циклический состав запрещён.
- Эффекты: вид, величина, длительность и описание. Новое описание магии не является
  исполняемым заклинанием; неизвестные эффекты требуют отдельного обработчика.
- Оружие/броня: базовые защита, пробитие и прочность; материалы могут задавать
  equipment_modifiers. Итог — база плюс средний модификатор по долямparts с округлением
  вниз, минимум0. Расчёт доступен в записи; это homebrew, не таблицаSRD.
- Существа: максимум здоровья, класс/роль, цели, особенности; у экземпляра текущее
  здоровье, деньги, отношения и другое состояние. Кошельки/точныеHP/добыча/секреты
  скрыты в публичном просмотре. ГолосуNPC передаются цели и память отношений,
  а не его кошелёк или все секреты.
- Прочие вещи: текст книги, внешний вид, назначение и другие JSON-свойства.
  Произвольные описательные поля не исполняются какPython/SQL.

Цены хранятся в целых медных единицах (100 на условную золотую). Это ориентиры
авторского каталога, не обязательная цена торговца и не реальная экономика.
Материальные цены относятся к условной порции, указанной в данных. Химия,
термодинамика и все магические взаимодействия пока не симулируются.

## Как новая вещь становится частью игры

Мастер ищет тип, затем предлагает регистрацию новых записей и причину появления.
Валидатор проверяетID, ссылки, количества, свойства и размещение. Нельзя незаметно
перезаписать установленный тип, создать дубльID, положить сундук внутрь самого
себя, изменить имущество удалённогоNPC или выдать новую вещь прямо в руки героя.
После регистрации появляется событие; предмет можно получить обычным действием.

НовыйNPC может владеть предметами и быть получателем. Новые существа имеют своиID
и не подменяют трёх старых собеседников. Вложенные вещи следуют контейнеру;
оставленные предметы сохраняют размещение. Известные вместимость/масса/запирание
проверяются до броска. При отсутствии нужных размеров система сообщает, какие
данные отсутствуют, вместо выдуманного подтверждения.

## Свобода игрока и броски

Моральная причина не является условием нападения. Игрок задаёт намерение; модель
понимает его и предлагает действие, движок проверяет состояние/возможности,
а рассказчик оформляет результат. Вопрос, цитата и отрицание не выполняют атаку.
Непривычная формулировка может быть явно подтверждена вместе с названием действия
и цели. Отмена до броска сохраняет RNG и ресурсы.

Для зарегистрированных существ есть начальные проверяемые попытки:

| Попытка | Текущий авторский расчёт |
|---|---|
| Нападение | Сила или Ловкость героя, большая из двух; сложность по защите цели,5–25. При попадании урон max(1,2+модификатор). Материалы корпуса могут менять защиту |
| Перевязка | Мудрость против10; нужен ваш бинт и живая раненая цель. Один бинт расходуется; успех восстанавливает до4ОЗ |
| Помощь | Мудрость против10; успех повышает показатель доверия на1 |
| Помеха/обидное обращение | Харизма против10; успех повышает показатель обиды на1 |

Это отдельный **homebrew-пилот**, не полный бой/медицинаSRD и не универсальное
выполнение любой работы. Помощь здесь влияет на отношение; она не строит мост
и не создаёт предметы. Обычный старый боевой цикл сохранён. Новые одиночные
попытки ещё не имеют полной инициативы/ответных действий/автономных плановNPC.

При явно смертельной попытке достигнутое0HP может стать подтверждённой смертью.
Промах не превращает поверженного в погибшего. Простая перевязка не воскрешает.
Добыча не выдаётся от одного упоминания смерти. Ошибка писателя не откатывает
здоровье/расход бинта и не бросает повторно. Самостоятельное описание смерти
моделью без результата движка отклоняется; это ограниченные эвристики, не доказательство
безошибочности всей свободной прозы.

## Где база и как смотреть

В игре: **Раздел → Каталог мира**. Есть десять фильтров, поиск поID/названию,
переключатель типов/экземпляров и сведения о выбранной записи. Кнопки готовых
игровых ответов не добавлялись.

После первой регистрации или попытки, использующей каталог, рабочая SQLite-копия
появляется по умолчанию здесь:

`D:\Projects\DND-NCFU-data\world-catalog.sqlite3`

Она обновляется после применения действий и загрузки. При смене героя показывает
его текущую кампанию после активации каталога. Другая чужаяБД по этому пути не
перезаписывается: используется собственный application_id и атомарная замена.
Стартовый справочник доступен и до появления этого файла.

ТриJSON-ячейки остаются основным сохранением сессии и содержат каталог/события.
РабочаяSQLite — восстанавливаемая проекция согласованного состояния, а не вторая
независимая версия денег/инвентаря. Старые бинты, золото, здоровье и экипировка
читаются через живые привязки к прежним правилам. Произвольные переносы этих
старых ресурсов ещё не унифицированы. Полный переход к одному рабочему хранилищу
и единому исполнителю событий — следующий этап согласованного плана.

Кнопка экспорта создаёт новыйSQLite-файл с кампанией, каталогом и закрытыми данными
для автора проекта. Существующий файл не перезаписывается. Внутри есть снимок,
который проверяемо восстанавливается через storage.knowledge.restore_session.
API-ключ в сохранение и базу не включается.

## Включение мастера и проверка

В Рассказчике оставьте RouterAI/DeepSeekFlash, включите свободный чат и план мира,
примените настройки API. Сам каталог не требует интернета. Сетевые генерации —
опциональны, с прежней проверкой месячного лимита≤2000₽. Обычно это план+рассказ;
дополнительный поиск и исправление рассказа — дополнительные обращения.

Пример проверки: в новой сессии опишите открытую мастерскую с хозяином и попросите
осмотреть её. Создание новых записей зависит от предложения реальной модели;
если она ничего не предложила, каталог не имитирует появление объектов.
Зарегистрированные объекты видны в Каталоге мира и контексте мастера. Проверьте
ихID, перенос, отношение после помощи, сохранение и загрузку. Для раненогоNPC
попробуйте перевязку имеющимся бинтом. Точный исход броска не гарантируется.

Сохраните игру в ячейку и закройте окно перед обновлением:

```powershell
& {
    $ErrorActionPreference = 'Stop'
    Set-Location D:\Projects\DND-NCFU
    $saveDir = 'D:\Projects\DND-NCFU-data\saves'
    if (Test-Path $saveDir) {
        $backupRoot = 'D:\Projects\DND-NCFU-data\backups'
        New-Item -ItemType Directory -Path $backupRoot -Force | Out-Null
        $backupDir = Join-Path $backupRoot ('before-catalog-' + (Get-Date -Format 'yyyyMMdd-HHmmss-fff'))
        Copy-Item -LiteralPath $saveDir -Destination $backupDir -Recurse
    }
    git switch setup/development-environment
    if ($LASTEXITCODE -ne 0) { throw 'Не удалось переключить ветку.' }
    git pull --ff-only
    if ($LASTEXITCODE -ne 0) { throw 'Обновление не получено. Сохраните вывод.' }
    .\.venv\Scripts\python.exe scripts\repair_fixture_checkout.py
    if ($LASTEXITCODE -ne 0) { throw 'Ошибка проверки эталона.' }
    .\.venv\Scripts\python.exe scripts\check.py
    if ($LASTEXITCODE -ne 0) { throw 'Проверка не прошла. Сохраните вывод.' }
    .\.venv\Scripts\python.exe scripts\run_game.py
}
```
