## Обновить существующий проект и собрать на вашем Windows

Закройте игру. Сборщику нужны Git и Python 3.12 x64; на вашем ПК они уже
используются для разработки. Игроку готового пакета они не нужны. Первая сборка
скачивает только закреплённые инструменты Python из hash-lock, без моделей.
Не запускайте PowerShell от администратора.

```powershell
Set-Location D:\Projects\DND-NCFU
& {
    $ErrorActionPreference = 'Stop'
    $backup = 'D:\Projects\DND-NCFU-backups\before-1X-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
    New-Item -ItemType Directory -Path $backup | Out-Null
    if (Test-Path 'D:\Projects\DND-NCFU-data') {
        Copy-Item 'D:\Projects\DND-NCFU-data' (Join-Path $backup 'source-data') -Recurse
    }
    $exeData = Join-Path $env:LOCALAPPDATA 'DND-NCFU'
    if (Test-Path $exeData) {
        Copy-Item $exeData (Join-Path $backup 'exe-data') -Recurse
    }
    if (Test-Path 'prompts\master_system_prompt.local.txt') {
        Copy-Item 'prompts\master_system_prompt.local.txt' $backup
    }
    git pull --ff-only
    if ($LASTEXITCODE -ne 0) { throw 'Обновление остановлено. Не делайте reset; сохраните вывод.' }
    & .\scripts\build_windows.cmd
    if ($LASTEXITCODE -ne 0) { throw 'Сборка остановлена; сохраните вывод.' }
    Start-Process '.\dist\DND-NCFU\DND-NCFU.exe' -ArgumentList '--data-dir "D:\Projects\DND-NCFU-data"'
}
```

Скрипт сам ставит `requirements-build.lock` с хэшами, проверяет фикстуры,
запускает `scripts/check.py`, собирает onedir и проверяет EXE вне каталога проекта.
При ошибке предыдущая готовая сборка остаётся доступна; при успехе прежний пакет
перемещается в `dist/previous/<время>`. Пользовательские данные не мигрируются.
Текущая ветка — `setup/development-environment`; при локальных изменениях Git
останавливается, принудительный сброс не требуется.

Ожидаются:

- `dist/DND-NCFU/DND-NCFU.exe` и вся папка `_internal` рядом;
- `dist/DND-NCFU-Windows-x64-v0.2.0.zip` и `.zip.sha256`;
- внутри ZIP — `BUILD_MANIFEST.json` с SHA-256 каждого файла, версии зависимостей,
  лицензии и `verification/self-check.json`, `verification/smoke-test.json`;
- после запуска — заставка, затем главное меню с прежним миром при указанном
  `--data-dir`. Текстовый мастер DeepSeek Flash и настройки Художника не заменяются.

Для обычного повторного запуска сборщику достаточно:

```powershell
Set-Location D:\Projects\DND-NCFU
.\scripts\build_windows.cmd
```

`build_windows.cmd` запускает существующий `build_windows.ps1` в отдельном процессе
PowerShell с `-NoProfile -ExecutionPolicy Bypass`. Это устраняет показанный на ПК
владельца запрет запуска `.ps1`; постоянные политики Windows не меняются.
Если проект уже обновлён, тот же запуск можно выполнить напрямую:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_windows.ps1
```

При запуске `.cmd` двойным щелчком окно сборки может закрыться после завершения;
для просмотра вывода запускайте команду выше или `.cmd` из открытого PowerShell.
Пакет EXE по-прежнему создаёт один прежний PowerShell-сборщик.

## Запуск игроком без терминала

Получите ZIP, проверьте SHA-256, распакуйте **всю** папку DND-NCFU и дважды
нажмите DND-NCFU.exe. Отдельный EXE без `_internal` не является portable-пакетом.
Python, Ollama, терминал и IDE не нужны; для чата нужен доступ к облачному мастеру.
Просмотр сохранений, дневника, Хроник и готовых изображений остаётся локальным.
API-ключ вводится в панели «Мастер»/«Художник» и сохраняется только по выбору игрока.
Сборка не содержит ключей, личных промптов, кампаний и модельных весов.

Обновление: закройте приложение, распакуйте новую полную папку отдельно, проверьте
новую версию и лишь затем убирайте старый пакет. Внешние данные общие, файлы
программы не записываются в пользовательскую кампанию.
Приложение не подписано сертификатом; проверка подписи/репутации Windows может
отличаться. Не отключайте антивирус ради запуска. Публичный релиз не выполнялся.

## Где остаются данные и старые кампании

EXE по умолчанию использует `%LOCALAPPDATA%\DND-NCFU`, исходники — прежнюю
`D:\Projects\DND-NCFU-data`. Сборка не выбирает за вас миграцию между этими папками.
Сохранения, SQLite, изображения/версии/референсы, настройки и зашифрованные ключи
остаются снаружи программы. Установка/обновление EXE не удаляет их.

Чтобы EXE продолжал прежние кампании, создайте обычный Windows-ярлык на EXE.
В поле «Объект» укажите, например:

```text
"D:\Projects\DND-NCFU\dist\DND-NCFU\DND-NCFU.exe" --data-dir "D:\Projects\DND-NCFU-data"
```

Затем запускайте ярлык двойным щелчком. Можно сохранить существующий абсолютный
`RPG_VKR_DATA_DIR` вместо аргумента. Для EXE относительная папка и папка внутри
установки запрещены, чтобы обновление не уничтожило данные. При переносе на
другой ПК шифрование DPAPI привязано к прежнему профилю Windows: ключи потребуется
ввести заново. Сохранения и изображения не имеют такой привязки.
Личная инструкция мастера в пользовательской папке `prompts/master_system_prompt.local.txt`
подхватывается прежней системой; в пакет входит только стандартная инструкция.
Не переносите личную версию без резервной копии и явного выбора папки данных.

## Проверки готового EXE

Обычный запуск не вызывает тестовые API/платные модели. Для диагностического
режима выберите **новый** путь отчёта вне установленной папки:

```powershell
$exe = 'D:\Projects\DND-NCFU\dist\DND-NCFU\DND-NCFU.exe'
$report = Join-Path $env:TEMP ('DND-self-' + [guid]::NewGuid().ToString('N') + '.json')
Start-Process $exe -ArgumentList @('--self-check', '--report', ('"' + $report + '"')) -Wait
Get-Content $report -Encoding UTF8
```

`--self-check` проверяет ресурсы, изображения, справочники, Python/Qt TLS и SQLite
без чтения кампаний/ключей. `--smoke-test` дополнительно использует временный мир:
сохранение JSON/SQLite, RNG, кэш/референсы, разделы окна, настоящий DPAPI на Windows.
Два HTTP-запроса идут только на локальный тестовый сервер 127.0.0.1. Это проверка
контрактов/упаковки, не оценка качества или доступности DeepSeek/Recraft/FLUX.
Автоматическая сборка запускает оба режима с очищенными Python/PATH-переменными.
Сам факт запуска на машине сборки ещё не заменяет проверку чистого ПК без Python.

При ошибке обычного запуска появляется окно; диагностика сохраняется в
`<папка данных>/logs/error-<id>.json`. В ней только версия, тип исключения,
имя модуля/функции/строка, без API-ответов, ключей, локальных переменных и истории.
Отчёт не перезаписывается, загрузки логов в сеть нет. Если папка данных недоступна,
приложение сообщает, что записать отчёт не удалось.

## GitHub Actions, если собирать локально неудобно

Подготовлен `.github/workflows/build-windows.yml`: только ручной
`workflow_dispatch`, Windows x64, фиксированные SHA Actions, `contents: read`,
без секретов, платных моделей, автоматической публикации и push-триггера.

Важное ограничение GitHub: ручной workflow должен присутствовать в **основной
ветке**, чтобы появился в Actions. Сейчас код обновляется в согласованной ветке
`setup/development-environment`, основная ветка репозитория — `main`. Слияние в
main этой задачей не выполняется. Если workflow ещё не виден, используйте локальную
сборку выше или после обычного просмотра изменений перенесите workflow в main.
После этого: Actions → Windows portable → Run workflow → выберите ветку
`setup/development-environment` → оставьте installer выключенным → Run.
После зелёного результата скачайте артефакт `DND-NCFU-Windows-x64`; внутри
архива артефакта будет portable ZIP с контрольной суммой. Распакуйте оба уровня.
Срок хранения артефакта — 14 дней; сохраните нужный ZIP отдельно.
Из этой сессии запуск Actions не выполнен: GitHub API недоступен (403).

## Необязательный установщик

Подготовлен `installer/DND-NCFU.iss`. Для разработчика с установленным Inno Setup6:

```powershell
.\scripts\build_windows.cmd -Installer
```

Сначала проходят все portable-проверки, затем запускается ISCC. Без компилятора
скрипт сообщает об этом, не устанавливая его самостоятельно. Установщик работает
от обычного пользователя, предлагает ярлыки, устанавливает в
`%LOCALAPPDATA%\Programs\DND-NCFU`. Сохранения в `%LOCALAPPDATA%\DND-NCFU`
деинсталлятор не удаляет. Сборка/установка/обновление/деинсталляция нативно ещё
не проверены; наличие рецепта не объявляется готовым проверенным Setup.exe.

## Ручная приёмка Windows 10/11 x64

1. На чистом ПК/VM без Python распаковать ZIP в путь с пробелами и кириллицей.
2. Двойной щелчок: нет терминала; видны название, иконка, анимация и главное меню.
3. Проверить масштабирование Windows 100/150/200%, меню, создание героя, Хроники,
   Мастера и Художника. Не запускать платную генерацию ради проверки упаковки.
4. На копии данных открыть старую кампанию, сохранить/перезапустить, проверить
   инвентарь, историю и кэш изображений. Перенос программы не должен терять данные.
5. Отдельно сохранить тестовый ключ через DPAPI, перезапустить, удалить его через
   интерфейс; ключ не должен появиться открытым текстом в пакете или логах.
6. Отключить сеть: доступен локальный просмотр; чат объясняет необходимость облака.
   Проверить отказ записи в выбранную папку и повреждение ресурса на копии пакета:
   должна появиться диагностика, а пользовательские данные сохраниться.
7. Для Setup отдельно проверить обычную установку, обновление поверх, ярлыки и
   удаление только программы. Не считать windows-latest эквивалентом Windows10/11.

Реальные оплачиваемые проверки API выполняются отдельно с согласия владельца.
Текущая работа не меняла игровые расчёты, канон, RNG, схемы сохранений и модели.
