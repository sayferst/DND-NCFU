# Мастер, память и ChatGPT — пакет 1N, 19 октября 2026

## Причина переработки

Пользовательский диалог показал: «пойду узнаю источник гула» превращается в
повтор пейзажа, а «подойду к девушке и спрошу» отклоняется как составная команда.
В прежнем цикле модель выбирала одну команду, затем могла только оформить
заранее подготовленный ответ. SYSTEM_PROMPT запрещал новые события; agency-фильтр
отклонял даже часть описаний заявленного игроком подхода. Это архитектурные
ограничения, а не доказательство, что веса Qwen неисправны.

## Что реализовано

Новый режим включён флажком «Мастер: развивать сцену и запоминать новые детали»
по умолчанию. Текст игрока поступает в контракт мастера, а не обязательно в
классификатор одной команды. Для мирной сцены модель предлагает рассказ,
говорящего существующего NPC и до трёх устойчивых фактов. Проверка сверяет ревизию,
место, доступность собеседника, схему и отсутствие замены установленного факта.
После проверки сцена, факты и сегменты реплик сохраняются вместе. Заявленный
подход и следующий вопрос могут быть описаны одним ответом.

Отдельно остаётся mechanical_command: бой, бросок, исследование характеристикой,
обмен, получение предмета или переход между игровыми местами сначала считает
движок. Смешать такой запрос с выдуманным результатом в одной proposal нельзя.
Явное исследование характеристиками по-прежнему имеет локальный надёжный маршрут.
Проза не меняет HP, золото, XP, инвентарь и числовые отношения напрямую.

Фантазия разрешена в реакциях, бытовых деталях, мотивах, заботах и слухах.
Предложенный факт относится только к текущему месту или собеседнику, получает
источник через SceneRecord.model и привязку к ходу. Замена того же subject/key
иным значением запрещена. Слух — слова персонажа, не доказанная истина.
Проверка структурная: она не доказывает смысловую непротиворечивость любых
разных предложений и не гарантирует литературное качество модели.

Сейчас действуют прежние три места и существующие NPC. Новых регионов, существ,
боссов, предметов/характеристик и динамических переходов модель ещё не создаёт.
План развития сцены — ограниченное повествовательное предложение, не универсальный
планировщик произвольных механических действий. Секретная память NPC пока не
генерируется; приватность предусмотрена в поиске, но её полного игрового цикла нет.

## Как использовать вашу подписку ChatGPT Plus

Plus относится к приложению ChatGPT. Она не включает программный API-баланс,
не предоставляет ключ игры и не позволяет из этого чата запустить обучение весов.
API — отдельное подключение с отдельными условиями оплаты; оно не добавлено.
Вход в аккаунт, cookies, браузерная автоматизация и неофициальные обходы не нужны.

Вместо этого реализован явный ручной обмен. Он не требует Ollama или платного API
и может работать с доступным пользователю обычным чат-интерфейсом.

1. Получите обновления, запустите игру. В «Рассказчик» включите «Включить
   ИИ-мастера (локальный или ChatGPT вручную)» и «ChatGPT вручную через
   копирование (без API)». Свободный ввод должен быть включён.
2. Вернитесь к игре. Напишите «подойду к девушке и спрошу, как у нее дела».
3. Откроется окно обмена. Нажмите «Копировать запрос для ChatGPT».
4. Откройте отдельный обычный разговор в ChatGPT для игры. Вставьте пакет
   целиком и попросите ответить по его инструкции. Лучше не использовать для
   этого ветку Codex, в которой меняются исходники проекта.
5. Скопируйте JSON-ответ ChatGPT целиком в нижнее поле окна игры и нажмите
   «Проверить и применить ответ». Содержимое должно включать исходный request_id.
   JSON-файл руками создавать не нужно. Игра не отправляет пакет самостоятельно.
6. При мирном разговоре сразу появится сцена. При механическом действии игра
   сначала считает результат, затем откроет второй пакет для художественного
   оформления уже готового итога. Второй ответ не бросает кубик повторно.
7. Сохраните сессию в одну из трёх ячеек. После перезапуска включите ручной
   режим снова; настройка источника мастера пока не сохраняется в предпочтениях.

Ответ другого запроса/сессии/ревизии не применяется. Закрытие первого окна
отменяет ещё не выполненный шаг; закрытие второго сохраняет уже рассчитанный
исход без нового художественного текста. Лимиты и доступность вашего ChatGPT
определяются вашим тарифом. Автоматического подключения к текущему чату нет.
Источник записывается честно: chatgpt-manual, точное имя модели неизвестно игре.
Если ChatGPT ответил обычной прозой вместо JSON, попросите вернуть только JSON
по proposal_schema и сохранить request_id. Не добавляйте API-ключи в пакет.

## Локальный автоматический режим

Отключите ручной ChatGPT, оставьте новый режим мастера и выберите установленную
модель Ollama. Модель использует тот же контракт и SQLite-подбор памяти. Для
мирной сцены требуется один запрос, не классификация + пересказ шаблона.
Механический исход всё ещё отделён от повествования. Можно временно выключить
новый режим для прежнего ограниченного маршрута. Новая модель не скачивается.

Qwen3 1.7B может ошибаться в русском языке, JSON и логике даже с исправленным
циклом. Это проверяется на настоящей модели отдельно. Контекст 8192 и лимит
900 выходных токенов нового режима требуют замера скорости/RAM на Windows;
старые стадии сохраняют прежние параметры. В облаке настоящей Ollama нет.

## Память SQLite и одна база кампании

storage/knowledge.py строит SQLite-представление текущей сессии. Таблицы:

| Таблица | Содержимое |
| --- | --- |
| snapshot | Полная восстанавливаемая сессия, версия 12 |
| entities | Герой, места, акторы, существующие публичные профили, занятия/цели |
| facts | Новые устойчивые детали с subject/key и видимостью |
| events | Все ходы, исходные слова игрока и результаты со ссылкой на источник |
| relationships | Существующие отношения/обида по игровым правилам |
| inventory | Текущий инвентарь героя |
| examples | Небольшие авторские примеры формы ответа и их происхождение |

Поиск параметризован; в запрос модели не выгружается snapshot или вся база.
Выбираются факты доступной сцены, до четырёх подходящих старых событий,
публичные данные присутствующих NPC и до двух сюжетных примеров. Общий предел
поискового блока — 6000 символов. Приватные факты не выдаются. Поиск лексический,
по SQLite LIKE; эмбеддинги/векторная БД/библиотеки RAG не требуются.

В «Память мира» есть «Экспорт всей сессии в SQLite…» и «Открыть сессию из SQLite…».
Выберите файл, например D:\Projects\campaign-2026-10-19.sqlite3, вне папки ячеек.
Один файл содержит всю текущую сессию и поисковые таблицы. Существующий файл
экспортом не перезаписывается; для новой версии выберите другое имя.
Открытие восстанавливает персонажа, историю, канон и последовательность кубиков.

Обычные три ячейки пока остаются атомарными JSON v12 для совместимости. SQLite —
реальная поисковая проекция и отдельный полноценный экспорт/импорт, а не вторая
синхронно изменяемая истина. При восстановлении authoritative snapshot имеет
приоритет над вручную изменёнными поисковыми таблицами. На каждый запрос индекс
пока строится заново в RAM; это сокращает контекст модели, не является ещё
оптимизацией времени индексации больших кампаний. Excel для вычислений/канона
не нужен; при необходимости CSV можно сделать отдельным представлением.

## Совместимость и проверка

Writer JSON v12/reader v1–v12; Turn.scene хранит SceneRecord, связанные факты и
модель. Narration v7/reader v1–v7, старые хэши сохранены. Настоящая fixture v11
получена кодом 514356a до изменений, seed5, оба прежних броска сохранены.
Старые fixtures v1–v10 и зависимости не менялись. Перед записью v12 нужна копия
прежних saves для отката на старую игру.

Проверяются HTTP-цепочка новой сцены, составная реплика, отмена/устаревшие ответы,
ручной обмен без сети, двухстадийная арифметика без повторного броска, SQLite
roundtrip, приватность/предел контекста, запрет замены фактов и откат отказа записи.
Legacy-сюита UI явно выбирает прежний режим; новый режим по умолчанию отдельно
проверяется на новом окне. Это не измерение качества настоящего ChatGPT/Qwen.
