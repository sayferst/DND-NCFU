# Новые шаблоны мастера и проверка предложений

Библиотеку можно подключить до обучения модели. Обучение меняет поведение
рассказчика, а доступ к HP, деньгам, предметам и RNG остаётся у Python-движка.
Не выдавайте модели соединение SQLite/PostgreSQL, SQL или команду `approve`.

## Как добавить нового NPC

Готовый оригинальный пример: `data/world_library/examples/authored-npc.json`.
Он рассчитан на библиотеку, инициализированную штатным `init`: ссылки на вид,
лекарства и дорожные припасы используют существующие ID. Это один новый
шаблон, а не изменение прежнего персонажа. Скопируйте пример под новым именем
и отредактируйте биографию, внешность и числовые поля. В JSON нет исполняемого кода.

Из корня распакованного проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe scripts\world_library.py --db C:\DND\world-library.sqlite3 propose data\world_library\examples\authored-npc.json
```

Команда выводит `proposal`, `record_id` и `status: pending`. Пока предложение
не подтверждено, оно не находится в поиске шаблонов и не создаёт NPC в мире.
Подставьте полученный идентификатор предложения вместо `PROPOSAL_ID`:

```powershell
.\.venv\Scripts\python.exe scripts\world_library.py --db C:\DND\world-library.sqlite3 proposal PROPOSAL_ID
.\.venv\Scripts\python.exe scripts\world_library.py --db C:\DND\world-library.sqlite3 approve PROPOSAL_ID
```

Для отказа используйте `reject PROPOSAL_ID` вместо `approve`. Оба решения
попадают в аудит. Нельзя подтвердить отвергнутое предложение. Повторная отправка
создаёт отдельную проверку того же содержимого; ID шаблона остаётся устойчивым.
Повтор уже выполненного подтверждения не создаёт вторую версию и не возвращает
в оборот архивированный шаблон.

В окне библиотеки кнопка «Предложить новый шаблон» принимает тот же JSON.
Перед решением отображаются описание и параметры; по умолчанию выбран отказ.
Для просмотра полного JSON используйте исходный файл или команду `proposal`.
Подтверждение добавляет только глобальный шаблон. Отдельная кнопка создания
экземпляра работает с новой копией экспортированного мира и не переписывает
выбранное исходное сохранение. Для NPC она также создаёт проверенный начальный
инвентарь. CLI-эквивалент с ID из `record_id`:

```powershell
.\.venv\Scripts\python.exe scripts\world_library.py --db C:\DND\world-library.sqlite3 instantiate TEMPLATE_ID elna_prichal C:\DND\world-before.sqlite3 C:\DND\world-with-elna.sqlite3 --with-inventory
```

## Контракт генерации

Верхний уровень файла содержит ровно `record`, `model`, `prompt_version`.
`record` соответствует профилю из `data/world_library/schemas.json`; поля
`id` и `provenance` можно опустить. Валидатор сформирует устойчивый ID из
нормализованной записи и запишет происхождение `invented/homebrew`, модель,
версию промпта и контракт движка. Поле `review` принудительно остаётся
`unreviewed`: нажатие кнопки не считается независимой редакторской приёмкой.
Время операции записывается базой в аудит. Максимум одной записи — 64 000
символов канонического JSON; модель и версия промпта — по 128 символов.

Новый NPC обязан иметь все шесть характеристик, HP, уровень, КД, урон,
биографию, внешность и остальные обязательные поля своего профиля. `species`
должен указывать на известный вид/расу и совпадать с единственной связью
`species` количества 1. Начальный инвентарь не может содержать другого NPC,
расу, навык или справочную карточку. Неизвестные события смены настроения
отклоняются, а не исполняются как текстовая команда.

Для новых NPC устанавливается `social_version: library-social-1`, для еды,
лекарств, вымышленных ядов, книг и квестовых вещей —
`utility_version: library-utility-1`. Эти явные контракты включают существующие
проверенные обработчики независимо от имени модели в происхождении. Нельзя
запросить неизвестную версию или добавить Python/SQL callback. Текст о новой
способности сам по себе не создаёт её обработчик. Прочие профили сохраняют
свои отдельные правила и ограничения; справочная карточка не становится
игровым заклинанием от смены названия.

## Ссылки, транзакции и совместимость

При отправке фиксируются версии и контрольные суммы связанных шаблонов.
Если материал, вид или предмет изменился либо был архивирован до решения,
подтверждение отклоняется: отправьте предложение заново и проверьте новые
зависимости. Нельзя незаметно подменить уже существующий шаблон новым содержимым.
Обновление существующего ID — отдельная операция сопровождающего с ожидаемой
ревизией. Экземпляры в прежних мирах сохраняют закреплённые Definition.

Шаблон, неизменяемая версия, ссылки, решение и аудит подтверждения записываются
одной транзакцией. Ошибка записи, включая ошибку финального SQLite `commit`,
откатывает всю операцию. В PostgreSQL шаблоны блокируются на время
проверки/записи, предложение — на время решения. Миграция 006 добавляет индекс
предложений и новые ревизии схем, не изменяет опубликованные миграции 001–005
и не открывает пользовательские сохранения.

Текущий канал создания нового шаблона — файл/API с проверкой сопровождающего.
В игровом чате мастер может предлагать создание по известному ID через
`library_requests`; автоматическая выдача рассказчику права подтверждать новые
шаблоны не предусмотрена. Порядок внедрения и обучение до/после подключения:
`docs/WORLD_MASTER_TRAINING.md`.
