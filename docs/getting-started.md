# Установка и первый запуск

## Windows-установщик

Скачайте нужный EXE и его `.sha256` из опубликованного GitHub Release.
Проверьте хэш командой `Get-FileHash .\setup.exe -Algorithm SHA256` (для второго
варианта замените имя на `setup_api.exe`). Затем запустите установщик и игру.
Python, Git и ngrok на компьютере игрока не нужны. Пакеты пока не подписаны
коммерческим сертификатом издателя; Windows может показывать неизвестного издателя.
Не отключайте защиту Windows; решение о запуске принимайте по источнику и хэшу файла.

`setup.exe`: откройте «Разработчик», задайте локальный пароль доступа к настройкам,
настройте ИИ-мастера и художника. Этот пароль не является аккаунтом провайдера.
`setup_api.exe`: нажмите «Активировать тестовую игру», вставьте лично полученный
код владельца. После активации подключения настраиваются через шлюз. Общедоступного
кода доступа нет; владелец должен оставить свой хост включённым.

Варианты имеют общий идентификатор приложения и каталог данных: установка одного
поверх другого заменяет профиль программы. Это не два независимых игровых аккаунта.
Перед сменой варианта сохраните резервную копию данных.

## Исходники

Команды установки Python 3.12 приведены в README. Сохраняйте `.venv` и lock-файлы;
активировать окружение в PowerShell необязательно — вызывайте его Python напрямую.
На Linux используйте `.venv/bin/python`; для GUI нужен графический сеанс и библиотеки Qt.

Данные исходников хранятся рядом с checkout в `<имя-проекта>-data`, данные EXE —
в `%LOCALAPPDATA%\DND-NCFU`. Ресурсы внутри установленной программы только читаются.
Для отдельного тестового профиля задайте абсолютный `RPG_VKR_DATA_DIR`.

Создайте героя, заполните пожелания к миру, нажмите «Создать новый мир».
Полоса ожидания не показывает точный процент обработки провайдера: завершение
подтверждается только после получения и проверки мира. При ошибке герой остаётся
черновиком; можно повторить запрос, но облачная повторная генерация может стоить денег.
