# Закрытое тестирование 0.3.0 — сервер и допуски

Статус: код и локальная интеграция реализованы. Владелец сообщил, что сервера
пока нет. Никакой сервер не арендован и не развёрнут в интернете. Настоящий
RouterAI не вызывался. Чужому компьютеру облачная игра станет доступна после
развёртывания HTTPS-сервиса и проверки владельцем. Windows-установщик создаётся
существующим сборщиком на Windows, не подменяется Linux-пакетом.

## Устройство

Игра → HTTPS DND-NCFU → фиксированный https://routerai.ru/api/v1 → ответ игре.
На сервере только Python 3.12 и стандартная библиотека, без PySide/моделей.
Игровые кампании, механика, публичные знания и иллюстрации остаются в клиенте.

`server/gateway.py` не входит в EXE. RouterAI-ключ задаётся только серверной
переменной DND_ROUTERAI_KEY. Токены Codex/MCP, административный SSH-доступ,
RouterAI и допуски тестировщиков — разные полномочия. Локальный пароль консоли
не отправляется серверу. HTTP-админки нет: выпуск/отзыв доступны только оператору
с доступом к серверной CLI и БД. Не передавайте эту БД тестировщикам.

Сервис допускает только DeepSeek Flash, Recraft V4.1 Flash и FLUX 3 Image Klein.
DeepSeek ID задаёт оператор при старте, клиент не может выбрать другую модель.
У владельца существующая выбранная модель при переносе интерфейса сохраняется.
Шлюз ограничивает формат/размер, число запросов/созданий миров, расходы одного
допуска и общий расход. Квоты допусков — на весь срок, автоматического месячного
обнуления нет. Для нового периода оператор выпускает новый допуск.

SQLite BEGIN IMMEDIATE резервирует стоимость до единственного POST. Один
незавершённый запрос на допуск, не более 6 платных запросов в минуту. Request ID
нельзя отправить второй раз, даже после сетевого сбоя. Отсутствие подтверждённой
стоимости оставляет резерв; ошибка/перезапуск его не освобождает. Сбой тарификации
выше резерва блокирует следующие генерации до проверки оператором.

Сумма текста резервируется по актуальному тарифу, верхней границе входа
(UTF-8 + запас на служебные токены) и запрошенному выходу. Для изображений
принимается только подтверждённая полная цена за изображение; дополнительные
неизвестные тарифы отклоняются. Резерв не гарантирует неизменность тарифов внешнего
провайдера: дополнительно поставьте жёсткий лимит в кабинете RouterAI. Изменения
локальных файлов клиента не меняют серверные квоты.

Граница новых миров считается для операции world_seed с выходом до 65536 токенов;
остальные операции ограничены 16000. Сервер не интерпретирует смысл произвольной
прозы и не определяет по тексту, пытается ли человек сочинить другой мир в чате.
Все такие запросы продолжают расходовать общую квоту и бюджет допуска.

Референсы принимаются только как bounded PNG data URL, без URL клиента. Получение
CDN-файла возможно только по URL из ответа провайдера, HTTPS, с проверкой всех
DNS-адресов и закреплением публичного IP при TLS-соединении; без Authorization и
переадресаций. Возвращается base64. Тела запросов, пароли, ключи, токены и текст
диалогов в серверные журналы/БД не записываются. В БД только хеши допусков, квоты,
ID/время запросов, суммы и состояние. Нет аппаратных идентификаторов/телеметрии.

## Развёртывание после появления сервера

Нужен постоянно доступный компьютер с Python 3.12, входящим HTTPS и доверенным
TLS-сертификатом для своего домена. Это может быть уже имеющийся компьютер;
покупать VPS сейчас не требуется. Доступность через NAT/провайдера и домен нужно
проверить отдельно. Самоподписанный сертификат обычная игра не примет. Не отключайте
проверку TLS. Бесплатный сертификат можно получить через ACME после настройки
своего домена. Действия с DNS/роутером/Windows выполняет владелец осознанно.

Скопируйте `server/` на сервер. Отдельный непривилегированный пользователь сервиса,
каталог БД с правами 700. Сертификат/закрытый ключ TLS и RouterAI-ключ — вне Git,
владелец процесса должен иметь доступ к ним. Пример Linux (секрет вводится скрыто,
не вставляется в историю команды):

```bash
cd /srv/dnd-ncfu
umask 077
read -rsp 'RouterAI key: ' DND_ROUTERAI_KEY
export DND_ROUTERAI_KEY
python3.12 -m server.gateway --db /srv/dnd-data/access.sqlite3 --global-rub 100 serve \
  --bind 0.0.0.0 --port 8443 \
  --cert /etc/dnd-tls/fullchain.pem --key /etc/dnd-tls/privkey.pem
```

Адрес клиента: `https://ваш-домен:8443/api/v1`. При использовании reverse proxy
он должен передавать на TLS listener, ограничивать соединения/тела/таймауты и не
логировать Authorization/тела/коды допуска. API не доверяет X-Forwarded-*.
Порт/сертификат/перезапуск сервиса настройте средствами своего хостинга. Шлюз
требует сертификат и ключ при serve, незашифрованный внешний listener не создаётся.

Серверные лимиты задаются оператором. Сохраняйте одно значение --global-rub при
управлении и serve. Значения в примере — пример, не разрешение на расходы.
Реальная облачная проверка требует отдельного согласия владельца.

## Выдать, проверить, отозвать допуск

В другом терминале сервера, с тем же пользователем/путём БД:

```bash
python3.12 -m server.gateway --db /srv/dnd-data/access.sqlite3 --global-rub 100 issue tester01 --days 7 --rub 10 --requests 50 --worlds 2
python3.12 -m server.gateway --db /srv/dnd-data/access.sqlite3 --global-rub 100 list
python3.12 -m server.gateway --db /srv/dnd-data/access.sqlite3 --global-rub 100 revoke tester01
```

Первая команда один раз печатает персональный код. Передайте его только выбранному
тестировщику; не публикуйте в issue/логе/репозитории. В БД только SHA-256 случайного
256-битного допуска. Допуск потенциально извлекаем из клиента, поэтому срок,
отзыв и квоты обязательны. Отзыв блокирует новые операции немедленно; уже
отправленный RouterAI-запрос может завершиться и быть оплачен.

Кнопка «Активировать тестовую игру» принимает код. На Windows он сохраняется
DPAPI текущего пользователя, после перезапуска повторный ввод не нужен. В Linux
допуск действует в сеансе; DND_TESTER_TOKEN предназначен для локальной разработки.
Авторизация проверяется сервером на каждом запросе. Активация сама не тратит деньги.

После аварии или неопределённого списания не удаляйте строки calls и не выдавайте
неограниченный новый допуск вместо сверки. Остановите сервис, сохраните копию БД,
сверьте запросы с кабинетом RouterAI. До такой сверки резерв/блокировка сохраняются.
В текущей версии отдельная автоматическая сверка с биллингом провайдера отсутствует.

## Сборки

Developer Build: стандартная команда владельца, выбранные провайдер/модель и DPAPI
сохраняются. Интерфейс открывается в режиме игрока; «Разработчик» требует локальный
пароль 995539, возможна смена. Пароль — только защита UI от случайного доступа.
Он не защищает API-ключ от владельца самого компьютера и не даёт прав на сервере.

Tester Build: в публичном release-profile.json только профиль, HTTPS-адрес, модель
и commit. Ни ключ владельца, ни общий допуск не включаются в пакет. Даже при старых
настройках владельца Tester Build использует только шлюз; нет прямого fallback.
Технические настройки прямых провайдеров отключены и после локального входа.

После реального развёртывания сервера, на Windows:

```powershell
Set-Location D:\Projects\DND-NCFU
.\scripts\build_windows.cmd -Installer -Profile tester -GatewayUrl 'https://ВАШ-ДОМЕН:8443/api/v1'
```

Сборка отвергает Tester Build без HTTPS-адреса. Отдельно проверьте доступность этого
адреса на компьютере тестировщика; наличие URL в пакете не означает доступный сервер.
Portable: `dist/DND-NCFU-Windows-x64-v0.3.0.zip` и SHA256.
Установщик: `dist/DND-NCFU-Setup.exe`, только после native проверок и Inno Setup 6.
Самопроверка пакета изолирует пользовательские ключи/допуски и использует loopback,
а не адрес настоящего сервера. История, RNG, ресурсы и визуальный реестр проверяются
в настоящем пакете; сквозной Tester flow дополнительно проверяется исходными Qt-тестами.

## Передача первому тестировщику

1. Развернуть HTTPS и выставить лимит отдельного RouterAI-ключа в кабинете.
2. Проверить сертификат, отказ без допуска, отзыв, квоты; разрешить один платный
   сценарий отдельно, если владелец готов к расходу. Сейчас он не выполнялся.
3. Собрать Tester Build на Windows и проверить clean install без Python, F11,
   1366×768/1920×1080, создание/сохранение/загрузку, фотоальбом и отключённые эффекты.
4. Выдать краткосрочный небольшой допуск, передать Setup/ZIP и код отдельно.
5. Тестировщик устанавливает, активирует, создаёт героя/мир, играет; модели не выбирает.
6. При ошибке сохраняет кампанию и передаёт безопасный отчёт/описание владельцу.
   По окончании отозвать допуск. Обновление/удаление программы сохраняет данные.

Не объявлять интернет-сервис и Windows installer проверенными на основании
локальных HTTP/Qt и Linux PyInstaller. Известные границы проверок — в отчёте
`docs/validation/player-ui-2026-10-21/README.md`.
