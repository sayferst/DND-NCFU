# Промпт Мастера: оформление сцен и диалогов

25.10.2026: стандартная инструкция заменена присланной владельцем версией v3.
Сводка внедрения большого DOCX и оставшиеся подсистемы:
[карта требований](design/gameplay-v3/README.md).

Версия проекта: [master_system_prompt.txt](../prompts/master_system_prompt.txt).
Это инструкция для модели, а не обещание идеального ответа: качество зависит
от выбранной модели, доступного контекста и лимита ответа.

Описания и действия отделены от прямой речи пустыми строками. Реплики начинаются
с длинного тире; говорящего обозначает известное имя или наблюдаемая роль.
Короткий заголовок места нужен при смене сцены. Точная дата и время допускаются
только если они действительно заданы игрой. Встроенный журнал остаётся обычным
текстом; Markdown-таблицы и жирная разметка не требуются.

Объём зависит от ситуации: обычное действие чаще занимает 1–3 предложения,
важная новая сцена раскрывается полнее, беседа не растягивается ради объёма.
Это ориентиры, а не обязательные квоты. «Кратко» имеет приоритет над общим
литературным тоном. Даже подробный режим не требует заполнить лимит символов.
Псевдоним DeepSeek получает тот же профиль объёма, что и конкретная модель.

Дополнены правила темпа: короткий ответ не раздувается до монолога, отказ и уход
не перезапускают бесконечную цепочку поручений, состоявшийся путь не повторяется.
Сводка сделки отделяет обсуждение от подтверждённой оплаты и передачи имущества.
Карточки используют только публичные подтверждённые данные. Тайны ведущего,
деньги NPC и неизвестные свойства не раскрываются ради красивого оформления.

Примеры — только образец формы, они не создают места, NPC или предметы.
Правила действуют в художественном тексте opening/reply; служебные JSON-планы
и категории проверок сохраняют свои схемы. Движок по-прежнему считает последствия.

## Как получить новую версию

В PowerShell из `D:\Projects\DND-NCFU`:

```powershell
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Обновление остановлено.' }
.\Команды\BUILD_EXE.bat
```

Для общего установщика вместо BUILD_EXE используйте BUILD_SETUP.bat
при работающем хосте. Уже установленный EXE не скачивает новый промпт сам:
его нужно пересобрать или установить новую сборку. Менять API-ключи, пароли
и создавать новый мир для применения правил к следующим ходам не требуется.
Новый промпт не переписывает прошлые сообщения и сохранённые события.

## Личная инструкция имеет приоритет

При запуске исходников личный файл находится в
`prompts\master_system_prompt.local.txt`. Для обычного установленного EXE:
`%LOCALAPPDATA%\DND-NCFU\prompts\master_system_prompt.local.txt`.
При заданном `RPG_VKR_DATA_DIR` используется каталог данных из этой переменной.
Если файл существует, он целиком заменяет стандартный промпт; обновление
проекта не перезаписывает его. Сохраните резервную копию и вручную перенесите
новые правила в личную версию либо переименуйте личный файл, чтобы применять
версию проекта. Неверный или пустой файл блокирует запрос с явной ошибкой.

## Проверка качества

Без платных запросов проверяются загрузка инструкции, протокол, сохранение
переносов строк и журнал. Это не оценка литературного качества живой модели.
Для ручной проверки используйте короткий вопрос NPC, уточнение цены без покупки,
отказ от поручения и уход. Проверьте, что Мастер отвечает по делу, отделяет речь,
не списывает деньги за обсуждение и не возвращает героя на уже пройденный путь.
Сравните короткое бытовое действие с новой важной сценой: ответы должны
отличаться объёмом по содержанию, а не механически соблюдать одну длину.
