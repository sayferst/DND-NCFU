# 1W — описание вещи для героя, мастера и художника

Для предмета теперь используется общий публичный профиль:

| Поле | Содержание |
|---|---|
| object_type | Конкретный тип: дорожный посох, перевязочный бинт, керамическая печать |
| appearance | Силуэт, форма, видимая поверхность, цвет и отличительные детали |
| purpose | Обычное или уже выясненное назначение |
| material | Только видимый или изученный материал |
| description | Дополнительное публичное описание при необходимости |

Хроники, контекст мастера и художник читают один профиль. Скрытые эффекты, точные
характеристики, цена, редкость, тайное назначение и состав не копируются из сырой
базы в этот профиль. Внешность неизвестного предмета можно описать без раскрытия
его истинной природы. Карточка и экспорт по-прежнему экранируют HTML.

## Хранение и совместимость

Новый генератор записывает `public_object_type`, `public_appearance`, `public_purpose`,
`public_material`, `public_description` в прежние properties/state. Уточнение уже
существующей вещи занимает одну существующую запись памяти:

```json
{
  "subject": "item_instance_id",
  "kind": "knowledge",
  "text": "{\"field\":\"object_profile\",\"value\":{\"object_type\":\"Керамическая печать\",\"appearance\":\"Три матовые грани и короткая рукоять\",\"purpose\":\"Оттиск на воске\"}}",
  "importance": 3,
  "private": false
}
```

Прежний лимит text1000 сохраняется; не требуется новый формат ячейки или SQLite.
Профиль восстанавливается из JSON и основной базы кампаний. Первая профильная
запись не заменяется случайным пересказом; канонические публичные поля каталога
имеют приоритет. Старые appearance-memory также видны. Закрытые/неувиденные объекты
и личные записи не превращаются в публичные знания. После ухода сохраняется
последнее наблюдение, без показа удалённых новых изменений состояния.

Отдельный `data/catalog/public-descriptions-v1.json` содержит47 авторских профилей:
46 базовых типов и монета из прежнего адаптера. Например, бинт — полоса ткани
в рулоне для перевязки; посох — длинный деревянный шест с хватом и опорным концом.
Это описания базовых форм, а не новые награды, характеристики или правила лечения.
Старый seed-v1.json и его хэши не менялись; индивидуальные известные признаки
имеют приоритет над справочными. Неопознанная вещь не получает скрытую функцию
из справочника только из-за владения.

Указания генератора находятся в narrative/object_prompt.py и добавляются к запросу
программой, в том числе при пользовательском local.txt. Сам local.txt и стандартный
промпт не переписаны. Это инструкции и контекст, не дообучение весов модели.

## Работа мастера

В прежний запрос плана мира добавляются до12 публичных карточек и до3 предметов
с отсутствующей внешностью. При встрече/осмотре/получении модель может дополнить
профиль через memories вместе с обычным ответом. Нет отдельного автоматического
платного запроса для каждой карточки. Существующий контекст рассказа получает
те же признаки, чтобы не придумывать вещь заново после загрузки.

Для произвольной старой вещи без описания откройте Хроники и нажмите
**«Уточнить описание»**. Кнопка готовит вопрос в поле чата, не отправляет его.
При непустом черновике текст не заменяется. Нажмите «Отправить» сами: нужен
включённый облачный мастер. После ответа проверьте карточку и сохраните сессию.
Модель может не заполнить память; интерфейс не выдаёт отсутствие описания за
доказанную тайну или самостоятельно сочинённый канон.

## Работа художника

Запрос содержит категорию, название, конкретный тип, внешний вид, известные
материал/назначение. Композиция выбирается отдельно:

- Предмет: сам объект целиком, крупно на простом фоне, без человека, рук,
  владельца, манекена и сцены использования. Одежда/броня показаны пустыми.
- NPC/существо: портрет одного указанного участника.
- Место: вид места, без выдуманного жителя вместо локации.
- Событие: подтверждённые участники и объекты сцены.

В предметном референсе нужно сохранить форму самого объекта, не персонажа/фон
из прошлой картинки. Назначение объясняет конструкцию, а не требует иллюстрировать
человека с вещью. Без установленных признаков не добавляются руны, магическое
свечение, повреждения и особые эффекты. Метка `object-art-2` сохраняется внутри
прежнего prompt в визуальном реестре.

Профили разных экземпляров с отдельной внешностью не делят одну типовую картинку.
Это не переключает обычную вещь в дорогую модель само по себе: первая генерация
без референсов может использовать Recraft. При использовании прежнего образа
по прежним правилам выбирается FLUX. Тарифы/бюджет/подтверждение и запрет повтора
не изменены. Просмотр кэша по-прежнему бесплатный.

Уже созданная картинка не меняется сама. Для старого посоха сначала уточните
описание, затем нажмите **«Перегенерировать»** и проверьте цену в подтверждении.
Новая инструкция уменьшает вероятность лишнего персонажа, но её соблюдение
зависит от модели; настоящая генерация в этой сессии не выполнялась.
