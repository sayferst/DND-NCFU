## Что изменено

У рассказчика теперь простой текстовый контракт. Он получает текущую сцену,
биографию, доступные сведения SQLite и последние события. Ему не передаётся
схема JSON-команды/фактов, матрица выигрышей или несколько литературных образцов
одновременно. Роль — вести одиночную RPG: ответить на смысл действия, описать
развитие, дать прямую речь NPC, сохранить выбор игроку и не назначать числовые
эффекты. Заявленный подход и вопрос допускаются вместе.

Модель возвращает обычный рассказ. Код сам создаёт внутреннюю Proposal/SceneRecord;
никакая команда из текста модели не исполняется. Если модель всё же вернула старый
JSON с непустой mechanical_command, он отклоняется целиком. Не извлекаем оттуда
«продать бинт» и не применяем facts. Старый корректный контейнер narration может
быть прочитан для совместимости. Обычные кавычки и публичные подписи NPC приводятся
к форме прямой речи, а не требуют от модели сложной схемы.

Механические действия распознаются отдельно по явному сообщению игрока: существующее
действие, простой переход, проверка характеристики. Поддерживается префикс «хочу» /
«попробую» у существующих действий. Вопрос, отрицание или длинная составная фраза
не превращаются в продажу по совпавшему слову. При выполнении проверяются прежние
место, ресурсы, цель, бой и подтверждение нападения на нейтральную цель. После
механики рассказчик описывает уже рассчитанный исход, без повторного броска.

Это не универсальный NLU/планировщик: неподдержанное механическое намерение нельзя
исполнить одной художественной фразой. Семантическая истинность всей прозы не
доказывается валидатором. Модель1.7B всё ещё может писать слабо или ошибаться;
роль/память не равны увеличению возможностей весов. Дообучения/новых весов нет.

## Надёжность и производительность

- Одна автоматическая повторная попытка для пустого, обрезанного, языкового или
  непригодного ответа. Причина коротко возвращается модели; не больше двух попыток.
- Обе попытки видны в техническом ответе. Сетевая ошибка, отказ API или отмена не
  вызывают скрытого действия/бесконечного повтора. Неотправленный ввод возвращается.
- Незавершённый ответ после смены сессии не применяется. Неудачная проза после
  броска сохраняет рассчитанный исход; повтор прозы не расходует RNG.
- Ollama keep_alive=5m вместо0: не выгружаем модель после каждого сообщения.
- Qwen3 получает think=false и /no_think. Промпт и контекст сокращены. Контекст4096,
  при длинной биографии8192; предел650 выходных токенов, при исправлении900.
- Таймаут рассказа150с, показ статуса первой/повторной попытки. Это верхний предел,
  не обещание скорости на ноутбуке. Требуется замер настоящей модели.

Новая история хранится как SceneRecord2 и полный текст события в SQLite-проекции;
сложный автоматический ввод новых типизированных facts моделью в этом пути убран.
Прежние NPCProfile/StoryFact читаются и имеют приоритет, история не стирается.
Новая проза narrator-prose-8. WriterJSON13/reader1–13, SQLite snapshot12/13.
Настоящая fixture12 получена кодомa222766 до новой схемы; сохранён исторический
источник chatgpt-manual. Загрузка старой ячейки не переписывает файл.

## Интерфейс: действия через чат

Ручной ChatGPT и окно копирования удалены из приложения. Кнопки готовых действий
(осмотр, разговор, торговля, бой, лечение, кубик, обучение, поручение, переходы)
убраны из рабочего интерфейса, включая широкий экран и вкладки. Кнопки ручного
запуска рассказа/авторассказа быстрых команд также скрыты. Остаются отправка текста,
меню/герой, сохранения, чтение/экспорт и настройка источника мастера. История
кубиков и расчёты остаются видимыми. Механика/старые записи сохранены.

Только для регрессионных проверок конструктора существует legacy_controls=True;
launcher его не включает, пользовательского переключателя нет. Это позволяет
проверять прежние сценарии без возвращения кнопок в игру. Новый интерфейс отдельно
проверяется на всех вкладках и после изменения размера/состояния торговли.

## Как проверить настоящую Ollama на Windows

1. Закройте игру, сохраните копию saves и обновите ветку по командам из чата.
2. Запустите установленную Ollama. Модельqwen3:1.7b должна быть уже загружена.
3. Из D:\Projects\DND-NCFU выполните:

```powershell
.\.venv\Scripts\python.exe scripts\check.py
.\.venv\Scripts\python.exe scripts\check_narrator.py --model qwen3:1.7b
```

check.py проверяет код без модели. check_narrator.py действительно обращается
к Ollama: создаёт временного героя с биографией и задаёт две реплики («осмотрюсь,
где я» и составной вопрос девушке). Используются те же payload/парсер/исправление,
что в приложении. Ваши ячейки не читаются, не перезаписываются и не удаляются;
скачиваний и платных запросов нет. Отчёт с уникальным run_id сохраняется в
D:\Projects\DND-NCFU-data\diagnostics. Исходы протокола и ответы показаны в консоли.
Успех означает пригодность ответа для цикла, а не литературную оценку человеком.

4. Запустите scripts\run_game.py, в «Рассказчик» выберите локальный источник,
   найдите модели и включите мастера/свободный ввод. Попробуйте те же реплики своим
   героем. Настройки включения/источника пока не сохраняются между запусками.
5. При отказе пришлите вывод check_narrator.py либо строки обеих попыток из
   технического ответа. Не называйте «пройденным» запуск с protocol_passed=false.

В облаке агент проверил отсутствие127.0.0.1:11434: connection refused. Скачивание
с registry.ollama.ai и Hugging Face блокируется CONNECT403; доступного инструмента
управления Windows пользователя нет. Факт этого отказа отдельно сохранён в
validation/linux-real-narrator-unavailable-2026-10-19.json. Тестовые HTTP-ответы
не выдаются за настоящую Qwen3/Windows-приёмку.

## Автоматический облачный мастер

Этот режим отправляет сообщения из игры сам, без копирования в чат.

1. В «Рассказчик» выберите OpenAI API либо OpenRouter API.
2. Укажите точный ID доступной у провайдера модели и API-ключ. Можно вместо ввода
   ключа задать RPG_VKR_LLM_API_KEY в окружении процесса вне репозитория.
3. Ознакомьтесь с условиями своего провайдера и включите разрешение отправки сцены.
   Подписка ChatGPT Plus не предоставляет API-баланс; возможны отдельные расходы.
   Условия бесплатных моделей/квот OpenRouter нужно проверять отдельно. Игра не
   обещает их наличия и не выбирает платную модель по умолчанию.
4. Примените настройки и отправьте сообщение в игре. Ручного переноса JSON нет.

Применение настроек само по себе не делает запрос и не доказывает подключение.
Фактический запрос — после действия игрока. При отсутствии ключа/разрешения вызова
нет. При отказе локальной модели автоматического перехода в платное облако нет.
Ключ маскируется в UI, хранится в памяти процесса и не записывается в ячейки,
предпочтения, диагностический текст или URL. Не используйте пароль/куки ChatGPT.

Разрешены два фиксированных HTTPS endpoint; проверка TLS сохранена, перенаправления
не следуются с Authorization. Авторизация — Bearer; ответ choices/message
нормализуется в общий текстовый цикл. Новые SDK/плагины не устанавливаются.
Без настоящего ключа облачные провайдеры здесь не вызывались: проверен адаптер
с временным HTTP, не доступность/качество/цены выбранной пользователем модели.
