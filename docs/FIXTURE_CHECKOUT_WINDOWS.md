# Восстановление эталона тестов на Windows

19 октября 2026 пользователь получил **676 passed / 2 failed, 34.61 с**.
Обе ошибки относятся к `tests/fixtures/save-v15.json`, а не к игровой ячейке.
Источник: [выдержки из отчёта Windows](validation/windows-fixture-crlf-repeat-2026-10-19.md).

Git раньше преобразовал строки файла из LF в CRLF. Правило `.gitattributes`
теперь запрещает это, но получение правила само по себе не переписывает старую
копию файла. В присланном выводе он по-прежнему содержит CRLF. Почему прежняя
команда восстановления не обновила его на ПК пользователя, пока неизвестно:
временный Git в среде агента успешно выполняет `git restore` в проверенном случае.

Вдобавок тест Git ошибочно считал рабочую копию исходным LF-эталоном и применял
к уже преобразованным строкам ещё одно преобразование: получался CRCRLF.
Теперь этот тест строит эксперимент из исходного Git-блока с проверенной
контрольной суммой и проверяет оба входа: LF и CRLF. Отдельный тест по-прежнему
строго проверяет байты настоящего файла в рабочей папке, без нормализации.

Исходная SHA-256:
`e00a333d44929de6d5e3ff6a87c70ca3e1b1f9704f55554ecaf2cb59bed94238`.
Присланная CRLF-копия:
`b1d9736c8d31f59f331da4e74ee2850f7f211488b2bbd6ff59f9f1e5b1d420f2`.
Ни исходный эталон в Git, ни ожидаемая сумма не изменены.

## Команды

Сохраните игровую сессию в ячейку и закройте окно игры. В PowerShell:

```powershell
& {
    $ErrorActionPreference = 'Stop'
    Set-Location D:\Projects\DND-NCFU
    git switch setup/development-environment
    if ($LASTEXITCODE -ne 0) { throw 'Не удалось переключить ветку.' }
    git pull --ff-only
    if ($LASTEXITCODE -ne 0) { throw 'Обновление не получено. Сохраните текст ошибки.' }
    .\.venv\Scripts\python.exe scripts\repair_fixture_checkout.py
    if ($LASTEXITCODE -ne 0) { throw 'Эталон не восстановлен. Сохраните текст ошибки.' }
    .\.venv\Scripts\python.exe scripts\check.py
    if ($LASTEXITCODE -ne 0) { throw 'Проверка не прошла. Сохраните вывод.' }
    .\.venv\Scripts\python.exe scripts\run_game.py
}
```

Новая команда читает исходный файл и его метаданные из текущего коммита Git
в двоичном режиме. Сначала проверяет исходную SHA-256, затем:

- если рабочая копия уже совпадает с исходной, оставляет её без записи;
- если отличается **только точной заменой всех LF на CRLF**, атомарно восстанавливает
  исходные байты и проверяет результат;
- при любых других изменениях, отсутствии файла или неверной исходной сумме
  останавливается. Не удаляйте файл и не меняйте ожидаемый хеш вручную.

Ожидается `Restored original LF bytes` или `Already matches committed bytes`,
затем `SHA-256 verified`. Повторный запуск безопасен. Проверка `scripts/check.py`
сама ничего не восстанавливает. Новый инструмент не использует кеш статуса Git,
не меняет индекс, глобальные настройки Git, зависимости, базу мира или ячейки в
`D:\Projects\DND-NCFU-data\saves`. PowerShell не перекодирует JSON через конвейер.

Если Git остановил получение обновления из-за локальных изменений, не используйте
`reset --hard` и не продолжайте блок вручную: сохраните сообщение для разбора.
После успешных автоматических проверок откроется обычное окно игры. Эту новую
проверку на настоящей Windows ещё должен выполнить пользователь.
