# Старый ngrok из winget — 22.10.2026

Владелец показал установкуngrok3.3.1 и четыре завершения до подтверждения
endpoint без ERR_NGROK. Предыдущая реализация проверялась наLinux3.39.12,
но не проверяла реальную версию наWindows; несовместимость была скрыта.
Нельзя объявлять такой лог доказательством сбояHTTPS443/VPN или ключа.

Исправлено:

- Ограничение поддерживаемой версии3.39.12+ до запуска дочернего туннеля.
  Старый/неопределённый агент даёт терминальный ValueError, без RestartTunnel.
- Owner-команда update-ngrok делает portable-копию установленного агента и
  вызывает его штатный signed updater с временным configv2 без секретов.
  Не меняет пакет winget. Использует общий lock сstart; не открываетStore/DPAPI.
- Копия вLOCALAPPDATA предпочитается устаревшемуPATH. После update проверяется
  версия. Время обновления ограничено180с. Ошибки не выводятraw/stderr/токены.
- ОшибкиCLI/config иERR_NGROK распознаются, явный отказ запуска не повторяется.

Источник: реальный `ngrok update --help` официальногоLinuxCLI3.39.12. Он описывает
проверку подписи обновления и требует writable-каталог; отдельно предупреждает
не обновлять установленный package manager файл. Поэтому создаётся ownerportable.
Нативная команда update сWindows3.3.1 и живая сеть владельца вLinux не проверены.
Токен из сообщения владельца не использовался, не копировался и не сохранялся.
Платных запросов, новых допусков, измененияWindows/VPN и публикацииURL не было.

Результаты проверок — отдельные raw-файлы рядом. Это проверка исправления
bootstrap/диагностики, а не подтверждение живого туннеля или готовогоSetup.
