отладка, не контролируемое A/B-исследование и не итоговая приёмка.

Старые механические launcher-пробы подменяют только cloud_gate в тестовом
процессе, чтобы проверить прежние RNG/сохранения. Современный gate отдельно
проверяется test_cloud_gate, в приложении он не отключён.

## Что проверено и что ещё нет

Проверены локальные HTTP, допустимые/ошибочные JSON, PNG и загрузка CDN без ключа,
разделение кампаний, бюджет/атомарные резервы, отказы/отмена/аварии без повторов,
версии/перезапуск, публичные описания, скрытые ID, очередь Qt и визуальные команды
без изменения сессии. Поиск прежнего образа после 100 других записей проверяет
SQLite/ID, а не 100 игровых ходов реального DeepSeek.

Реальные GET `https://routerai.ru/api/v1/models` и `/docs/reference` также при
повторной проверке после восстановления дали **Tunnel connection failed: 403**.
Это ограничение сети данной среды, не доказательство недоступности сайта на ПК.
Конкретный живой контракт `size`, `input_references`, тарифов/лимитов и ответа
остаётся несверенным. [Перечень предположений адаптера](../../IMAGES_API_CONTRACT.md).
Консервативная проверка неизвестного полного тарифа/возможностей запрещает POST.
Возможна доработка отображения полей после получения настоящей документации.

**Платных запросов Codex не выполнял.** Нет измерений живой стоимости, задержки,
качества pixel-art или сходства референсов. Нельзя считать синтетический успешный
ответ подтверждением работающего API провайдера. Нативные Windows GUI/DPAPI/EXE
также остаются ручной приёмкой. Для реального теста нужно отдельное разрешение
владельца после сверки контракта; текущая реализация по умолчанию имеет бюджет 0 ₽.
