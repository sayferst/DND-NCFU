## 1A — d20 и сохранения реализованы

- Команда «бросить d20» (также «бросить д20») использует отдельный локальный
  генератор Random с seed и выдаёт целое число 1–20. Seed и история позволяют
  воспроизвести последовательность. Проверки успеха, критические удары и модификаторы
  не добавлены; это общий вычислительный примитив, не полная реализация SRD.
- Три ячейки: сохранить, загрузить, перезаписать и удалить; подтверждение
  перезаписи/удаления, предупреждение о несохранённых изменениях при закрытии/загрузке.
- Версионированный JSON хранит журнал, seed и броски; запись через временный файл
  и os.replace. Ошибки чтения/записи показываются без замены текущей сессии.
- По умолчанию данные в соседней с checkout папке: для Windows
  `D:\Projects\DND-NCFU-data\saves`. Возможен `RPG_VKR_DATA_DIR`.
- Новых зависимостей нет. SQLite остаётся доступным для будущего игрового мира.
- Linux: **65 passed**, 0 failed, 0 skipped; pip check и Ruff успешны.
  Два отдельных запуска настоящего launcher проверяют сохранение, завершение
  процесса, повторную загрузку журнала и продолжение бросков.
- Проверены границы d20, seed, независимость ячеек, перезапись/удаление,
  отмена подтверждений, повреждённые файлы и отказ атомарной записи.

## 1C — реализован более крупный законченный набор

- Вкладки приключения и персонажа, кнопки быстрых действий, новый герой и редактор.
- Валидируемое неизменяемое состояние: место, HP/maxHP, золото, бинты, корзина,
  прогресс поручения, флаг исследования, запасы/деньги торговца.
- Авторский эпизод: взять поручение, исследовать дорогу, доставить корзину,
  получить одноразовую награду, купить/продать бинт и восстановить здоровье.
- У отклонённых действий ресурсы и RNG не меняются. При внутреннем отказе
  валидации RNG откатывается, чтобы не нарушить воспроизводимость сохранения.
- При торговле сохраняются общие деньги и предметы покупателя/торговца;
  нет повторной награды, повторной находки и лечения выше maxHP.
- Редактор меняет имя/характеристики, не восполняет ресурсы; изменение пишется
  в журнал. Новый герой создаёт отдельную сессию и не удаляет три ячейки.
- JSON v3 хранит мир и героя, читает v1/v2 без изменения исходного файла.
  Старые реплики не переигрываются. У старых сессий мир начинает эпизод с
  начальными ресурсами, поскольку в прежнем формате ресурсов ещё не было.
- **145 passed** в Linux, 0 failed, 0 skipped; pip check, Ruff lint/format успешны.
  Проверен полный цикл через два настоящих процесса приложения.
- Новых зависимостей нет. Цены, награды, HP и бинт — homebrew, не таблицы SRD.

## Ожидается приёмка 1C на Windows

Сохранить сессию, закрыть окно; получить обновление через `git pull --ff-only`,
проверить и запустить. Пройти docs/EPISODE.md, проверить редактор и сохранение
мира после перезапуска. На пробной ячейке проверить загрузку v1/v2.
Следующий набор функций выбирается после этой приёмки.

## Возобновление агентом

Прочитать AGENTS, мастер, статус, DECISIONS/RESEARCH_LOG/TEST_PLAN. Проверить git status,
использовать существующий checkout и `.venv`. Не создавать worktree без просьбы.
Облачные install_script/start_skill должны соответствовать этапу 1C; процессы не
сохраняются между задачами. Публикация и восстановление снимка требуют отдельной проверки.
После каждого шага сохранять реальные результаты и остановиться для проверки пользователя.
