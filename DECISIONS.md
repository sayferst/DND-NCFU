## Разрешённые противоречия исходников

- `_OLDER` оставляет бюджет/офлайн открытыми, допускает недорогой облачный API;
  актуальны 0 ₽ и обязательный автономный режим из текущего запроса и мастера.
- Архивное ТЗ предлагает сразу SQLAlchemy/Alembic/Pydantic/Hypothesis и широкий
  импорт SRD. Добавление отложено до реальной потребности; сначала маленькие шаги.
- Старый первый запрос и мастер включают окно в этап 0. В текущей задаче 0A
  заканчивается настройкой; окно и игровой ответ принадлежат будущему 0B.
- В источниках научные ссылки местами названы «подтверждёнными»; эта сессия
  не проверяла публикации. В RESEARCH_LOG они зарегистрированы как кандидаты.

## Открытые вопросы (не блокируют подготовку)

1. Точная тема ВКР, методичка, дедлайн и смысл «агентской разработки» у руководителя.
2. Требуемая научная новизна, формальная модель, протокол и размер выборки.
3. Версия Windows, ручная проверка среды и будущего GUI на целевом ноутбуке.
4. Детали игрового дизайна из Q6–Q12 мастера — перед соответствующим модулем.
5. Разрешения на модели/бесплатный API и вопросы Q13–Q18 — позже, не считать выданными.

## D011 / 2026-10-16 — минимальная поставка Qt

Статус: принято, реализует D003. Выбраны PySide6-Essentials 6.10.1 и shiboken6
6.10.1 с импортами из PySide6. Qt Widgets входит в Essentials; пакет Addons
не нужен. Загрузка Windows около 72 МБ, Linux около 74 МБ. Python 3.12 подходит
под ограничение этих пакетов >=3.9,<3.15; Python 3.15 здесь не поддерживается.
Альтернативы: полный PySide6 (больше модулей/загрузки), Tkinter (смена выбранного UI).
Лицензии зафиксированы по метаданным пакетов; DLL/so в Git не копируются.

## D012 / 2026-10-16 — честный минимальный offline_rules

Статус: принято. Авторские команды распознаются целиком, с нормализацией регистра
и пробелов. Составные и неизвестные действия вызывают уточнение вместо выдуманного
успеха. UI и рассказчик разделены. Журнал — только в памяти, ввод отображается
простым текстом. Сцена не заявляет правил SRD или изменения игровых ресурсов.
Альтернатива — LLM/расширенный парсер — отложена до необходимости и отдельного решения.

## D013 / 2026-10-16 — отдельный расчёт d20 и воспроизводимая сессия

Статус: принято. Пользователь принял первое окно и поручил добавить d20.
У каждой сессии собственный `random.Random` с seed; без задания seed используется
128-битная системная случайность. `randint(1, 20)` выдаёт целое число, UI показывает
его после расчёта. Рассказчик не выбирает результат. Seed, порядок и значения
бросков сохраняются; восстановление проверяет их и продолжает ту же последовательность.
Это общий примитив кубика, без заимствованных текстов SRD, модификаторов,
проверки сложности и правил критического успеха/урона. Соответствующие механики
SRD потребуют отдельной сверки источника и реализации.

## D014 / 2026-10-16 — три локальные ячейки JSON v1

Статус: принято. Во время этапа пользователь добавил сохранение/загрузку,
перезапись и удаление трёх ячеек. Выбран небольшой версионированный JSON:
текущая сессия пока содержит только журнал и броски. Запись — через временный
файл и атомарный `os.replace`; загрузка проверяется до замены состояния в окне.
Подтверждения перезаписи/удаления и потери несохранённых изменений обязательны.
Ограничения: 2000 действий, 4 МБ, одно активное окно, автосохранения нет.
Альтернатива — SQLite для всего мира — остаётся планом, когда появятся персонаж,
ресурсы и связи сущностей. Будущий переход должен сохранить старые данные
через явную миграцию, не переименовывать формат v1 молча.

## D015 / 2026-10-16 — сохранения на диске проекта вне Git

Статус: принято. Пользователь работает на D: из-за нехватки места на C:.
Выбрана соседняя папка `<имя-checkout>-data/saves`, то есть
`D:\Projects\DND-NCFU-data\saves`, вместо предложенного ранее профиля Windows.
Это сохраняет данные отдельно от исходников и обновлений Git. Путь можно явно
выбрать переменной `RPG_VKR_DATA_DIR`; перенос/переименование checkout требует
переноса данных либо фиксированного пути. Файлы не отправляются на GitHub.

## D016 / 2026-10-16 — учебный профиль и базовая проверка характеристики

Статус: принято. После приёмки d20/ячеек пользователь поручил продолжить.
Добавлен фиксированный авторский профиль «Путник» с шестью характеристиками,
без полного создания персонажа, класса, HP и владений. Формула модификатора и
успех при `d20 + modifier >= DC` сверены по SRD 5.2.1, с. 5–6.
Учебные команды используют DC 10 и не меняют мир. Чистая функция поддерживает
score 1–30, DC 1–30, без автоматического успеха/неудачи от 20/1.
Редактор, навыки, преимущество/помеха и игровые последствия — отдельные задачи.

## D017 / 2026-10-16 — JSON v2 с явным чтением v1

Статус: принято. Новая схема сохраняет профиль и числовые детали проверок.
v1 преобразуется только в памяти: стандартный профиль, исторические реплики
без переигрывания ранее неизвестных команд, та же последовательность RNG.
Сам файл меняется только при сохранении с обычным подтверждением перезаписи.
Проверки используют fixture, созданный настоящим кодом коммита 4346127.
При откате на старое приложение требуется отдельная копия v1 — старый reader
не понимает v2. Будущие изменения должны сохранять миграционный путь.

## D018 / 2026-10-16 — происхождение правил и лицензия

Статус: принято с ограничением проверки происхождения. Прямой доступ к PDF

## D019 / 2026-10-16 — более крупные законченные этапы

Статус: принято по просьбе пользователя. Вместо одного параметра за этап выбран
связанный набор: редактор героя, HP/золото/инвентарь, путешествие, поручение,
исследование, лавка, лечение и сохранение всего мира. Следующая приёмка охватывает
этот эпизод целиком. Требование остановиться после этапа сохраняется.
В конце каждого изменения обязательно давать PowerShell-команды для обновления
локальной папки на D:, проверки и запуска, а не только ссылку на GitHub.

## D020 / 2026-10-16 — homebrew и границы свободного редактора

Статус: принято. Редактор меняет имя и характеристики в диапазоне 1–30 без бюджета
очков; это песочница, не полный SRD-генератор. Ресурсы при редактировании не меняются.
Новый герой начинает отдельную сессию, не удаляя ячейки. HP=12, золото=10, стартовый
бинт, цены 3/1, награда 5, находка 2, урон 3 и лечение до 4 — авторские параметры.
Проверка ловкости использует уже сверенную механику SRD при DC 10. Новых боевых,
классовых и медицинских правил SRD не заявляем.

## D021 / 2026-10-16 — валидируемое состояние и JSON v3

Статус: принято. WorldState — неизменяемая структура с неотрицательными ресурсами,
ограниченным HP, связью корзины/поручения и флагом одноразового исследования.
Действие вычисляет новый объект до применения. При ошибке вычисления состояние
и RNG не изменяются. Торговля сохраняет общую сумму денег и количество предметов.
JSON v3 сохраняет мир; v1/v2 мигрируют в памяти с начальными ресурсами, без
переигрывания старых реплик. Для регрессии сохранён fixture v2 из кода 8374ae1.
Объём мира пока мал, поэтому отдельная SQLite-схема отложена до связанных сущностей.
Полное восстановление мира из исторических текстов и защита от ручного читерства
в JSON не заявляются; для исследовательского replay нужен отдельный протокол событий.
